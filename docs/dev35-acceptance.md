# dev.35 业务引导与代办验收

## 范围

本轮只扩展随平台交付的 Skill 与薄业务接口，版本为 `0.4.1-dev.35`。不重做首页、固定执行器或任务系统。没有操作 MuMu、运行真实视频/巡检、调用付费模型、打包、推送或更新远端。

## 行为基线

无项目历史上下文的独立 Agent 只读取旧 Skill，回答“定制坚果干果厂家主题、排除零售/仓储/吃播、以后保存和轮换、先不运行”。原回答把主题存储推荐为 `memory_save`，用记忆中的游标模拟下次换词，并把无法确认表述为不匹配。它没有发现已有内容计划和按轮次轮换能力。该回答在修改 Skill 前保存，不能用修改后的材料冒充旧基线。

新版要修复的是实际操作路线，不只是增加文档关键词：主题保存进入内容计划，运行参数进入预设，记忆仅保存偏好；严格生产主题要求当前画面证据，证据不足为不确定，不等同厂家身份核验。

## 后端回归

新增 action 复用内容计划、预设、模型和通知服务。所有写入使用原持久化请求回执，查询不要求写入请求号；未知副作用不自动重放。模型状态只读，测试与启用仍使用原服务和限制，Key 不通过 Skill 输入。

Task 1 RED 曾得到 25 项中 5 失败、2 错误，对应缺少新操作、内容计划重复索要字段、读取被当作写入及结果摘要缺失。修改后针对 automation、Skill 基线、相邻内容计划/模型/角标和 Agent facade 的定向测试通过。全量验证及最终行为结果以本节后续记录为准，定向通过不等同整体验收通过。

## 独立行为与隔离执行

首轮新版独立 Agent 未连接平台、未保存或运行任务，正确解释内容计划与按轮次轮换，但把可填写的提示词写成 `exact/adjacent/unrelated/uncertain` 四分类，未遵守“命中／必须证据／排除”输入格式。该轮未判为通过；已要求明确区分输入模板和结果分类，并修订完整示例后用新的无历史 Agent 重测。

修订后，另一个全新 Agent 仅收到完整 Markdown 与相同需求，实际输出三段可填写标准、分组搜索词及正确轮换说明；只写草案，没有连接、保存或启动。随后分别收到“保存并改第4组、核对旧版”和“使用新版明确启动一轮2条零互动搜索”的指令。

它通过分发客户端在隔离平台实际调用内容计划列表、保存两版、分别读取新旧版本，再查询设备与任务、读取当前修订、创建计划、启动同一计划、查询进度及任务证据。持久化记录确认仅创建一个任务并完成，原始计划冻结了所选修订，未要求用户重填已保存搜索词/标准；六项互动概率均0，消息检查关闭，队列仍暂停。没有使用记忆模拟内容计划或轮换，也没有点击确认卡。

其最终复盘引用 `result_summary` 的2条模拟完成、2条命中、0跳过和0互动，明确模型计数缺失为 `null` 而非0，现场证据未保存不能复核画面或推算四类分布。独立检查脚本对实际 API 审计和隔离 SQLite 逐项断言通过。

隔离平台使用真实 automation、计划、任务存储及客户端回执，但执行者是显式模拟器；上述数量只证明接口闭环，不是实际设备业务效果。首次接入、重复请求/未知结果、内容计划四轮映射、原批次恢复等由相应自动测试覆盖，不冒充这些场景均由独立 Agent 逐一实测。

## 完整验证与本机交付

候选全量 Python 首轮916项中1失败、1跳过：旧安装测试硬编码参数必须位于 SKILL 正文。核对安装函数确实复制全部参考文件后，测试改为验证参考/API/客户端实际安装且重复安装不改变时间戳，继续检查原参数内容，没有删除兼容性断言。重跑916项通过（915通过，1项历史个人主页截图在隔离工作区缺失而跳过）。针对模型凭证/忙碌错误的57项回归、安装兼容14项及实际技能例子保存/四轮映射均通过。

OpenSpec严格校验44项、前端45项、两套类型检查、lint及生产构建通过。独立代码复核未发现剩余阻断项。全量输出含故意注入的断连、模型拒绝及模板失败日志，不代表进行了真实设备或付费调用。

本机切换待验证。切换前后通过只读快照核对暂停、原 4 条等待任务、任务/内容计划/预设/草稿/设备档案、原生会话及配置哈希。备份、快照、独立 Agent 回执和浏览器截图留在忽略的本地验收目录，不随 Skill 或源码发行。

只有最终干净提交已启动且 API、首页复制/下载及数据核对通过，才能认定本机更新完成。
