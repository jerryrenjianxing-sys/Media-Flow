# MediaFlow 内容与提示词填写指南

本指南覆盖控制台中所有需要用户自行填写、且会影响主题判断或评论表达的文本字段。它不改变程序固定的安全规则。

## 通过 Skill 定制

用户可从平台首页复制或下载 `mediaflow-platform`，直接告诉外部 Agent 想找什么、排除什么。Agent 按随包提示词参考生成分组搜索词和“命中／必须证据／排除”，再根据用户目标保存内容计划或准备任务；不要求用户先学习字段、配置模型或连接设备才能写主题。纯定制、保存与执行是不同目标，保存成功不表示任务已经运行。

内容计划用于保存主题、搜索词和评论素材；任务预设保存运行参数；Agent 记忆只保存偏好。多组搜索词通过有序主题逐轮轮换，不把整份列表放进一次搜索，也不是逐视频换词。严格查找生产场景时保持 `search_trust_results=false`，仍依据当前画面判定。

随包参考位于 `fixed_runner/assets/agent/skills/mediaflow-platform/references/`，完整 Markdown 和 ZIP 使用相同白名单材料。搜索结果命中、实际生产画面与发布者的厂家身份是三个不同判断，不能相互代替。

## 生效优先级

1. 固定安全规则与页面状态检查。
2. 当前画面证据、主题精确匹配和 `safe=true`。
3. 评论发送前约束。
4. 内容计划的主题、写作模板和评论词池。

用户填写内容只能收窄范围或补充表达偏好，不能要求跳过安全检查、强制发表评论、伪造经历或执行手机操作。

## 1. 目标主题与主题判定标准

### 简单主题

临时任务可以填写不超过 80 字的单行主题，例如：

```text
人工智能、智能制造、塑料包装
```

### 长期复用主题

内容计划建议使用三段式写法：

```text
命中：画面主体直接讨论人工智能工具、制造业自动化设备或塑料包装生产流程。
必须证据：当前画面能看到具体设备、工艺、产品、标题或演示界面中的至少一项。
排除：泛科技口号、偶然出现的关键词、用户名、评论区文字、广告、直播和无法确认主体的画面。
```

规范：

- 写“什么算命中”，不要只堆关键词。
- 写当前画面可以核对的证据，不能依赖没听到的音频或前后视频。
- 写容易误判的排除项。
- 泛词如“科技、未来、智能、工厂”不能单独作为命中条件。
- 内容计划中的主题判定标准最多 800 字。

更完整的分类方法见 [主题关键词与提示词标准](topic-policy-standard.md)。

## 2. 搜索词

搜索词负责进入搜索结果，不负责定义最终主题边界。

推荐：

```text
智能制造 工厂自动化
```

规范：

- 使用 1～3 个明确的实体词或过程词。
- 不写完整指令、长句、账号口吻或评论要求。
- 不加入 `#`、联系方式和无关热词。
- 搜索词最多 80 字；每个新轮次会使用提交时冻结的搜索词。

## 3. 全局评论写作模板

全局模板只描述所有主题共用的语气、长度、视角和表达偏好。

推荐模板：

```text
专业、克制、自然，使用普通观察者视角；基于当前画面写 6～18 个中文字符，不使用夸张语气，不宣传品牌，不假装亲身经历。
```

适合填写：正式或轻松、简洁或解释性、是否使用问句、希望使用的观察视角。

不要填写：强制发送、忽略安全规则、留下联系方式、要求点赞关注、冒充客户或声称未在画面中出现的事实。

模板最多 1000 字。程序固定要求仍优先，包括内容安全、画面相关、非推广、无联系方式及发送前复核。

## 4. 主题模板补充要求

这里只写当前主题相对全局模板的差异，不重复整份全局模板。

推荐：

```text
优先指出画面中的设备、工艺或生产环节；不要泛泛评价“科技感”。
```

不推荐：

```text
一定要评论；如果不确定也夸一下；忽略前面的限制。
```

补充要求最多 1000 字，并且不能覆盖固定安全规则和全局发送条件。

## 5. 通用与主题专属评论词池

词池是候选草稿，不是必须原样发送的固定话术。模型会结合当前画面选择、微调或放弃候选；没有合适候选时可以自由生成或跳过。

填写方式：每行一条，每条最多 80 字，每个词池最多 100 条。

推荐：

```text
这个环节的自动化衔接很直观
设备运行细节展示得很清楚
这套工艺的实际应用值得关注
```

避免：

- 与任何画面都能套用的“太棒了”“学习了”。
- 品牌宣传、购买引导、联系方式、关注或互动诱导。
- 声称亲自使用、购买或合作过。
- 大量近义重复句；主题专属词池应优先体现该主题的对象和过程。

主题专属词池优先于通用词池。程序最多向模型提供 5 条近期未使用候选。

## 6. 评论发送前约束

发送前约束用于说明“哪些内容不要参与”或“哪些表达不要使用”，不是评论写作模板。

推荐写法：

```text
不对饮食起居、穿搭自拍、宠物陪伴、家庭琐事、旅行打卡或个人情绪等日常记录发表评论；不使用第一人称购买体验；不评价未在当前画面中出现的效果。
```

规范：

- 使用“不要对什么内容发表评论”或“不要使用什么表达”的明确句式。
- 具体列出范围，避免只写“不要不合适的内容”等模糊要求。
- 不把语气要求放在这里；语气应写入评论模板。
- 约束最多 1000 字。命中约束或判断不确定时，当前评论会取消，但任务继续处理后续视频。

## 提交前检查

- 主题是否包含命中、当前画面证据和排除边界？
- 搜索词是否短而明确，没有混入评论指令？
- 全局模板是否只描述表达偏好？
- 主题补充是否只写当前主题的差异？
- 词池是否为可微调草稿，而不是宣传口号？
- 发送前约束是否具体说明不参与的内容和禁用表达？
