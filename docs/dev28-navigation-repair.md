# dev.28 本机原生聊天／控制台导航修复

## 已确认原因

本机实际运行的是 dev.24（15f3a7f），不是已制作但未安装的 dev.27 私人包。
本轮是对该运行基线的窄修复，不把 dev.25–27 候选整体切入本机，也不更改已交付安装包。

1. 品牌栏和关于页使用同源 `/manage` 普通链接。原生 Solid Router 拦截后将其解释为目录路由，实际跳到 `/new-session?draftId=…`。浏览器已复现；没有产生后台会话创建请求。
2. 管理端的返回／设置仍进入旧 React Agent 页面，与原生首页形成两套入口。
3. 原宿主管理端口随机分配；3001 上另有旧预览进程。独立控制台直接读 API 时，CORS 只允许3000，导致页面可显示而数据不可读。

## 修复边界

- 管理链接 `target=_blank rel=external noopener noreferrer`，避开原生路由，保留原聊天及未发送草稿；没有修改原生路由、消息、滚动或工具逻辑。
- 管理兼容地址307跳转至独立控制台；后台固定管理端口3001并检查冲突，不任意结束占用程序。聊天仍为3000。
- API仅允许本机3000和3001两个准确Origin读取，GET和OPTIONS均回归，其他Origin不反射。
- 控制台不再挂载旧Agent。独立设置页复用原偏好、关于和模型配置入口；旧设置书签仍可跳转。聊天模型设置继续使用OpenCode原生弹窗。
- 保留会话、凭据、任务、档案、Skill及固定执行器。本轮不打包、推送、操作远端／MuMu或调用模型。
