# dev.35 完整业务引导与 Skill 代办能力

## Global Constraints

实现用户批准的 dev.35 方案：一个 mediaflow-platform Skill 贯通理解目标、主题定制、按需配置、保存/运行、结果与复盘。复用现有业务服务、队列和固定执行器，不增加权限层。复制 Markdown 和 ZIP 同源，材料不含机器路径、凭据或运行数据。未指定互动默认零，咨询/主题定制/保存不启动任务；服务未运行先询问。只更新本机，保留暂停及原等待任务；不操作 MuMu、不跑真实业务、不调用付费模型、不打包、不推送或更新远端。

## Task 1: 业务代办与内容计划预检

扩展现有 automation 服务与标准库客户端，复用内容计划查询/读取/保存新版本/归档、预设查询/保存、模型状态/用户明确要求后的测试和启用、提醒查询/确认。不要新建业务存储或模型请求通道。Key 仍在原平台界面填写，接口不得回显。新增写操作沿用持久化 request_id 和 request_status，重复请求不重复副作用，未知结果不重放。

模型测试仍遵守原上传同意及模型费用/忙碌检查；本轮只能通过离线 fake transport 验证。读取模型状态不得触发付费验证。保留旧接口兼容。内容计划先验证计划ID/修订对应并解析有效主题，再判断缺少搜索词/主题标准；已有字段不重复询问，冻结原修订并使用现有轮次映射。不要从原高写入草稿继承参数。

先写失败测试，覆盖新操作持久化/重复/重启/未知、保存版本/归档历史、内容计划无需重复字段可预览提交、错误修订、轮换及冻结、模型请求和通知语义。只修改后端和脚本、对应测试。完整报告含 RED/GREEN 命令、输出、接口字段和文件清单；提交限定文件。

## Task 2: 完整引导、打包与行为验证

根据现有 docs/content-prompt-guide.md 与 docs/topic-policy-standard.md，简化 SKILL 入口为目标识别与按需读取资料，不做强制问卷。纳入搜索词、命中/必须证据/排除、坚果干果工厂完整示例、搜索不等于命中及画面不等于厂家身份。说明 general/mixed/search/hybrid 模式、search_trust_results 的真实影响，多搜索词按内容计划逐轮轮换而非逐视频换词。严格生产场景默认不信任搜索结果。

区分内容计划(主题评论)、预设(运行参数)和记忆(偏好)，保存/修改复用本任务新增真实接口。评论仅按需进入，说明通用语气/主题补充/词池/发送约束。模型说明区分外部Agent和平台视觉，Key用户设置；纯文案不要求设备/模型。复盘引用真实完成数量、分类/跳过、异常及证据，分清建议和已修改；首页角标保留数字/99+/红点与确认语义。保留初始只读检查、标准虚拟机准备、按需登录及原批次恢复流程。首次材料不能覆盖明确的纯文案请求。

仅一个完整技能包，新增参考文件必须加入同一打包白名单。适当增加可运行示例与回归，验证 Markdown 重建/ZIP 一致及现有客户端可跑。不用只有关键词匹配的测试代替行为验证。先由独立Agent使用旧Skill建立基线，再以无历史上下文执行新版场景。必要的数据与任务操作仅在隔离库/测试执行器完成。

## Task 3: 版本、规格、验收与本机更新

升级 packaging/version.json 开发迭代35，更新现有 integrate-opencode-agent-workbench 变更与相关主规格，不归档其中无关未完成验收。更新提示词说明及验收记录。先严格 OpenSpec、全量 Python unittest、前端测试/类型/lint/生产构建，再 API/首页下载复制检查。完成后唯一干净提交安全更新本机，备份并核对任务、草稿、配置、历史及暂停状态；不恢复旧任务、不操作MuMu。所有未通过范围必须如实交付。
