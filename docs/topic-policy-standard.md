# RiskFlow 主题关键词与提示词标准

## 核心结论

主题配置不是“堆关键词”。关键词只是帮助视觉模型理解语义的线索，最终命中必须同时满足：主要画面属于允许类别、当前画面有可核对证据、没有命中排除或安全阻断。

## 新主题统一写法

每个长期复用主题都按下面顺序定义：

1. `policy_id`：稳定英文标识，例如 `ai-manufacturing-plastics`。
2. `version`：语义边界改变时升级，例如 `1.0.0`。
3. `name`：给人看的中文名称。
4. `eligible_categories`：编号后的允许类别。每类都写主体范围、纳入线索、类内排除。
5. `adjacent_categories`：相关但不算精准命中的内容。
6. `global_exclusions`：广告、偶然关键词、安全问题等全局排除。
7. `evidence_requirement`：当前单帧至少要看到什么才能下结论。

## 类别模板

```text
类别名称：
主体范围：这个类别真正讨论或展示什么。
纳入线索：常见标题、对象、产品、流程、事件；只作语义提示。
类内排除：最容易被误认成该类别，但实际不算的内容。
正例：至少 2 个经人工确认的截图。
相邻例：至少 1 个同领域但不精准的截图。
反例：至少 2 个容易误触发的截图。
不确定例：至少 1 个单帧不足以下结论的截图。
```

## 关键词选择标准

- 优先使用能指向具体主体的实体词和过程词，例如“大模型评测”“吹膜机生产流程”。
- 泛词不能单独使用，例如“科技”“未来”“智能”“工厂”“包装”。
- 同一个词若常出现在用户名、评论、搜索建议或广告中，必须同时写入排除说明。
- 不要求画面逐字命中关键词；同义表达和清楚的视觉对象也可以作为证据。
- 不允许根据画外音、前后视频或看不见的上下文猜测。

## 判断顺序

1. 先检查广告、直播、商业跳转和其他安全阻断。
2. 再判断主要画面主体，不使用评论区和用户名替代主体。
3. 对照允许类别，找到至少一项具体证据。
4. 检查类内排除和全局排除。
5. 满足才是 `exact`；同领域不直接满足是 `adjacent`；明显无关是 `unrelated`；看不清是 `uncertain`。

## 评测最低标准

正式宣称准确率前，人工确认样本必须覆盖四种相关性，并至少包含“偶然关键词”和“纯视觉商业内容”两类硬负例。Codex、MBH 或第二模型给出的标签默认只是候选，不进入准确率分母。

当前样板策略位于 `fixed_runner/topic_policies/ai-manufacturing-plastics-v1.json`。复制它并替换业务类别、线索、排除和样本，即可建立下一个主题。
