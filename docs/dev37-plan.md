# dev.37 五台真机混合流实际使用修复

用户已明确要求按真实需求修复并在验证通过后运行。主路线仍为 MuMu；本次选择平台已展示的五台真机，不修改虚拟机或恢复旧任务。

## 范围

- Agent 计划入口接受当前设备清单中明确标为 physical 的 ADB 序列号，和虚拟机一样冻结、复核身份；不按名称猜测、不接受清单外地址、不静默缩小范围。
- 新建混合任务以 `hybrid_probability_mode=topic` 在搜索、主页两阶段按命中/未命中分别使用完整三项概率。安全页面、视觉安全和评论发送检查不变；未命中评论不套用主题话术。
- `round_interval_basis=completion` 在每台设备上一轮（含该轮检查）实际终态后休息指定分钟。持久化后续排程，不能越过正在休息的轮次。历史无字段任务保留 legacy/scheduled 行为。
- 不增加费用限制。不重做前端、不打包、不推送。
- 真机首页角标检查不进入 MuMu 专用准备流程；使用原物理设备控制档案和首页判断。显式 `batch_stop_policy=round_count` 不设执行时间截止，轮数完成才正常结束；原 deadline 批次保留到期行为，单次操作超时与安全停止不变。

## 风险与回退

身份混淆、旧任务语义漂移、重复提交及轮次乱序须由隔离回归覆盖。保留设备独占、未知写入不重放；业务失败留证并停止受影响批次。源码切换前备份与确认空闲，失败回退程序、不覆盖运行数据。

## 验收

五台物理设备经过真实计划服务生成 50 视频任务和 15 首页角标检查；重复提交为同批次，旧队列与草稿不变。两阶段命中 .7/.6/.5、未命中 .3/.2/.1，安全失败全零。实际轮末后休息 60 秒、检查先执行、重启不丢计时、不同设备隔离。依次严格规格、Python、控制台、接口、页面及必要设备预演，通过后更新本机并仅启动授权批次。
