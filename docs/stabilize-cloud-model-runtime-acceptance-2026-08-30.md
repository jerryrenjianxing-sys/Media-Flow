# RiskFlow 云端模型与长任务稳定性验收

验收时间：2026-08-30（Asia/Shanghai）

## 结论

本次正式窗口使用 4 台真实 Android 设备并行执行 10 个独立轮次，每轮 20 个视频。10/10 轮均以 `completed` 结束，整轮成功率 100%；共浏览 200 个视频，183/183 次主题模型判断返回有效结构，模型有效率 100%。按“至少 9/10 轮完成、模型有效率至少 95%、未知状态动作不自动重放”的验收口径通过。

## 动作安全审计

- 10 个运行轨迹中 `reaction_retry` 为 0。
- 两次点赞补点候选均因重新读取后的页面闸门不允许互动而记录 `reaction_retry_aborted`，没有再次点击。
- 两次身份验证均记录 `reaction_session_circuit_opened`，关闭本轮点赞与收藏后继续浏览。
- 本窗口没有评论发送尝试；3 条评论候选均被用户配置的发送前约束拦截，因此没有为了制造成功数据而放宽约束。
- 没有未知结果的状态改变动作被自动重放。

## 主要修复

1. OpenRouter 同模型供应商故障转移不再依赖是否配置备用模型，避免无备用模型时固定落到单一不稳定供应商。
2. 模型错误与页面异常分离；模型故障不再错误累计为页面异常或触发无意义的应用恢复。
3. 点赞/收藏只在重新读取后明确仍未激活时允许一次补点；未知、冲突或页面变化时不重放。
4. 平台身份安全验证使用标题与正文组合信号识别，安全返回后对本轮点赞/收藏熔断，浏览继续。

- 控制台：构建通过，7 项服务端渲染测试通过。
- lint：0 错误，1 条既有普通图片性能提示。
- OpenSpec：严格校验通过。
- 运行结束：4 台设备在线、4 个 Worker 身份已验证、0 运行任务、0 等待任务。
- 真实 Chrome：后台安全重启后记录页显示“记录已同步”，读取到 19 个设备任务组；最新轮次详情实测为 20 条视频、19/19 次有效模型判断，并正确显示点赞与收藏截图数量。

## 边界

本窗口没有实际发送评论，因为所有生成候选均被当前“评论发送前约束”安全拦截；这证明约束失败关闭，但不构成该窗口内的真实评论发送验收。评论发送仍保持零重试，并由离线回归覆盖。若后续要单独验收评论发送，应使用符合当前约束的内部测试内容和独立小窗口，不应关闭约束来追求表面成功率。
