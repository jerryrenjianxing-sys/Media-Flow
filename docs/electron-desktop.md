# MediaFlow Electron桌面运行与更新

现有外部Agent＋Skill＋业务后台架构不变。Electron承载Skill首页、任务台、设备、结果和设置，不内置另一套聊天系统。实际交付版本和通过范围以[STATUS](../STATUS.md)及对应发行说明为准。

## 运行与数据

- 桌面端使用精确Electron 44.7.0、electron-builder 26.17.0、electron-updater 6.8.10及npm锁文件。
- 程序资源在安装目录的resources/platform；Python、Node、ADB、控制组件和Skill随软件提供。业务数据仍在原有外部目录，升级不移动数据库或改写凭据。
- Python后台由当前Windows用户计划任务独立托管。启动桌面等待后台身份及健康检查；已有健康后台直接复用，不重复注册。
- 后台配置默认保存在外部数据目录的`instance-profile.json`；启动和登记核对文件句柄返回的实际路径，生产实例不能依赖Codex等MSIX应用的私有`LocalCache`映射。后台命令参数、包内解释器、脚本及工作目录逐项按Windows路径语义比对，不以路径子串判断归属。
- 后台在业务依赖导入前创建UTF-8启动诊断，记录阶段及安全错误摘要。管理入口区分任务禁用、运行时缺失、提前退出、端口占用与身份冲突；诊断保存在当前数据目录的`background-startup.json`和日志，无法读取配置时使用实例隔离的备用诊断目录。不会将凭据或上游原始正文写入诊断。
- NSIS辅助代码使用受信.NET程序集的绝对引用，不从含原生`System.dll`插件的当前目录解析编译依赖。安装阶段结果追加保存到程序目录旁的`.installation.log`（UTF-16），不随临时目录删除；后台诊断及PowerShell结构化结果仍为UTF-8。
- 关闭窗口收进托盘；“完全退出MediaFlow”通过同一安全停机入口核验后台退出后关闭桌面；“仅退出界面”保留后台。忙碌或失败不强行停止，保留窗口及诊断。退出与启动/更新收口串行，安装已交接时不并发退出。
- 普通浏览器不需要preload，现有页面继续可访问；桌面状态和更新通过有限preload接口提供。拒绝任意命令、路径与非本窗口IPC。
- 首页只交付短MD文件，两个主操作为复制文件和任务台，不再提供下载。首页固定复制`MediaFlow连接说明.md`，无文件名编辑或展开控件。桌面主进程生成实例私有、按名称/内容隔离的缓存，用Electron文件剪贴板复制；文件跨退出保留。兼容桥接仍校验合法.md文件名，定位仅允许已生成文件。不向页面开放任意路径、正文或命令。普通浏览器文件复制禁用并提示需桌面版，任务台可用；既有其他页面的受限文字剪贴板权限不扩大。

## 用户更新流程

每次启动检查一次GitHub，设置及托盘可手动检查。发现新版显示说明、“更新”和“稍后”；稍后只隐藏本次提示。

发现版本只读取已公开Release，不以Atom标签代替发行；排除草稿、未发布时间及其他频道，最多3页×100条、共享10秒截止。核对dev.yml、版本、安装资产及大小后，仍交原更新库下载。已安装与最高公开版本分别展示，候选高于公开版本时不降级。自动检查不可用仅在设置显示；手动可重试/关闭提示/查看日志，不冒充安装或后台失败。

点击更新后显示实际下载百分比、速度和传输量。差分失败时说明并转完整下载；并非每次都能节省固定比例。下载完成重新核对SHA512，校验失败不安装。

后台持久化更新操作编号并阻止新的业务领取、维护、虚拟机操作和人工控制。已有操作忙碌时等待、显示原因且可取消；等待任务本身不算运行占用，也不因此被恢复或清除。

安全空闲后核验后台已退出，再显示可取消倒计时，打开可见NSIS安装器。关闭软件不自动安装。取消或安装器启动失败时恢复原后台并对账原操作；结果不明不能换编号重放。

新程序启动后核对桌面及API目标版本，才结束原更新操作。软件更新不重放任务、修改队列暂停状态或清空数据。下载日志不记录Key或上游完整错误正文。

## 迁移与恢复

首次Electron版支持经过身份核实的dev.44 Velopack程序：保留原程序、任务定义、快捷方式和注册信息；取得校验一致的旧安装器作为恢复材料后才停旧后台。旧卸载完成后再注册新后台，防止旧卸载钩子删除新任务。

不能确认旧身份、后台未退出或目录仍有活动进程时停止迁移，不强杀无关程序。旧dev.44活动宿主不能遵守新更新门禁时，要求先通过旧版正常入口停止，再核验实际退出，不把旧停机误报为同步安全停机。安装失败保留transaction.json和程序备份，只回退程序，不覆盖数据库或删除新消息。

旧dev.44不支持实例隔离，因此在仍运行开发服务的同一Windows用户中不能把真实旧版迁移测试伪装为安全隔离夹具；尚未实测时必须标记未通过。

## 隔离验收

安装器接受 `/INSTANCEPROFILE=绝对路径`，Electron接受 `--instance-profile=绝对路径`。schema 1配置含id、acceptance、install_root、data_root、ui_port、api_port、stream_port和task_name；验收使用独立目录、端口、任务、注册键、窗口偏好和缓存。

验收模式禁用设备探测、Worker和模型调用，不接触开发数据。页面通过只读preload实例信息在请求发出前解析本地API地址；Electron重定向仅作隔离守卫，不依靠跨域重定向取得页面连接。无preload的普通浏览器保持原地址。验收模式不开放外部浏览器入口，以免绕过此定向。生产浏览器入口正常保留。

源码开发模式只连接现有服务，不注册计划任务、不下载更新。依赖缺失、端口被占用和实例身份不符均给出明确错误，不借用Codex进程或系统运行时兜底。

验收证据保存在忽略的work目录。自动测试通过不等于Windows窗口、实际dev.44迁移或真实GitHub升级已通过；分别记录。
