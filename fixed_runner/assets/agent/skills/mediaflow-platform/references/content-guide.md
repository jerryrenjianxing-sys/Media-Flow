# 内容计划、主题与评论

## 三类材料不要混用

| 对象 | 保存什么 | 不保存什么 | automation 动作 |
| --- | --- | --- | --- |
| 内容计划 | 主题、每个主题的搜索词、全局/主题评论模板、通用/主题词池 | 设备、轮数、概率、运行游标 | `content_plan_list/get/save/archive` |
| 任务预设 | 条数、轮数、停留、模式、概率、评论约束等运行参数 | 设备、密钥、真实运行结果 | `preset_list/save` |
| 记忆 | 用户稳定偏好、称呼、表达习惯 | 主题对象、搜索轮换游标、任务状态、密钥 | `memory_list/save/history/restore` |

保存内容计划或预设不会创建计划、启动 Worker 或操作设备。用户说“只保存”时，保存后停止；用户明确要求准备任务预览或运行时，才进入 `plan_tasks`，其中“先准备、不启动”只返回计划，不调用 `execute_plan`。修改内容计划用原 `content_plan_id` 保存不可变新版本，旧修订仍可读取；归档不删除历史。

## 从自然语言生成可用主题

不强制问卷。先复述目标，已有信息直接使用，只追问会改变边界的缺项。临时 `topic_prompt` 应短而清楚；内容计划中每个 `topic_prompt` 必填且不超过 800 字，每个 `search_query` 必填且不超过 80 字。内容计划须有 1～20 个主题，且至少一个启用。

长期主题的可填写 `topic_prompt` 固定按以下三段写，三个标题都要保留：

```text
命中：主要画面真正讨论或展示什么。
必须证据：当前画面至少能核对哪些对象、工序、产品、标题或界面。
排除：最容易误触发的相邻类别、广告、偶然关键词和不安全内容。
```

这是保存给内容计划的输入格式。平台执行或评测时可能产生的相关性标签不是 `topic_prompt` 的段落，不能替代上面的“命中 / 必须证据 / 排除”。

判断顺序固定为：先安全阻断，再看主要画面主体，再找必须证据，最后核对排除。关键词只是线索：

- 搜索结果不等于主题命中；搜索只负责进入候选内容。
- 不用用户名、评论区、搜索建议或偶然字幕替代主体证据。
- 工厂、设备或生产线画面能证明画面中存在生产活动，不能单独认证发布账号就是厂家。
- 不依赖没听到的音频、前后视频或看不见的上下文。

开发评测用的策略 ID、版本号、样本集和人工真值不是用户创建主题的门槛。没有人工真值时可以使用主题，但不得宣称准确率已经验证。

## 搜索词与轮换

搜索词使用 1～3 个明确实体词或过程词，不写长指令、评论要求、联系方式、无关热词或不可靠的否定语法。把排除项写进主题标准。

多组搜索词应保存为内容计划中多个有序、启用的主题条目，每个条目带一条 `search_query`。程序按**轮次**映射：第 1/2/3/4 轮使用第 1/2/3/4 个启用主题，超出后从头循环；同一轮的所有设备使用同一主题。每次新提交从第一个启用主题开始，并冻结当时的修订。它不是逐视频换词，也不需要把“下次组”游标写进记忆；保存新修订不会改变已经冻结的批次。

## 完整示例：坚果干果生产厂家

目标是寻找能由当前画面证明真实生产能力的坚果、干果、炒货或每日坚果制造内容，同时排除零售、仓发和吃播。

四组轮换搜索词：

1. `坚果工厂 生产线 源头厂家`
2. `每日坚果 OEM代工`
3. `干果炒货 自动化车间`
4. `坚果分装 生产包装线`

可直接复制到 `topic_prompt`：

```text
命中：视频主要内容是坚果、干果、炒货或每日坚果制造，展示实际产品以及生产车间、连续生产线或得到画面印证的 OEM/ODM、代加工、贴牌、产能、工艺、品控能力。

必须证据：当前画面能看到实际坚果/干果产品，并至少看到清洗、烘干、烘烤、去壳、筛选、色选、分级、调味、混料、称重、生产包装、质检中的一项；厂家能力宣传还须由设备、工序或质检画面印证。生产线称重、灌装、封口、装盒可作为生产包装证据。

排除：门店、商超、摊位、探店；仓库盘点、货架、拣货、人工装快递箱、贴面单、装车发货；吃播、试吃、测评、开箱；纯商品陈列、价格促销、直播切片；没有生产证据的厂家宣传、招商或泛食品内容。工厂原料库/成品库只有在主体仍是制造能力且同时出现生产工序时才可命中；只拍门头、办公室、样品间、账号名或字幕不命中。任何生产画面都不能单独认证发布者身份；证据不足不强行判为命中或排除。
```

可直接保存的完整参数在 [`examples/content-plan-nut-factory.json`](../examples/content-plan-nut-factory.json)。它把四组词建成四个启用主题，让平台执行轮次映射。保存新计划：

```powershell
./scripts/mediaflow.ps1 content_plan_save --arguments-file ./examples/content-plan-nut-factory.json --request-id REPLACE_WITH_UNIQUE_REQUEST_ID
```

读取返回的 `result.content_plan.plan_id` 和 `revision_id`；实际运行时两者一起放进 `plan_tasks.arguments.config`。要修改则在参数顶层补 `content_plan_id`，保留完整 `document`，用新的写请求编号保存新版本。不要猜 ID，不把占位符直接执行。

## 四种内容模式

| 模式 | 内容来源 | 主题判断 | 必要输入 |
| --- | --- | --- | --- |
| `general` | 首页推荐流 | 不做主题筛选；计划 ID 会被忽略 | 无主题字段 |
| `mixed` | 首页推荐流 | 对每条候选做主题判断 | `topic_prompt` 或内容计划修订 |
| `search` | 单一搜索结果流 | 对每条候选做主题判断 | `search_query`；可由内容计划当前轮提供 |
| `hybrid` | 搜索流与首页流按配置的有效视频段交替 | 两个来源都做主题判断 | `search_query`，以及主题标准/内容计划 |

`search_trust_results` 只影响搜索阶段的点赞/收藏概率路线：

- `false`：仍以当前画面判定是否命中；命中用 matched 概率，未命中的安全内容用通用概率，未命中评论固定阻断。
- `true`：搜索阶段的点赞/收藏把检索来源当作已选中来源，使用 matched 概率；评论仍要求当前画面真正命中。
- `hybrid` 的首页阶段不受 `search_trust_results` 影响：点赞和收藏即使命中也使用通用概率；评论仍须当前画面命中，命中后使用通用评论概率。

它从不意味着“搜索即命中”，不会跳过安全判断，也不会让未命中内容发表评论。严格查找生产厂家、合规筛选或证据要求高的场景默认 `false`。

## 复盘中的相关性标签

只有实际任务/评测证据返回相关性标签时，复盘才引用 `exact`、`adjacent`、`unrelated`、`uncertain`。证据不足是 `uncertain`，不能为了方便改写成 `unrelated` 或 `exact`；没有分类明细时不自行生成，也不据此宣称准确率。这四类只解释实际结果，绝不是用户可填写 `topic_prompt` 的结构。

## 评论材料与发送约束

评论仅在用户需要评论草稿、预览或发送时配置。纯主题定制不要求评论字段有内容。

- `document.comment_template`：所有主题共用的语气、长度、视角和表达偏好，最多 1000 字。
- `theme.comment_template`：当前主题相对全局模板的补充，最多 1000 字。
- `document.common_comment_pool`：通用候选词池。
- `theme.comment_pool`：主题专属候选词池，优先于通用词池。
- 每个词池最多 100 条；单条最多 80 字。标准条目为 `{"id":"stable-id","text":"候选句","enabled":true}`。
- `config.comment_policy_enabled` 与 `config.comment_policy_prompt`：发送前约束，说明哪些内容不要参与、哪些表达不要使用，最多 1000 字。它属于任务预设/任务参数，不属于评论写作模板。

词池是可微调候选，不是强制原样发送。固定安全规则、当前画面相关性、无推广/联系方式、不得伪造经历及发送前复核始终优先。命中约束、低置信、无效模型响应或模型异常时取消当前评论并继续后续视频。未指定互动时六项概率全部为 0；真实评论还需用户明确选择并设置 `preview_only=false`，只预览则保持 `true`。
