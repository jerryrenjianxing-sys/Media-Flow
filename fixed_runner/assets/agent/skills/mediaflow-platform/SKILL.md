# MediaFlow：把目标交给平台

你可以帮用户定制搜索主题、准备设备、安排任务、查看结果和消息提醒。外部 Agent 理解目标和整理文案；MediaFlow 的固定执行器负责设备操作。先接续用户已经说清的需求，只问会改变结果的缺项。

## 按目标开始

| 用户要什么 | 现在做什么 | 按需读取 |
| --- | --- | --- |
| 问“能做什么” | 简短介绍下面的能力与例子，沿用已有连接结果 | 本文件即可 |
| 写主题、搜索词或评论 | 直接完成文案，无需平台、设备或业务模型 | [内容指南](references/content-guide.md) |
| 保存、修改可复用方案 | 连接后读取对应对象，保存并交付回执 | [保存流程](references/workflows.md#保存与修改) |
| 准备虚拟机、应用或输入 | 只检查本次需要的条件，复用已有环境 | [配置引导](references/setup.md) |
| 查看方案或运行任务 | 保留已知参数，核对本次范围后按意图准备或提交 | [任务流程](references/workflows.md#从目标到运行) |
| 看结果、消息提醒、继续或排错 | 读取原任务及已有证据，按真实状态处理 | [工作流](references/workflows.md)、[故障处理](references/troubleshooting.md) |

主题标准使用“命中 / 必须证据 / 排除”三段，搜索词分组使用；坚果干果生产厂家的完整示例在内容指南。单纯写主题时不进行接入检查。

## 首次接入：一次检查即可

用户只交付MD连接文件或本 Skill、没有其他具体目标时：

1. 确认你能在用户这台 Windows 电脑执行本机命令。云端或另一台电脑的回环地址不是用户电脑；无法代查时说明限制，给用户连接卡里的检查命令。
2. **MD文件方式**：读取文件指向的现成 `SKILL.md`，运行其中提供的 PowerShell `check --connection-file` 命令。直接使用软件已有文件。文件名可更改，不影响内容中的接入方式。
   兼容已有ZIP：解压后直接读取本文件，在此目录运行 `powershell.exe -NoProfile -ExecutionPolicy Bypass -File ./scripts/mediaflow.ps1 check`。只为该进程选择执行方式，不改系统策略；无需全局安装或重启宿主。
3. `check` 只发一次只读 GET，共享5秒请求截止；不需要系统 Python，不创建工作文件，不扫描设备，不启动后台或任务。已有明确需求时，检查成功后直接接续该目标。
4. 连接成功，简短报告平台已连接及下一步。登记设备只是历史快照，不代表当前在线或本次任务就绪。仅在有助于用户时提及登记数量和检测时间；默认不展开任务历史、退役设备表或内部参数。

健康连接后的回复示意（状态须来自实际结果）：

> 已连接 MediaFlow。可以帮你定制主题、准备设备、安排任务和查看结果；设备是否可运行会在安排任务时核对。
> 例如：“找坚果干果生产厂家的视频，排除零售门店”“帮我准备一台虚拟机”“看看上次任务为什么失败”。你想先做哪一项？

用户已给具体需求时，以完成该目标代替末尾询问。用户只要求阅读、解释或修改材料时，直接完成该目标，不执行接入检查。

### 连接不成功

- 已核实后台停止：问“MediaFlow 尚未启动，需要我帮你启动吗？”等待回答，再按[启动服务](references/setup.md#启动服务仅在用户同意后)处理。
- 超时或拒绝连接：说明尚未连上、停止原因未确认；先询问用户或检查已知入口，不能仅凭超时认定软件没开。
- 路径失效、错误实例或运行时缺失：按客户端原因引导重新复制连接说明或打开已安装软件；详见故障处理。保留已有配置，不全盘搜索、猜路径或重复拉起后台。

## 使用现成客户端

连接卡带有 `--connection-file` 时，后续每次客户端调用均沿用它。客户端每次重读当前连接资料，显式文件优先；升级路径由软件更新，Agent 不缓存旧程序或 Python 路径。ZIP 没有本机连接资料时沿用原配置方式，见 [README](README.md)。

后续 Windows 命令沿用首次检查的进程级 PowerShell 启动方式，将 `check` 替换为目标动作；系统执行策略保持原样。

需要具体动作、参数和回执字段时才读取 [API 参考](references/api.md)。纯读不需要请求编号；写操作保存稳定唯一的 `request_id` 和回执。超时或结果未知时查询原编号，不能换编号重放。设备锁、计划冻结、任务队列及动作去重由平台承担。

## 方案、执行与评论分开表达

- “只保存”只保存内容或预设；“先看方案、不启动”只准备方案。
- 明确要求运行且参数齐全：正常创建并提交计划，不增加口令、确认卡或权限分级。已保存内容直接复用，不要求重复填写。
- 未指定互动时，点赞、收藏和评论概率默认全零，不继承旧高概率草稿。
- **评论仅预览**只表示生成评论、不发送（兼容字段 `preview_only=true`），不是整个任务不执行，也不禁用已明确选择的点赞或收藏。明确要求发送评论时使用对应发送设置。

区分“平台已连接、设备已登记、本次任务就绪、任务已提交、任务执行完成”。接入成功、排队成功或执行者启动都不能冒充业务完成。结果依据真实回执和证据；缺失结果说“尚无结果”，不补成零或成功。

当前“消息巡检”只看首页角标：有消息／无消息；数字清楚则记录原文，检查失败不当无消息。读取数量、证据与提醒时再读[消息巡检](references/workflows.md#消息巡检)。
