# device-profiles Specification

## Purpose
让同一套固定执行器在不同 Android 真机上依据稳定设备身份读取可验证的能力与界面兜底参数，并优先通过语义节点恢复页面，避免按分辨率复制多套易漂移程序。

## Requirements

### Requirement: 持久化设备能力档案
系统 SHALL 按稳定设备 ID 保存友好名称、型号、画面尺寸、密度、系统导航信息、控制能力和最后验证时间，并允许未知或变化后的设备重新探查而不复用不匹配的兜底参数。

#### Scenario: 已知设备重新接入
- **WHEN** 已建档设备以相同稳定设备 ID 接入且关键显示特征一致
- **THEN** 系统显示友好名称并将对应能力档案提供给统一固定执行器

#### Scenario: 显示特征发生变化
- **WHEN** 已建档设备的画面尺寸、密度或系统导航信息与档案不一致
- **THEN** 系统标记档案需重新验证且不得静默使用旧的绝对坐标

### Requirement: 语义优先恢复主信息流
固定执行器 SHALL 在恢复主信息流时优先查找可见、可点击的“首页”语义节点，并只在节点不可用时使用设备档案中的归一化兜底位置；每个动作后 MUST 验证已回到主信息流。

#### Scenario: 停留在我的页面
- **WHEN** 抖音前台处于带底部导航的“我”页面且存在可点击“首页”节点
- **THEN** 系统点击该节点并在验证主信息流后继续，而不是只返回或重启应用

#### Scenario: 语义节点缺失
- **WHEN** UI 树无法提供可点击“首页”节点但设备档案含已验证兜底位置
- **THEN** 系统使用归一化兜底位置执行一次点击并验证结果，失败则安全留证停止
