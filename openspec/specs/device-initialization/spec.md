# device-initialization Specification

## Purpose
让已完成 ADB 授权的 Android 设备通过 RiskFlow 独立完成控制组件准备、平台校准、人工断点续跑和可审计就绪判定，不依赖 MBH 或 Codex 常驻。

## Requirements

### Requirement: 独立初始化生命周期
系统 SHALL 为每台设备保存独立初始化记录，状态 MUST 为 `queued`、`running`、`waiting_user`、`ready`、`stale`、`failed` 或 `cancelled` 之一，且不得把初始化记录混入普通社媒任务。

#### Scenario: 新设备开始初始化
- **WHEN** 用户对在线且已授权的新设备启动初始化
- **THEN** 系统创建一条初始化记录并按阶段推进，同时保持普通任务记录与终态不变

#### Scenario: 重复提交同一步骤
- **WHEN** 用户重复点击开始或继续且对应阶段已经成功
- **THEN** 系统复用已验证结果，不重复安装组件或执行写入验收

### Requirement: 控制能力准备与恢复
初始化 SHALL 探测设备显示与导航事实，准备并验证 uiautomator2、截图、UI 树、滑动和中文输入能力；输入验证结束后 MUST 恢复初始化前的默认输入法。现有真机 SHALL 继续使用输入组件安装与人工断点路径；Root 虚拟机在系统明确拒绝输入法切换时 MAY 使用 UIAutomator 控件输入兜底，但必须在无写入搜索框中写入中文并原样回读成功后才可通过。

#### Scenario: 控制能力全部通过
- **WHEN** 设备可读取截图和 UI 树、可执行无害滑动且 FastInputIME 能完成中文输入
- **THEN** 系统记录每项能力、组件版本和验证时间并继续平台校准

#### Scenario: 厂商拦截安装
- **WHEN** 控制组件安装需要手机侧确认或被厂商安全页面阻断
- **THEN** 初始化进入 `waiting_user` 并展示具体人工步骤，用户完成后从同一阶段继续

#### Scenario: Root 虚拟机拒绝切换输入法
- **WHEN** 控制 APK 已安装、设备为 Root 且系统禁用 `ime enable/set`
- **THEN** 初始化记录控件输入兜底模式并继续无写入搜索校准，不要求用户处理不存在的安装弹窗

#### Scenario: 控件输入回读失败
- **WHEN** 固定程序无法从搜索输入框读回完全一致的中文测试词
- **THEN** 初始化不得标记中文输入能力通过，也不得生成 `ready` 档案

#### Scenario: 真机兼容路径不变
- **WHEN** 非 Root 真机需要厂商安装确认或输入组件可以正常启用
- **THEN** 系统继续使用既有人工断点或输入组件路径，并在结束后恢复原输入法

### Requirement: 抖音安全导航校准
初始化 SHALL 检查抖音已安装且可用，并在不产生账号写入的阶段验证主页、搜索、视频结果、沉浸流、互动控件和评论面板的定位与页面转移。

#### Scenario: 无写入校准成功
- **WHEN** 固定程序能恢复主页、进入搜索流、打开并关闭评论区并重新识别当前页面
- **THEN** 系统保存经复验的抖音平台档案和对应截图/UI 树证据

#### Scenario: 目标应用未登录
- **WHEN** 初始化识别到登录、身份验证或不可自动处理的账号页面
- **THEN** 初始化进入 `waiting_user`，不得自动输入凭据、绕过验证或错误标记为就绪

### Requirement: 显式完整写入验收
初始化 MUST 默认无写入；只有用户在本次初始化显式开启完整写入验收时，固定程序才可在普通、安全、非直播和非广告视频上执行一次有界验证。

#### Scenario: 点赞收藏验收
- **WHEN** 用户显式开启写入验收且固定程序明确读取到动作原状态
- **THEN** 系统执行一次点赞和收藏、验证生效、恢复原状态并再次验证

#### Scenario: 评论验收
- **WHEN** 用户显式开启写入验收且安全视频评论入口与发送控件均已验证
- **THEN** 系统最多发送一次固定初始化测试评论并保存发送后截图，不自动删除评论

#### Scenario: 写入结果未知
- **WHEN** 任一状态改变动作后的结果无法确认
- **THEN** 初始化失败留证且不得重放对应动作

### Requirement: 初始化报告与人工断点
系统 SHALL 保存逐阶段结果、证据、失败原因和人工步骤，并允许用户继续、重新校准、查看报告或取消。

#### Scenario: 用户完成手机侧确认
- **WHEN** `waiting_user` 状态的用户点击继续
- **THEN** 固定程序重新观察设备和当前阶段前置条件，满足后继续，不满足则保留等待及新证据

#### Scenario: 初始化完成
- **WHEN** 必需控制能力和抖音平台校准全部通过
- **THEN** 初始化进入 `ready` 并在设备状态中展示完成时间和档案版本

### Requirement: 自动初始化后执行零写入自检
自动接管的虚拟机 SHALL 复用现有独立初始化，完整通过后再执行一轮 3 条视频的全零动作自检；自检必须保持点赞、收藏、评论概率为零并启用评论预览。

#### Scenario: 初始化与自检通过
- **WHEN** 自动初始化进入 `ready` 且 3 条自检任务完整完成、模型有效、页面错误为零、写入计数为零
- **THEN** 系统把该虚拟机标记为自动接管已验证，并允许进入当前方案阶段

#### Scenario: 初始化或自检失败
- **WHEN** 初始化进入等待、失败、取消或陈旧状态，或者自检不是完整成功
- **THEN** 自动流水线停在对应阶段并保存原因，不重新初始化、不重新提交自检
