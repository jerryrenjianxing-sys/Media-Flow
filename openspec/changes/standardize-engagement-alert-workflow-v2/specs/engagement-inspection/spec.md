## MODIFIED Requirements

### Requirement: 单次巡检覆盖版本化列表入口
系统 SHALL 保持兼容的 v1 巡检，并在任务明确冻结 `inspection_workflow_version=v2` 时依次检查消息入口角标、赞与收藏、收到的评论、收到的弹幕和主页访客。v2 MUST 在每个页面进入后及每次滑动动作后重新截图观察，禁止打开会话、回复、快捷互动、他人主页或访客设置。

#### Scenario: 当前聚合消息页面已校准
- **WHEN** v2 任务在已校准的应用版本和显示签名上找到“互动消息 → 全部消息”
- **THEN** 系统按白名单选择点赞、评论和弹幕入口并分别收口
- **AND** 不点击列表行中的回复、点赞、关注或主页控件

#### Scenario: 应用或显示签名变化
- **WHEN** 运行时应用版本或显示签名与任务冻结值不同
- **THEN** v2 在执行任何巡检入口前停止原任务并分类为可恢复前置条件
- **AND** 系统以原任务 ID 和当前版本指纹保证最多自动复验一次
- **AND** 复验禁用旧坐标，只使用当前 UI 语义连续验证三遍页面与恢复路径
- **AND** 三遍一致时保存新的版本化档案并用原冻结参数创建一条关联替代任务
- **AND** 原任务保持失败事实，通过父子关系显示“复验后完成”

#### Scenario: 版本复验不一致或需要登录验证
- **WHEN** 当前语义控件已变化、出现登录或安全验证、页面无法恢复，或三遍结果不一致
- **THEN** 恢复记录进入 `waiting_user` 并保留最小截图与 UI 树
- **AND** 系统不得使用旧坐标、不得循环复验且不得创建替代任务

#### Scenario: 巡检动作开始后发生漂移
- **WHEN** 任务已经进入任一巡检分区后才发现版本或显示漂移
- **THEN** 系统失败关闭且不得自动复验或重放

### Requirement: 巡检结果区分控制流程和数据完整性
系统 SHALL 分别统计控制流程成功率与数据完整率。平台缺少某个入口 SHALL 标记为不可用或降级，不得误报为“无互动”，也不得计入程序失败。

#### Scenario: 一批巡检完成
- **WHEN** 用户查看同一批设备的巡检结果
- **THEN** 页面分别显示流程完成、部分入口不可用、前置条件已自动复验并完成、等待人工处理和真正程序失败
- **AND** 版本问题显示预期/实际版本、复验进度、替代任务和最终结果
- **AND** 控制流程成功率基于领取、导航、读取、恢复和落盘计算
- **AND** 数据完整率基于实际存在且成功读取的消息、点赞、评论、弹幕和访客入口计算

### Requirement: 访客变化使用本地脱敏基线
系统 SHALL 以访客页进入后的首屏建立设备级基线，仅保存行数、首行文本哈希和裁剪区视觉指纹。首次成功 MUST 只建立基线；UI 与视觉证据共同确认变化时才提醒；证据冲突 MUST 标为待确认且不得覆盖旧基线。

#### Scenario: 首次成功巡检
- **WHEN** 设备尚无匹配应用和显示签名的访客基线
- **THEN** 系统保存脱敏基线且不产生访客提醒

#### Scenario: 证据冲突
- **WHEN** UI 哈希变化但视觉指纹未变化，或反之
- **THEN** 系统记录待确认、不提醒且保留旧基线

### Requirement: 成功截图为临时证据
v2 成功运行的步骤截图和 UI 树 SHALL 只存在于当次运行临时范围并在结果落盘后删除。失败运行 MAY 保留最小现场截图和 UI 树，但公开接口 MUST NOT 返回原始图像、身份文本或绝对路径。

#### Scenario: 巡检完整成功
- **WHEN** 四个分区均完成并确认返回首页
- **THEN** 系统删除该次 `inspection-v2-*` 原图和 UI 树
- **AND** 只保留动作计数、脱敏结论和指纹
