## Context

2026-09-01 对抖音5号 `6HJ4C19917021309`、抖音 33.0.0、1080×2340 显示环境进行了三遍 MBH 校准。后两遍页面语义与恢复路径一致。实际入口为“互动消息 → 全部消息”，点赞入口显示为“赞与收藏”，评论和弹幕为两个独立筛选项；主页访客入口使用“新访客”或“主页访客”语义。

## Decisions

### 1. v1/v2 在提交时冻结

设备档案提供 v2 校准版本、应用版本和显示签名。计划器创建任务时复制这些值；Worker 不根据后续档案变化重写已排队任务。未校准设备继续 v1。

### 2. 固定执行器仍是唯一动作平面

MBH 仅用于逐步探索与校准。正式执行继续由每设备唯一 Worker、RiskFlow 设备锁和 `EngagementInspector` 完成。v2 只点击语义白名单入口，禁止会话、快捷互动、他人主页和设置控件。

### 3. 访客检测使用双证据本地基线

基线记录可见行数、首行文本哈希和首行裁剪区视觉指纹。首次成功只建基线；UI 与视觉共同变化才提醒；证据冲突标为待确认且不覆盖旧基线。原始姓名和图像不进入数据库。

### 4. 一次巡检聚合一条提醒

私信、点赞、评论弹幕和确认后的访客变化合并为一条提醒。设备与来源摘要生成稳定指纹并由数据库唯一约束去重。横幅只在确认接口成功后跳转并关闭，历史记录保留。

### 5. 临时截图按运行结果收口

成功 v2 只保留动作计数、状态和哈希，删除 `inspection-v2-*` 原图/UI 树。失败保留最小现场证据供本地诊断，不进入提醒接口。

### 6. 动作前版本漂移采用一次性自愈

应用版本或显示签名在任何巡检入口点击前发生变化时，原任务保持失败并创建独立恢复记录。Worker 在同一设备独占上下文中只使用 UI 语义完成三遍只读复验；复验不会打开具体私信会话，也不会执行点赞、收藏、评论或回复。三遍语义与恢复结果一致后，设备档案写入新的版本化巡检校准，并创建一条携带原任务冻结参数的替代任务。

恢复以“原任务 ID + 当前版本指纹”幂等，同一漂移最多尝试一次。若语义变化、登录验证、页面恢复失败或三遍不一致，状态停在 `waiting_user`；如果原任务已经进入任一巡检分区，则继续禁止自动重放。结果展示通过恢复记录关联原任务与替代任务，不修改原任务终态。

## Calibration Receipt

- 目标：仅抖音5号；应用 33.0.0；显示签名 `1080x2340x480x0x100`。
- 方法：`Mobilerun → local-android-adb → Portal`，观察—单步动作—再观察—验证，共三遍。
- 结论：三遍均安全返回首页，后两遍页面语义一致；访客列表四次有效下滑后到达边界。
- 动作边界：未打开会话、未回复、未点赞/收藏/评论、未关注、未进入他人主页、未修改访客设置。
- 隐私：回执不含账号名、私信文本、访客身份、截图或 UI 原文。
- 队列复验：实际领取顺序为第1～5轮、v2巡检、第6轮；七个任务均由同一执行者串行领取，点赞、收藏、评论和回复均为0。云模型密钥缺失使视频轮次降级，但未阻止本地巡检或第6轮领取。
- 设备差异：队列期间出现未提供已校准访客入口的企业主页变体。v2 完成消息、点赞、评论和弹幕后对访客分区失败关闭，未把其他主页快捷入口当作访客记录；该差异只记录为设备/账号级事实。
