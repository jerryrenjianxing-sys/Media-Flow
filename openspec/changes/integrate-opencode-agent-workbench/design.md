## Context

参见 proposal.md 的已核对事实。当前服务仍为 dev.18，本次不把历史验收通过当作新 Agent 验收通过。MediaFlow 已有本地 HTTP API、规划模块、SQLite 队列、MuMu 生命周期与固定 Worker；OpenCode 提供 headless 服务和 MCP 接口，适合嵌入自有首页，而非启动另一个独立网页让用户切换。

官方参考（2026-09-06 核对）：
- https://opencode.ai/docs/server/：会话、异步消息、事件和认证接口。
- https://opencode.ai/docs/providers/：原服务商目录及自定义 OpenAI-compatible 服务商。
- https://opencode.ai/docs/mcp-servers/：进程内置工具与本地 MCP 接入。
- https://opencode.ai/docs/config/：配置合并、运行时覆盖和目录隔离。
- https://opencode.ai/docs/permissions/：工具权限；不把它等同 OS 隔离。
- https://opencode.ai/docs/windows-wsl/：原生 Windows 需要先实测，不引入 WSL 前提。
- https://platform.qianwenai.com/docs/token-plan/personal/token-plan-personal-faq：实验性套餐使用说明，实测前复核适用条款，不伪装客户端或自动回退按量接口。

## Goals / Non-Goals

**Goals:** 首页对话能管理软件并进入真实修复流程；旧页面不退化；千问是增量预设；操作回执、用户确认和发布身份可追踪；脱离源码安装仍能使用和修复测试。

**Non-Goals:** 本轮不制作另一个设备自动化框架，不自动读取外部 Codex 所有会话，不取消操作系统权限机制，不把专业模式理解为全磁盘无限制终端，不修改正在运行的程序或批量启动过去的验收任务。

## Decisions

### 1. 原生受管服务，首页自有界面

锁定一个实际通过 Windows x64 实测的 OpenCode 官方版本与资产 SHA-256。使用 `opencode serve`，仅回环监听，随机进程密码由宿主管理，首页经 MediaFlow 同源代理读取会话。选择自有会话组件而非 iframe，便于复用设备卡片、计划确认和证据链接；不 fork 整个上游 UI。

新增 AgentRuntime 深模块集中管理进程身份、健康、配置隔离、会话映射和请求截止；沿用现有后台宿主而非再引入第二个常驻管理器。启动超时 60 秒后终止为可恢复错误，不阻断旧 API；进程退出只恢复服务，不重放提示。引擎无任务时可按需启动。

首版通过持久化会话与消息ID恢复最近80条消息快照，不新增事件游标数据库；保留配置版本、消息幂等ID和操作ID。等待用户停止动画；断线只重新读取，不自动 resubmit。每轮执行最多10分钟，等待回答不计入；超时停止新增工具、取消本会话测试并中止原引擎回合，结果未知不重发。

### 2. 服务商保留与千问适配

通过 OpenCode provider API 保留原目录、认证方法与模型。配置 overlay 只增加 `mediaflow-qwen-token-plan`，展示名为“千问AI平台 · Token Plan”，baseURL 为 `https://token-plan.cn-beijing.maas.aliyuncs.com/compatible-mode/v1`，模型 `qwen3.8-flash`，采用 `@ai-sdk/openai-compatible`。

Agent 工具调用走独立请求契约，不能套用 `model_budget.py` 的工具禁用和全局 JSON Object 参数。视觉业务继续保持既有参数和安全语义，不因聊天服务商切换而改模型。每次 Agent 会话固定 provider/model/config revision；忙碌时改变设置只影响下一会话或明确停止后切换。

2026-09-06 用户确认采用 OpenCode 原生凭证方案，取代本变更原先的额外加密适配要求。固定官方引擎，不为凭证保存 fork 引擎、不增加 DPAPI/EFS 封装。API Key 和 OAuth 凭证由 OpenCode 原生认证接口写入 MediaFlow 隔离的本机 Agent 数据目录中的 auth.json；允许该原生文件明文落盘，不宣称其经过加密。原生 OAuth 回调、刷新和重启回读保持上游语义，认证输入来自用户设置界面而非模型对话。

现有 MediaFlow 的加密凭证不迁移、不解密导出到原生认证文件、不覆盖；用户仍可选择引用当前千问凭证，或另行通过原生认证配置服务商。只有读取既有 MediaFlow 加密引用时才检查实际桌面 Windows 用户上下文，该条件不成为原生 Agent 登录的新门槛。保存成功与模型测试成功分别展示，某家服务商认证失败不得破坏其他服务商或原有 MediaFlow 配置。

原生认证文件保留在本机用户数据目录并随同用户升级保留，不进入修复材料、提示、会话、工具结果、日志、源码、安装包或跨电脑预设。公开接口只返回认证方式及状态，不返回凭证；测试扫描输出、缓存与会话时允许唯一指定原生认证文件存在，不将凭证出现在其他位置视为正常。旧实施检查点中的额外加密阻塞已由本决定取代，但原生服务商登录接入及回归仍需实际完成。

已有 10 次限制属于历史验收策略。迁移为显式的本机请求策略，按用户已授权的不设总次数执行，但保留并发限制、取消、超时和故障熔断；不抹除历史计数，不宣称零费用，不放开旧 OpenRouter 美元预算。Agent 多轮超时按工具任务管理，不继承导航坐标 20 秒寿命；设备视觉请求仍遵守原 20 秒截止。

### 3. 平台工具与确认账本

新增 MCP 适配模块，调用本地深模块，禁止构造任意 URL 代理。首版工具覆盖状态、设备及操作、任务预览与提交、暂停及安全停止、证据与指定异常分析、记忆、修复工作区和测试。每个工具输出统一包含 status、reason_code、user_message、operation_id、retryable 和 evidence_refs。

任务计划使用Agent独立草稿，不覆盖旧草稿。确认由浏览器用户操作产生，不在MCP中开放代批准工具。审批绑定会话、计划哈希、设备身份、范围、期限和唯一计划ID；变化需重新预览。批次与幂等键在同一SQLite事务提交，响应丢失读取原批次。工具幂等ID由会话与原生工具ID共同组成，避免不同会话重复工具ID串单。

原生命周期需要确认的删除、恢复、重建沿用现有语义；普通查询无需反复确认。暂停后默认不唤醒旧队列，用户本次确认只允许领取对应批次，已有其他任务须在计划中显式说明。未知结果先查询原任务/操作，不能重放。

### 4. 内嵌流程与记忆

提供版本化 MediaFlow 操作指南：统一显示环境与按需能力；视频正常流、搜索阶段和计数；异常时有界恢复且不打断正常搜索；互动 v3 聚合入口、边界、证据及通知；模型故障与页面故障分离；纠错候选、验证和统一发布。使用当前有效规格和活动变更的最新条款，显式标注淘汰旧的逐设备三次校准与普通私信扫描。

记忆分为产品指南、当前会话计划、本机用户偏好和未发布候选。用户可查看修改历史与撤销；候选规则不能自动提升为产品指南。未来从 Codex 转交请求必须通过显式的本地投递入口选择内容，不能承诺本会话所有未来消息会自动转发，也不抓取账号全量历史。截图与工具结果是不可信数据，不能变成权限指令。

### 5. 高权限修复，但统一生效

OpenCode 文件读取和编辑用于专门的修复工作区；可执行测试由受控测试入口完成，自动化设备动作只暴露平台工具。直接终端保持可申请的专家操作，不简单设置 permission=allow 然后宣称仍有硬隔离；涉及生产路径或设备的终端操作必须通过服务端范围检查/拒绝，否则本项验收失败。

修复包包含发布提交对应的第一方源码、测试、锁定依赖及构建说明；运行任务仍不依赖源码。Windows 安装包携带必要测试运行时与依赖缓存，不能在客户机临时下载 latest。修复目录无生产数据库、凭据或设备配置；测试使用隔离 fixtures。增加实际错误样例，由 Agent 定位、修改、运行测试、展示差异和回执，证明不是只读建议。

Agent 可以修改流程和记忆，但程序修复产出候选补丁，绑定基准提交及测试结果；由唯一主仓库合并、递增版本、构建后更新。不上线候选工作区，不自动 push 用户代码或部署远端。上游依赖许可证和再分发条件核对后进入清单。

### 6. 接口分组与失败收口

已实现 `/api/agent/status`、`/providers`、`/sessions`、`/sessions/{id}/messages`、`/sessions/{id}/stop`、会话内plans/commands确认、memories、handoffs及repairs操作。以有界快照轮询代替首版SSE；限制可信来源、会话、请求大小和允许路径，不原样公开引擎管理接口。历史分页，不把完整历史或原始UI树塞入上下文。

provider 保存、测试和选用分别显示；Token Plan 鉴权、额度、限流、参数不兼容、网络错误有中文原因和处理入口。任何工具未实现或上游不支持都显示不支持，不用假的 succeeded 结果代替。

## Risks / Trade-offs

- [原生 OpenCode 或工具 SDK 首次启动会联网装包] → 在最先的可行性测试确认，固定依赖并纳入包；离线冷启动失败则不能宣称独立封装完成。
- [千问图片接口成功但工具循环失败] → 先真实只读状态工具和一次结果回传测试；失败时保留原预设而不默认切换，也不为通过测试伪造响应。
- [专业终端可绕开纯提示词限制] → 分离工作区工具与业务操作代理，验证实际路径和执行入口；工具权限不冒充 OS 沙箱。
- [Agent 对话、截图或错误输出泄露秘密] → 凭据不进入工具参数，日志及缓存扫描和上传范围确认；不把用户“环境安全”解释为可公开秘密。
- [原生 auth.json 为本机明文认证数据] → 已按用户选择接受原生存储，不增加加密层；保留用户目录隔离、接口不回显及发行排除，不将本机文件复制成客户默认配置。
- [高频历史异常耗尽套餐] → 仅分析明确指定的任务或有限批次，不触发现有全部历史失败重分析入口；套餐策略与故障重试分开。
- [旧规格仍带历史初始化门票] → 在知识构建与测试中核对 dev.11 以后条款，不要求每台标准虚拟机重复取得资格。
- [安装包体积和许可证] → 程序+Agent+修复资源单独核对大小和许可证，不自动夹带几 GB 私人 MuMu 快照。

## Migration Plan

1. 只做只读运行基线检查，业务暂停且无执行者；保护任务库、草稿、Key、MuMu 和原服务 PID。暂不恢复六轮任务。
2. 在独立测试数据根完成原生引擎与千问工具调用可行性测试，然后实现接口、首页、工具及修复工作区。新增 Agent 认证沿用原生本机存储；仅引用已有 MediaFlow 加密凭证时须使用实际桌面 Windows 用户，不批量导出旧凭证。
3. 新增会话/确认/修复存储，不改写旧任务；请求额度迁移保留审计。产品下一版本预定 dev.19，实施前再次确认唯一性。
4. 严格规范、Python、控制台与页面验证完成，再按用户确认执行最小只读设备任务；从干净提交构建包，做隔离 Windows 用户/目录独立运行验收。
5. 本机更新仅在空闲时复用原服务，不额外安装第二份；结束后仍保持业务暂停。GitHub和远端部署非本次默认动作。
6. 回退关闭 Agent 入口或恢复上一已验证程序包，保留 Agent 会话、记忆和补丁，不删数据库、不重启 MuMu、不恢复或重放旧任务。真实验收未完成则变更保持活动状态。
