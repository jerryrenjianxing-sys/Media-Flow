## Purpose

为 MediaFlow 提供内嵌对话式操作与修复工作台，使专业用户能够通过明确的任务计划、真实工具回执及可恢复会话操作现有软件，并在保留既有界面和固定设备执行链路的基础上验证、提交统一版本的修复。

## ADDED Requirements

### Requirement: 混合首页保留完整旧功能
系统 SHALL 在首页提供内嵌 Agent 会话，并保留现有任务参数、设备管理、结果与设置入口；Agent 不可用不得导致旧界面不可用。

#### Scenario: Agent 独立首页
- **WHEN** 用户打开首页
- **THEN** 只加载 MediaFlow 助手工作区；原表单位于 /workbench，旧设备、结果和设置从管理中心进入，聊天不得改写旧任务草稿

#### Scenario: Agent 启动失败
- **WHEN** Agent 依赖缺失、端口冲突或进程退出
- **THEN** 首页显示明确原因、重试和传统任务台入口，已有后台任务不受影响

#### Scenario: 插件资源扫描慢或不可访问
- **WHEN** 插件准备扫描超过截止时间，或文件缺失、损坏、权限不足、磁盘异常
- **THEN** 系统区分具体原因，保存阶段、耗时与无秘密诊断编号；允许显式重试复用已验证资源，不残留上次错误，不自动重放会话或设备任务

### Requirement: 会话与操作可恢复
系统 MUST 持久化会话、用户问题、工具调用关联及操作回执，区分排队、执行、等待回答、等待确认、完成、失败和取消；所有执行阶段 SHALL 有截止时间、停止入口及最近进度。

#### Scenario: 关闭页面后重新打开
- **WHEN** 用户在 Agent 等待确认或执行操作期间关闭并重新打开页面
- **THEN** 恢复原会话和真实操作状态，不自动重复发送提示或执行操作

#### Scenario: 切页和读取故障
- **WHEN** 用户切到设备页再返回、刷新或发生服务断连
- **THEN** 通过 URL 或最近会话恢复选择、未发送草稿、待回答内容和原请求 ID；区分加载、空白、读取失败，迟到响应不覆盖其他会话

#### Scenario: 执行者未启动
- **WHEN** 已确认计划的固定执行者启动失败
- **THEN** 原批次保留，持久化执行者错误和显式恢复入口，不误报虚拟机未运行，不重复生成任务

#### Scenario: 服务重启且结果未知
- **WHEN** 工具派发后 Agent 或后端重启，不能确定操作结果
- **THEN** 查询原操作回执并显示等待确认，不自动重发动作

#### Scenario: 用户停止会话
- **WHEN** 用户点击停止
- **THEN** 停止新增工具调用；已提交设备任务通过既有安全停止接口收口，不将聊天停止冒充设备已经停止

### Requirement: 原服务商预设增量扩展
系统 SHALL 保留所集成 Agent 的原有服务商目录、模型选择和认证方式，仅额外加入独立的千问AI平台 Token Plan 预设，使用 qwen3.8-flash 及指定兼容地址；不覆盖其他千问或 OpenRouter 配置，不自动切换服务商。

#### Scenario: 用户选择其他服务商
- **WHEN** 用户打开服务商选择并配置原目录中支持的服务商
- **THEN** 原认证和模型选择仍可使用，不要求配置千问

#### Scenario: 用户选择千问 Token Plan
- **WHEN** 用户选择新增预设
- **THEN** 系统提供预置地址、独立凭证状态及实验性套餐说明，不要求用户手填地址

### Requirement: 真正的工具调用和凭证隔离
Agent 请求 SHALL 支持所选模型实际能力及工具调用协议，不能用仅图片或文本响应的成功替代工具执行验收。Agent 凭证 SHALL 沿用官方 OpenCode 按服务商保存的原生认证方式，在独立的本机 Agent 数据目录使用 auth.json，允许原生明文存储，不增加加密适配或定制引擎。凭证 MUST NOT 进入会话正文、工具结果、记忆、日志、源码或安装包；接口不得回显凭证。既有 MediaFlow 加密凭证 MUST 保持不变，不自动导出或迁移。

#### Scenario: 视觉测试成功但工具协议失败
- **WHEN** 千问图片测试通过而 Agent 工具调用格式不兼容
- **THEN** 独立显示 Agent 工具能力未通过及原因，不显示可接管软件

#### Scenario: 使用当前千问配置
- **WHEN** 用户选择关联已保存千问凭证
- **THEN** 后端在当前 Windows 用户上下文读取凭证，不返回明文给网页或 Agent 对话，失败保留原配置

#### Scenario: 原生认证保存和恢复
- **WHEN** 用户在服务商设置中提交 API Key 或完成原生 OAuth 登录，随后重启软件
- **THEN** 使用隔离数据目录内的原生认证文件恢复和刷新认证，不要求额外加密初始化；界面分别显示已保存和实际测试状态，不把保存成功当作模型验证通过

#### Scenario: 认证失败不破坏其他配置
- **WHEN** 某一服务商认证失败或用户替换该服务商的凭证
- **THEN** 显示该服务商的错误和重试入口，其他服务商认证及既有 MediaFlow 加密配置保持不变，不从聊天读取 Key

#### Scenario: 原有限额迁移
- **WHEN** 当前用户采用已经授权的不设固定请求总次数配置
- **THEN** 不再被历史 10 次验收额度拦截，但保留可停止、逐调用记录、故障熔断和上游限额处理，不自动改用其他付费线路

### Requirement: 必要参数追问与计划确认
Agent SHALL 先读取真实库存与当前任务状态，只询问缺失的设备范围、视频数量及轮次、内容入口或搜索词、巡检频率、互动方式及停止条件；已知参数不得反复追问。新业务任务 MUST 展示后端生成的冻结计划并取得用户确认后再开始。

#### Scenario: 用户只说跑这几台设备
- **WHEN** 设备指代或关键参数尚不明确
- **THEN** Agent 汇总缺少参数供用户回答，不创建任务、不启动设备

#### Scenario: 参数已经齐全
- **WHEN** 用户给出明确设备及完整参数
- **THEN** 若用户要求执行则展示冻结回执并直接提交，不重复要求点击确认；若仅策划则只生成预览

#### Scenario: 库存永久编号用于任务计划
- **WHEN** Agent 使用设备清单返回的永久虚拟设备ID生成计划
- **THEN** 后端从同一次真实库存观察解析唯一ADB映射，冻结身份和端点；不要求模型猜测临时地址。无ADB或身份不唯一时给出具体原因，确认时再次核对身份，不静默切换执行设备。

#### Scenario: 确认后重复请求
- **WHEN** 客户端超时重发同一确认或 Agent 重复调用提交工具
- **THEN** 返回同一任务批次回执，不重复创建；计划或设备状态变化时旧确认失效

#### Scenario: 在线虚拟机保留任务停止标志
- **WHEN** 所选虚拟机仍在线但任务安全停止标志存在
- **THEN** 明确区分任务停止和虚拟机关机，用户可在聊天明确恢复本批次或使用卡片；普通继续不解除紧急停止。在同一提交事务中校验占用及所有自动操作停止状态，失败时保留停止标志。全局队列和其他设备保持暂停，原已提交批次只恢复原任务，不重新生成。

### Requirement: 工具操作必须可审计且结果真实
Agent SHALL 能通过软件工具查询状态、管理虚拟机、准备和运行任务、停止、查看证据及发起故障分析；任何宣称完成的操作 MUST 引用真实任务或操作回执。未接入能力 SHALL 明示而不是输出虚构执行结果。

#### Scenario: 用户请求诊断巡检失败
- **WHEN** Agent 读取指定任务的异常
- **THEN** 按阶段、截图与 UI 摘要报告原因和证据，缺少现场时明确无法确认，不批量重试全部历史分析

#### Scenario: 设备被占用
- **WHEN** Agent 请求生命周期或维护操作时设备已有执行者
- **THEN** 复用既有占用判断并返回占用者和可执行处理入口，不抢锁

### Requirement: 流程知识与记忆版本化
系统 SHALL 内置当前有效的视频、互动巡检、页面恢复、模型故障及版本发布指南，并提供有来源和版本的本机记忆查看、编辑、禁用及撤销。历史过时条款、网页内容和设备截图 MUST NOT 自动成为新指令或授权。

#### Scenario: 用户要求记住新的偏好
- **WHEN** 用户明确要求保存操作偏好
- **THEN** 保存可见的本机记忆版本；不得把偏好解释为永久删除授权或覆盖固定执行器规则

#### Scenario: 巡检知识加载
- **WHEN** Agent 准备互动巡检
- **THEN** 使用消息到互动聚合页、已读或结束边界、现场证据、聚合通知及有界恢复规则，不调用旧私信扫描流程

### Requirement: 修复能力与统一发布
Agent SHALL 能在独立修复工作区读取版本化代码与故障材料、编辑、执行隔离测试并产出差异及结果；修改 MUST 经唯一发布源生成新版本后才影响运行程序。用户 SHALL 可查看、拒绝或撤销候选修改。

#### Scenario: Agent 修复一个回归
- **WHEN** Agent 修改流程代码并通过测试
- **THEN** 保存基准提交、差异、测试命令与结果，并显示待统一发布，不覆盖运行程序或修改历史任务终态

#### Scenario: 修复测试需要设备
- **WHEN** 离线测试不足且修复需要实际设备验证
- **THEN** 生成限定设备与动作的验证计划，确认后通过同一固定执行链路运行，不从修复终端直接操作设备

### Requirement: 接管验收覆盖完整工具链
系统 MUST 对会话、服务商配置、追问、计划确认、工具执行、错误诊断、代码修复、测试、重启和独立安装逐项验收；模拟响应与真实模型结果分开统计。

#### Scenario: 声明混合版验收通过
- **WHEN** 报告 Agent 已接管软件
- **THEN** 提供真实读取状态、至少一次确认后操作回执、故障证据定位、实际文件修复及测试结果；保留未通过功能列表，不以聊天成功替代全链路成功

### Requirement: 会话分级权限
系统 SHALL 默认为操作模式，支持用户显式开启维护或开发模式，仅在该会话中持久化。模型、记忆及工具输出 MUST NOT 自行授予权限。开发范围限 MediaFlow 项目，不能修改授权账本。

#### Scenario: 新会话与撤销
- **WHEN** 用户切页、重启、新建会话或撤销权限
- **THEN** 原会话授权恢复，新会话保持操作模式，撤销后新的高权限调用被拒绝并显示升级入口

#### Scenario: 开发修复应用
- **WHEN** 开发会话通过测试并展示补丁，用户回复应用该修复
- **THEN** 授权绑定补丁版本；空闲时由独立流程更新本机，失败回退，补丁变化重新确认，保留用户数据与会话
