## ADDED Requirements

### Requirement: 内嵌Agent通过工具编排而非直接动作
内嵌 Agent SHALL 通过原生工具及平台Skill产生计划、业务调用和项目修改；本地自动化API MUST 验证参数、幂等身份及实际设备状态后调用既有规划、队列与维护操作，不要求MediaFlow自建聊天回合。设备点击、输入、页面恢复及验证继续由持有同一设备独占锁的固定执行程序完成。

#### Scenario: Agent 提交视频任务
- **WHEN** Agent 为用户确认后的计划调用执行工具
- **THEN** 工具服务生成冻结任务并交给现有 Worker，不开启 Agent 自己的 ADB 点击循环

#### Scenario: Agent 请求删除实例
- **WHEN** Agent 提议删除或重建虚拟机
- **THEN** 使用既有准确清单、占用阻断及用户确认，聊天中的模型声明不能伪造确认

### Requirement: 专业修复工具与活动运行隔离
系统 SHALL 允许内嵌 Agent 在修复工作区编辑和测试程序，同时 MUST 区分项目授权与操作系统权限。工具权限不得被描述为操作系统沙箱；程序级保护必须由实际执行服务检查，外部命令不能绕开设备锁、确认或覆盖当前安装目录。

#### Scenario: 测试夹具试图使用生产数据
- **WHEN** 修复测试配置指向实际任务库、密钥目录或在线设备
- **THEN** 测试入口拒绝并提示使用隔离资源或发起单独的设备验证计划

#### Scenario: 统一发布修复
- **WHEN** 修复经验证进入正式发布提交
- **THEN** 新版本记录唯一提交和资产哈希，客户端使用统一更新流程；工作区修改本身不会改变活动程序
### Requirement: 本地自动化复用当前可选设备
自动化计划 SHALL 接受当前平台清单中的虚拟机身份或明确 physical 设备的 ADB 序列号，提交前复核身份与可执行状态。清单外设备、歧义映射及部分设备不可用 MUST 明确失败，不得猜测名称或缩减用户设备范围。真机展示偏好保持不变。

#### Scenario: 已显示五台物理设备
- **WHEN** 用户明确选中平台当前展示的五台物理设备并要求混合流运行
- **THEN** 计划、提交、恢复复用原任务服务，不因缺少 MuMu 实例映射拒绝真机
- **AND** 设备离线、占用或身份变化仍返回对应业务原因

### Requirement: 按轮数结束的显式批次策略
用户明确要求按轮数而不按时间结束时，系统 SHALL 冻结 `batch_stop_policy=round_count`，运行、等待、暂停恢复均不套用估算时间截止。历史批次继续使用原 deadline。安全停止、操作超时及未知写入不重放 MUST 保留。

#### Scenario: 模型响应较慢
- **WHEN** round_count 批次尚未完成指定轮数且已超过旧估算时长
- **THEN** 不因墙上时钟到期取消任务，用户仍可暂停或停止原批次
