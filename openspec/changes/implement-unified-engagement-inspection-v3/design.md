## Context

现有 `EngagementInspector` 同时保留 v1/v2；任务层只接受这两个版本，设备档案缺值时默认为 v1。v2 依赖多个入口和独立访客页，而当前抖音将各类互动合并在“互动消息”列表中。证据、回执、横幅和统一异常记录能力已经存在，应复用而不是重建。

## Goals / Non-Goals

**Goals:**

- 用单一深模块封装 v3 的导航、边界扫描、分类、证据和恢复。
- 固定规则独立可用；规则无法确认时可选视觉兜底，模型缺失只阻断需要视觉的阶段。
- 让控制台、任务规划和结果页共享同一 v3 状态契约。

**Non-Goals:**

- 不移除历史 v1/v2 解析或改写旧任务结果。
- 不扫描普通私信，不打开互动行，不改变隐私设置。
- 不在正式运行时调用 MBH 或自动采用分析候选规则。

## Decisions

0. **dev.8 首页恢复补修。** 开始巡检前确认非首页时，在Worker既有设备锁内执行一次`app_stop`与`app_start`，有界等待并复核首页；仅重新打开已运行应用不算大退。结束时轻量恢复失败可调用同一方法，每次巡检最多一次冷启动，不能在失败收尾再次重启。登录/身份验证停止留证，不清应用数据、不操作MuMu、不重放业务。校准显式传v3并验证统一列表完整，异常在恢复前接入既有incident记录。旧证据不改写；回退程序保持队列暂停。

1. **v3 作为显式工作流而非覆盖 v2。** `EngagementInspector.inspect` 显式分派 v3，任务存储接受 v3；历史 payload 保持原解释。这样可回放旧证据并避免迁移歧义。
2. **固定规则优先、视觉候选受限。** 入口先用UI文字和可点击祖先定位；缺失时共用`control_vision`识别新鲜截图。模型返回页面类型、目标区域和依据，不持有设备。固定执行器校验包名、锁、900×1600显示、允许目标及区域稳定后仅执行一个导航动作，再重新观察证明目标页。候选不得用于普通会话、用户主页、登录设置或任何互动写入；云端输出中的页面指令不具有执行权限。
3. **单一有界扫描器。** 首屏先判定“已读”，否则至多十二次有效滚动、四十五秒，连续两个视口指纹不变即停。只有已读、显式空页或显式末尾可完成，其他终态失败关闭。
4. **兼容摘要由统一结果派生。** v3 保存 `unified_activity`，并生成 `received_likes`、`comment_danmaku`、`profile_visitors` 三个兼容 section；不生成 `private_messages`。
5. **提醒独立于账号设置。** 控制台在关闭到开启巡检时弹窗确认；确认按稳定虚拟设备 ID、当前 Android 身份和应用数据代次保存。身份、清数据或重新初始化会使确认失效；页面明确检测访客关闭会使本次降级。
6. **纠错候选不能自执行。** 失败现场交给既有异常模块；MBH 只在开发设备锁内用于观察和单步验证。候选规则必须先进入固定测试夹具，再经三次同机和一次跨机复验。
7. **共享规则与本机快速复验。** 新规则通过同场景三次和第二台一次复验后提升共享；匹配共享规则的新实例仅一次快速复验。校准由持锁Worker执行，不产生业务任务或横幅；失败不提升档案，也不删除已采集证据。

8. **dev.9有界观察。** 导航后每0.5秒观察，最多8秒；每阶段一次视觉请求，仅候选过期允许新截图第二次请求。每次请求含完整响应读取总共20秒。聚合页45秒包含视觉等待；整次巡检120秒，不以重试重新起算。迟到结果丢弃，未知动作不重放，恢复仍最多一次大退。
9. **预算与错误。** 本轮所有模型请求共用持久化5美元预算账本，调用前保守预留、返回后按usage结算；费用不可确定则保留预留额，禁止无预算发起。复用现有鉴权/余额/拒绝/限流/网络/格式分类和三次永久拒绝熔断。403不一律视作Key无效；同任务同指纹故障累计次数，不反复生成相同异常。

## Risks / Trade-offs

- [部分抖音页面不暴露文字] → 受限视觉识别页面、入口和列表边界；仍不确定则保存不完整回执，不猜坐标或误报无互动。
- [打开互动列表本身可能改变未读状态] → 在首次进入立即保存证据，并在界面说明这是只读内容检查但并非完全无状态。
- [旧等待任务可能继续走 v1] → 只取消仍为 pending 的旧虚拟机巡检，保留全部历史；不自动补跑。
- [两台本机虚拟机当前不符合标准] → 离线测试先完成，真实验收保持阻断，不为通过验收自动修复或启动设备。

## Migration Plan

1. 将版本提升到 `0.4.1-dev.3` 并保留 v1/v2 读取兼容。
2. 标准虚拟机档案解析缺少v3时要求复验；共享规则匹配仅一次快速复验，新规则按三次及跨机验证提升，不回退旧流程。
3. 幂等取消 pending 的旧版本标准虚拟机巡检，写入 `superseded_by_v3`，不删除任务。
4. 先发布开发版并完成离线、API 和浏览器验收；设备满足标准后再执行三十次只读验收。
5. 回退程序时保留新增结果字段和证据；旧版本按未知附加字段忽略，不改数据库历史。
