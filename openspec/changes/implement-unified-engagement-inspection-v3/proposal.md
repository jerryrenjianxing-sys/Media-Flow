## Why

当前互动巡检仍按 v1/v2 的私信、点赞、评论和访客多入口执行，和抖音现有“消息 → 互动消息”统一列表不一致，导致标准虚拟机回退旧流程、入口识别失败以及没有可靠读边界时误报结果。需要用单一只读流程、明确的“已读”边界和现有纠错证据闭环提高可验证成功率。

## What Changes

- dev.10补修：新增实验性千问Token Plan预设qwen3.8-flash。全平台手动选择同一配置版本，独立加密候选Key经图片/JSON测试后启用；无自动服务商回退。首次千问验收持久化最多10次请求，失败及超时计入；Credits独立于dev.9 OpenRouter美元账本。未确认上传和个人版条款不得调用。本轮不进行设备任务、打包、GitHub推送或远端更新。

- dev.9补修：固定规则优先，缺少页面文字时通过现有视觉模块返回受限导航/读取候选，由固定执行器复核新鲜画面并单步执行、验证结果。允许完整应用截图，不允许桌面、Key或配置上传；本轮验收模型预算5美元。
- 导航观察每0.5秒、最多8秒；视觉请求总截止20秒；聚合列表扫描45秒包含视觉等待，整次巡检120秒。复用模型错误分类与熔断，保留固定规则的离线能力。

- dev.8补修：巡检前非首页直接执行一次抖音强停冷启动；结束恢复的轻量返回失败后使用同一大退路径。登录/验证不得绕过，失败不循环重启。校准显式分派v3并接入统一异常现场记录。

- 新增 v3 统一互动列表巡检，只进入“互动消息”聚合页，不读取普通私信。
- 以页面语义和可点击祖先识别可移动入口，以“已读”、明确空列表或明确列表末尾作为完成边界。
- 将点赞收藏、评论回复弹幕和主页访客分类为兼容结果，并保留全过程截图、UI 树、回执、横幅通知和纠错记录。
- 启用巡检时提示开启访客记录；明确关闭时保存其他结果但不计完整成功。
- 标准虚拟机必须使用已复验 v3 档案，禁止缺档案时静默回退 v1。
- v3初始版本为 `0.4.1-dev.3`；当前补修升级 `0.4.1-dev.9`，不同代码内容不得复用版本号。本轮仅本机源码服务更新，不打包、推送或远端升级。
- 非目标：不打开具体互动记录、私信或用户主页，不产生任何对外互动，不在正式安装版运行 MBH 或自修改规则。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `engagement-inspection`: 将四入口 v2 巡检改为统一互动列表 v3，并增加边界、提醒、版本门禁和验收要求。

## Impact

影响互动巡检固定执行器、任务负载校验、标准虚拟机档案解析、互动回执与横幅展示、控制台启用提示、OpenSpec 和产品版本。历史 v1/v2 任务、回执与证据保持只读兼容。
