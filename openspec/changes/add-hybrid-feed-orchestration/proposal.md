## Why

当前纯搜索视频流能够提高指定主题样本密度，但连续停留在单一搜索入口会缩窄隔离测试覆盖面，也无法同时观察同一设备在搜索结果流与主页推荐流中的真实执行差异。现在需要一条可审计、可重复的交替入口模式，在保留现有搜索主路线和旧模式的前提下，让单个任务按固定段落覆盖两类视频流。

## What Changes

- 新增 `hybrid` 内容模式：单个设备任务从搜索视频流开始，每次进入阶段时使用任务随机种子抽取本段视频数，再切换至另一入口并循环至任务总视频数完成；默认搜索段随机 7–14 条、主页段随机 5–10 条。
- 搜索阶段沿用现有搜索词、搜索结果验证、`search_trust_results` 与搜索来源可信路由；主页阶段沿用现有混合主题路由，不相关内容不得评论，安全内容的点赞和收藏继续按既有概率与随机种子抽样。
- 每次阶段切换都验证当前入口；页面漂移或应用重启后按照当前目标阶段重新建立搜索流或主页流，不把上一阶段的上下文带入下一阶段。
- 任务详情和结果摘要分别展示搜索阶段与主页阶段的处理量、主题判定、动作、跳过、恢复和截图证据，同时保留任务级总计。
- 控制台新增“搜索＋主页交替测试”主模式和只读内置预设；当前安装的默认方案切换到该模式但不自动提交任务。原 `general`、`mixed`、`search` 模式、参数、预设和历史记录完整保留。
- 旧任务缺少交替阶段字段时继续按原模式执行；不限主题、混合主题与纯搜索任务不受新字段影响。
- 将主页正常内容进一步拆分为视频与图文：图文作品属于可浏览、可滑过的主页流项目，但不得进入主题模型、互动或有效视频计数；连续图文供给不足使用一次阶段重入和一次明确熔断收口。
- 真机与 Root 虚拟机采用同一档案、Adapter 和固定执行器，但初始化入口分轨：真机由 Agent 按标准指南辅助处理厂商确认和语义校准，虚拟机仅在本地 ADB、模拟器身份与 Root 三重验证后由固定程序自动初始化和零写入自检。
- MBH 只用于已有证据无法解释的只读页面差异探索；候选路径连续三次一致并由固定程序复验后方可版本化，MBH 不进入正式批量运行链路。
- 非目标：不引入根据平台反馈自动改变节奏或策略的闭环，不让 AI/MBH/Codex 直接点击设备，不取消设备独占、安全闸门、预演默认、写入后验证、身份验证阻断或未知写入不得重放规则，不删除或迁移历史任务与截图，不在同一轮自动轮换搜索词。
- 当前已核实事实：现有系统支持 `general | mixed | search`，纯搜索模式可重新建立搜索视频流，搜索来源可信只放宽安全视频的点赞与收藏，评论仍要求 `exact + 当前画面证据 + safe=true + 发送前约束`。
- 设计假设：交替模式从搜索阶段开始，搜索和主页各自的最小值、最大值可由用户修改；每次进入阶段重新进行一次包含上下限的整数抽样，相同任务随机种子可复现相同段长序列，最后不足一整段时以任务总视频数截断。

## Capabilities

### New Capabilities

- `hybrid-feed-orchestration`: 定义搜索视频流与主页推荐流在同一任务中的固定交替、入口验证、阶段恢复、结果分段和兼容行为。

### Modified Capabilities

- `topic-routing`: 增加交替模式下搜索阶段与主页阶段各自独立的主题和动作路由要求。
- `strategy-presets`: 增加交替模式内置预设、可保存阶段长度以及旧预设兼容要求。
- `runtime-safety-baseline`: 增加应用重启或页面漂移后按当前目标阶段恢复入口的安全要求。

## Impact

- 控制台：模式选择、交替阶段数值、内置预设、提交校验、任务详情和分阶段指标展示。
- 本地 API 与配置：接受 `content_mode=hybrid` 以及搜索段、主页段视频数；旧载荷保持兼容。
- 固定执行器：增加单任务阶段状态机、阶段入口切换、按阶段恢复和上下文清理；仍由每设备唯一 Worker 串行执行。
- 结果与证据：在现有任务结果 JSON 和截图索引中增加阶段维度，不要求迁移 SQLite 历史数据。
- 测试与发布：需要配置、路由、恢复、统计、页面、构建和单台真机零写入验收；不新增第三方运行时依赖。
