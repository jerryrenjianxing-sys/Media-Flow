## Context

参见 [proposal.md](./proposal.md) 的 Why。当前执行路径为控制台提交配置、本地 API 写入 SQLite WAL 队列、每设备唯一 Worker 取任务、固定执行器通过 uiautomator2/ADB 操作 Android。`execution_tasks.py` 目前在任务开头按 `content_mode` 选择一次入口，`search` 会建立搜索视频流，`mixed` 与 `general` 使用主页流；动作循环随后处理全部 `video_count`。

当前任务配置和结果以 JSON 载荷保存在既有任务记录中，因此新增可选字段与结果子结构无需修改历史表。设备动作必须继续经过语义控件验证、安全闸门、动作后验证和未知写入不重放规则；MBH/Codex 仍只用于开发诊断，不进入正式动作链路。

## Goals / Non-Goals

**Goals:**

- 在一个任务、一个设备锁和一个随机数序列内可靠交替搜索流与主页流。
- 让入口、动作路由、恢复和结果证据都明确带有当前阶段，避免搜索可信状态泄漏到主页。
- 复用现有搜索入口、主页恢复、主题判定、概率抽样和写入验证能力，保持实现简单。
- 旧模式、旧任务、旧预设和历史结果无迁移继续可读可执行。

**Non-Goals:**

- 不做基于风控结果、账号反馈或平台响应的自适应策略学习。
- 不让视觉模型决定阶段长度、切换时机或直接点击坐标。
- 不改变云端模型选择、主题协议版本、身份验证策略或任务自动续跑活动。
- 不把搜索指标与主页指标合并成一个“自然推荐率”，也不轮换搜索词。

## Decisions

### 1. 新增 `content_mode=hybrid`，不重定义现有 `mixed`

`mixed` 已有稳定语义：在主页推荐流中对匹配与未匹配内容使用两组概率。将其改造成入口交替会破坏历史任务和预设，因此新增第四种模式。API 校验允许 `general | mixed | search | hybrid`；只有 `hybrid` 读取搜索段和主页段各自的最小值、最大值。

替代方案是给 `mixed` 增加“是否搜索”开关，字段更少但会让同一模式具有两种不兼容语义，故不采用。

### 2. 在单个执行循环中使用显式阶段状态机

执行器构造一个轻量阶段计划器，状态为：

```text
ENTER_SEARCH -> SEARCH_BROWSE(N) -> ENTER_HOME -> HOME_BROWSE(M) -> repeat
```

计划器只持有 `phase`、`phase_target`、`phase_processed` 与任务总处理量。每次进入新阶段时，从该阶段闭区间内抽取一次 `phase_target`；入口验证成功后才允许消费视频，到达阶段目标或任务总量后切换。默认搜索范围为 7–14、主页范围为 5–10；四个边界复用任务 `video_count` 的现有上限，并校验最小值不大于最大值。

段长抽样与动作概率共用任务级伪随机数生成器，不使用系统时间另建随机源。这样每次运行中的段长会变化，但给定相同种子、配置与消费顺序时可以复现。抽样只在成功准备进入一个新阶段时发生一次；页面恢复不会重新抽取当前阶段目标，避免一次异常改变后续计划。

替代方案是为每段创建队列子任务。该方案会释放设备锁、拆散随机数序列、制造更多任务记录并放大未知写入重放风险，故不采用。

### 3. 入口切换复用现有能力并增加主页语义确认

搜索阶段调用既有搜索入口流程，并继续要求搜索外壳和沉浸式流的语义证据。主页阶段优先执行有界返回/关闭，再点击或调用现有“首页”恢复能力，最后验证目标应用包、主信息流外壳以及不存在搜索查询上下文。若无法确认，则进入现有应用大退恢复，并按目标阶段重新建流。

执行上下文增加 `feed_phase`，每次进入新阶段先将 `search_feed_ready`、搜索来源可信缓存和上一阶段页面证据清空。只有当前阶段入口验证成功后才设置对应状态。

替代方案是仅执行一次返回并假设已到主页。不同设备和页面层级下不可靠，且会把搜索结果误记为主页样本，故不采用。

### 4. 主题模型每条只调用一次，路由在本地按阶段解释

两阶段继续共享现有一次多模态主题判断。模型只返回既有 `exact | adjacent | unrelated | uncertain`、当前画面证据与 `safe`；固定执行器根据 `feed_phase` 决定概率组：

- `search`：启用搜索来源可信时，安全视频的点赞与收藏走匹配组；评论仍只允许严格 `exact`。
- `home`：所有安全内容的点赞与收藏统一走主页组概率；只有严格 `exact` 才允许按主页评论概率继续进入发送前约束，其他内容评论关闭。旧 `mixed` 模式仍维持原来的匹配/未匹配双概率语义。
- 任一阶段不安全：三个动作全部关闭。

这样不需要新模型提示词，也不会增加每条视频的模型调用和延迟。随机数生成器仍在任务开始时初始化一次，阶段切换不重置。

### 5. 结果采用向后兼容的 `phase_summaries` 子结构

保留现有任务级字段，并新增：

```json
{
  "phase_summaries": {
    "search": { "videos": 0, "topic_exact": 0, "actions": {}, "incidents": 0 },
    "home": { "videos": 0, "topic_exact": 0, "actions": {}, "incidents": 0 }
  }
}
```

每条主题判定、动作证据和纠错记录增加 `feed_phase`。控制台只在字段存在时展示分阶段卡片；旧结果继续走现有详情。截图文件本身不复制，只在证据索引中增加阶段元数据。

替代方案是新增数据库表。当前结果量与查询方式不需要关系化迁移，且迁移会提高独立安装升级风险，故不采用。

### 6. 控制台将交替模式作为推荐主入口，旧模式继续备用

主任务区增加“搜索＋主页交替测试”，显示搜索词、搜索来源可信、搜索段 7–14、主页段 5–10 和两组现有动作概率。当前安装的一次性配置更新只调用保存配置，不触发提交。备用区继续提供纯搜索、混合与不限主题，切换时保留各自未提交参数。

提交前同时验证搜索词、主题标准和两个阶段长度。任务总量小于一个完整周期时允许提交，并按总量截断。

### 7. 主页壳层与可互动视频页分层确认

主页恢复只要求组合证据证明处于推荐流壳层；当前项目是否允许主题判断和互动则继续要求完整的视频语义与动作控件。带有主页底栏、推荐页签、图文标记、图片分页和互动控件的图文作品归类为 `home_image_note`，记录 `non_video_feed_item` 后上滑，不调用主题模型、不增加 `videos_seen`、不进入任何写入闸门，也不累计未知页面异常。

同一阶段连续遇到 20 个图文安全项目且没有有效视频时，固定程序只重新建立一次当前阶段；重入后再次连续 20 个仍没有有效视频，则以 `insufficient_video_supply` 留证停止。有效视频出现后重新开始这一有界计数。阶段重入沿用冻结搜索词、段长、主题和已完成有效视频数。

### 8. 初始化采用同执行器的双轨入口

真机不追求厂商级完全无人值守。控制台把真机初始化展示为 Agent 辅助流程，标准指南负责序列号映射、前置条件、厂商确认、只读校准、固定复验、档案保存和 3 条零写入冒烟；`waiting_user` 是明确人工断点而非程序失败。Root 虚拟机继续由后台固定程序自动发现，但必须同时证明回环/标准模拟器 ADB、模拟器身份和 Root，Root 真机永不自动接管。

虚拟机平台签名记录 Android 镜像/构建、分辨率、DPI、导航模式、抖音版本、输入方式和 Adapter 版本。自动初始化通过后只执行 3 条零写入自检，本变更不自动提交正式任务。两条入口共用 `PlatformAdapter`、设备档案、平台档案、独占锁和固定执行器。

### 9. MBH 只探索真正未知差异

已有截图和 UI 树足以判定的页面问题必须优先通过离线回归和固定规则修复。只有同一未知页面指纹重复出现、现有证据无法确定语义时才允许 MBH 只读探索；不得打开具体私信会话或执行点赞、收藏、评论、关注、回复。候选入口需要同一路径连续三次一致，再由固定程序完成最终复验；平台或账号确实不提供入口时保留 `unavailable`，不算程序失败。

### 10. 恢复按页面语义收敛，不按固定三次返回猜测

真机复验确认，从搜索沉浸视频返回主页可能依次经过沉浸视频、视频结果、综合结果、搜索输入聚焦、搜索输入失焦共五层。主页恢复因此最多执行六次有界返回，每一步都重新读取页面语义，确认主页后立即停止；只有整条返回链仍无法回到主页时才冷启动应用。一次 UI 树读取失败只记录观察异常并继续下一次有界观察，不能单独证明页面错误。

搜索阶段重建若第一次进入搜索流失败，先完整验证回到主页，再使用冻结搜索词重试一次。两次均失败才终止当前设备任务；重试不得重抽段长、推进有效视频进度或放宽写入闸门。

评论面板关闭后分开判断“面板是否仍打开”和“当前阶段是否仍正确”。若面板已关闭但落到搜索宫格或搜索落地页，固定程序直接重建当前要求的视频流，不再继续盲按返回，也不把它误报为评论面板关闭失败。评论已发送或写入结果未知时只恢复导航，绝不重放评论。

### 11. 纯观察主页流不依赖主题模型

当 `content_mode=general` 且点赞、收藏、评论三项概率全部为零时，任务只是验证页面、观看和滑动，不存在主题筛选或候选互动。固定程序在确认有效视频后直接记录 `observation_only`，不调用主题模型；页面分类、有效视频计数、设备锁和恢复检查保持不变。

任一互动概率大于零，或模式为 `mixed / search / hybrid` 时，仍必须执行现有主题与视觉安全判断。评论预览也属于可能生成互动内容的路径，不得借“预览”名义跳过模型。该优化只删除无业务用途的外部依赖，不放宽任何写入安全门。

### 12. 已验证恢复本地归档，未知事件才进入智能分析

事件已经包含 `verified_recovery.verified=true` 时，固定程序已知道规则、动作和复验结果。纠错分析器直接生成本地“已恢复”说明并标记完成，不再请求云模型；这样上游限流不会把成功恢复显示成“纠错分析失败”。

没有已验证规则、语义仍未知或恢复失败的事件继续进入只读智能分析，必要时再按 MBH 边界探索。历史事件和原任务结果保持不可变；本地归档只影响新增事件的分析状态。

## Risks / Trade-offs

- [主页入口在不同设备上证据不同] → 复用设备画像中的语义元素，优先资源 ID/文本/结构识别；不把新坐标写入共享逻辑，真机零写入验收覆盖至少一台不同分辨率设备。
- [阶段切换增加少量固定开销] → 仅在处理完一段视频后切换，默认搜索 7–14、主页 5–10；入口验证不调用额外视觉主题模型。
- [阶段上下文泄漏导致错误路由] → 阶段进入前显式清空来源状态，路由函数必须显式接收 `feed_phase`，缺失或未知阶段时失败关闭写入。
- [长任务中恢复后重复处理当前视频] → 保留已处理计数；恢复只重新建立入口，未知写入不得重放，并从下一条可确认视频继续。
- [新版控制台向旧 Worker 提交 `hybrid`] → 按 API/Worker、控制台、默认配置的顺序部署；只有支持新模式的本地 API 返回能力后才显示可提交入口。
- [结果总计与分段统计不一致] → 总计仍由现有路径累加，分段同步累加；测试断言两段相加等于任务总计，差异记录为执行错误而不是静默展示。
- [更长返回链误触离开目标应用] → 每次返回后都验证目标包和页面语义，主页一旦确认即停止；最多六步，失败后只执行一次既有冷启动恢复。
- [评论关闭后导航漂移被误报] → 面板语义消失后禁止继续盲按返回，改为重建冻结阶段；只恢复页面，不重放任何已尝试写入。
- [纯观察任务仍受模型网络影响] → 仅在主页不限主题且三项互动概率均为零时跳过模型；任何可能互动或主题模式继续走完整安全判断。
- [成功恢复被云端限流误报为纠错失败] → 带验证证据的固定恢复本地归档，只有未知事件才调用智能分析。

## Migration Plan

1. 先上线配置校验、固定执行器阶段状态机、结果字段与离线测试；此时不修改默认页面配置。
2. 在队列空闲且无设备任务执行时重启本地 API/Worker，验证旧三种模式仍能读取和排队。
3. 上线控制台模式、预设和详情展示，完成构建与真实浏览器检查。
4. 仅保存一次性默认交替方案，不自动提交；确认队列仍为空。
5. 单台设备执行动作概率全为零的 24 条预演，验证搜索段落在 7–14 条内、主页段落在 5–10 条内、入口证据和分段统计。
6. 预演通过后才允许从页面显式提交内部参数任务；其他设备按相同验收顺序扩展。

回滚时先将控制台默认切回纯搜索并隐藏新提交入口，再等待已排队的 `hybrid` 任务进入终态。执行器和 API 继续保留读取 `hybrid` 与历史 `phase_summaries` 的兼容代码，避免正在运行或历史任务不可读；不得删除 SQLite、运行截图、设备画像或应用数据。最后恢复旧默认配置并重启服务，设备维持当前应用状态，不执行清数据、卸载或批量重置。
