## Why

当前系统能保存异常证据和生成只读建议，也有若干分散的固定恢复步骤，但“曾经解决过的页面第二次应自动恢复”还没有统一的规则目录、动作后验证和可解释记录。结果是同一类弹窗可能再次让任务失败，任务级失败还会被笼统显示成“已跳过”，让使用者误以为程序已经恢复。

## What Changes

- 建立版本化的已验证恢复规则目录，只允许固定执行器按明确页面信号执行有界、可逆或已授权的恢复动作。
- 每次恢复都执行“观察—单步动作—重新观察—确认返回主信息流”；只有确认成功才记录为 `recovered`。
- 将未成年人/青少年模式弹窗沉淀为正式规则：优先语义“关闭”，缺失时使用语义“不再提醒”作为已授权备用动作。
- 保留广告跳转和其他未知页面的通用首页、返回、关闭、重启恢复链，并记录实际成功的动作；未知建议仍不会由 AI 自动点击或自动升级为规则。
- 纠错面板区分“已恢复并继续”“已跳过当前视频”“任务已安全结束”和“需处理”，避免任务级失败被误读。
- 本变更不自动重放点赞、收藏、评论等状态改变动作，不让 AI/MBH 常驻控制设备，不清理或改写历史异常记录。

## Capabilities

### New Capabilities

- `verified-recovery-loop`: 定义已验证规则、动作后校验、恢复事件台账和首次异常到后续自动恢复的治理闭环。

### Modified Capabilities

- `runtime-safety-baseline`: 将已知弹窗和页面漂移恢复统一为有界白名单规则并要求动作后验证。
- `correction-advisory`: 明确只读候选建议与已实现固定规则之间的状态边界和重复异常处理方式。
- `records-browser`: 细化任务级与视频级纠错结果的用户可见文案。

## Impact

- 影响 `fixed_runner/douyin_uia2_runner.py`、新增恢复规则模块及其离线测试。
- 影响异常记录的上下文与控制台展示文案；不改变既有任务终态枚举和 API 兼容字段。
- 不新增云模型、设备控制或第三方依赖；可使用保存的 UI 树完成离线回归。
