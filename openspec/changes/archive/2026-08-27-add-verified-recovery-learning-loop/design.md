## Context

现有固定执行器已经包含未成年人模式识别、评论面板退出和首页/返回/关闭/重启恢复，但规则散落在流程函数中，恢复成功的依据与页面展示也不够统一。独立异常分析器按现有安全架构只能提出只读建议，不能持有设备连接。

## Goals / Non-Goals

**Goals:**

- 用小型静态规则目录统一已验证页面信号和动作顺序。
- 每次只执行一个动作，随后重新观察并验证主信息流。
- 让执行日志与纠错面板准确区分恢复、视频跳过和任务安全结束。
- 用保存的真实 UI 树建立无需设备写入的回归夹具。

**Non-Goals:**

- 不训练或微调模型，不让分析器自动生成可执行坐标。
- 不自动重放点赞、收藏、评论等结果不明的状态改变动作。
- 不承诺首次遇到任何未知页面都能当场恢复；首次必须先留证并完成规则验证。

## Decisions

### 规则目录使用代码内不可变定义

规则只包含稳定文本信号、语义按钮标签、顺序和上限，由版本控制和测试保护。相比运行时可编辑 JSON，这避免只读模型建议或错误配置绕过代码评审成为设备动作。设备差异仍由既有设备档案负责，不在规则中复制整套脚本。

### 恢复器记录最近成功规则但保持布尔接口兼容

既有调用方继续接收成功/失败布尔值；执行器内部同时记录规则标识、动作和验证结果供事件日志与异常上下文使用。这样不破坏现有 Worker/API，同时补足可观察性。

### 未成年人弹窗采用 X 优先、文字按钮备用

优先点击语义“关闭”；若 UI 树没有关闭控件但明确同时出现模式标题和动作说明，则点击语义“不再提醒”。两者都只在精确弹窗信号下执行，并且动作后必须重新确认主信息流。

### 通用页面漂移不交给模型点击

广告落地页和其他偏航继续使用首页、返回、明确关闭和应用重启链。未知页面只留证；模型建议要经人或 MBH 单步验证后再增加静态规则。

## Risks / Trade-offs

- [应用文案变化导致规则不命中] → 保存 UI 树与截图，新增规则信号前先回归旧夹具。
- [“不再提醒”改变测试机应用偏好] → 仅作为用户已授权的明确弹窗备用动作，并记录实际动作。
- [通用“关闭”可能命中错误控件] → 只有已知页面规则允许弹窗关闭；通用偏航链每步都验证主信息流且尝试次数有限。
- [历史 `skipped` 记录语义不够清晰] → 不改写历史数据库，只在展示层根据 `video_index` 与阶段解释作用范围。

## Migration Plan

1. 用保存的未成年人弹窗 UI 树和合成未知弹窗建立离线测试。
2. 实施规则目录、动作后验证和展示文案，运行全部 Python 与控制台测试。
3. 保持正式任务池暂停；只有真实弹窗自然再次出现时才收集现场恢复证据，不为验收主动制造状态改变。
4. 回退时删除规则目录接入并恢复原展示函数；不修改历史数据库、不删除截图，设备偏好变化只可能来自已明确执行的“不再提醒”。
