## Context

实时 ADB 已枚举五台设备且均已授权；RiskFlow 任务池处于暂停且没有运行中任务。设备池切换必须以五台控制环境版本统一、真实在线和可控为完成条件。

## Goals / Non-Goals

**Goals:**

- 为每台真机建立可审计的序列号、型号和控制能力记录。
- 将 Mobilerun Portal 尽量统一为已验证的 0.7.25，并确认 uiautomator2 控制端可用；Portal 安装被厂商系统组件故障阻断时，允许以已验证的 ADB-only 模式进入设备池。
- 在不执行应用业务动作的前提下证明截图与 UI 树可用。
- 原子更新 RiskFlow 的设备列表并保持任务池暂停。
- 让非技术用户可以从设备区主动刷新设备，并避免把离线或未授权设备带入新任务配置。

**Non-Goals:**

- 不运行社媒任务，不点击、输入、点赞、收藏或评论。
- 不清空现有任务和证据，不修改其他运行参数。

## Decisions

- ADB 用于枚举、授权诊断和安装已验证的 Portal 安装包；正常控制验证走 `mobilerun_core.Mobilerun` 的 `local-android-adb` 后端。
- 从已运行设备提取 Portal 0.7.25 安装包并校验 SHA-256，避免已安装 Portal 的设备混用来源或版本。
- 进入设备池的硬条件是状态为 `device`，且 Mobile Harness ADB 模式和 uiautomator2 的截图、UI 树均成功。Portal 0.7.25 是增强能力；若厂商安全校验组件自身崩溃，记录具体系统异常后允许 ADB-only 兼容例外，不以 root 绕过安装保护。
- 控制台继续复用 `/api/status` 的设备清单，不新增重复接口；主动检索会用最新响应覆盖当前勾选，只保留状态为 `device` 的设备。
- 非 `device` 状态的设备仍展示故障原因，但复选框禁用且不保持勾选；检索结果为空时允许界面处于零选择，保存和提交按钮保持不可用。
- 在五台未全部满足条件前保留旧设备池，避免产生半配置状态。

## Risks / Trade-offs

- [设备未授权] → 由用户在对应手机上确认 USB 调试授权后重新检查。
- [第五台未枚举] → 检查 USB 模式、线缆、端口和 Windows 驱动；未发现前不写入设备池。
- [厂商安装拦截] → 保留系统安全确认，由用户手动完成人机验证；若系统校验组件自身崩溃，则保留日志并降级为 ADB-only，不绕过设备安全校验。
- [误覆盖其他参数] → 读取完整现有配置，仅替换 `device_id` 和 `device_ids` 后回读验证。
- [后台轮询覆盖用户选择] → 只有用户主动点击检索时才重建勾选列表，常规状态轮询只更新在线状态。

## Migration Plan

五台通过基础控制前检后保存新设备列表并保持暂停。若 API 回读或设备状态不一致，立即恢复保存前的完整配置；该过程不接触运行数据库和设备账号状态。Portal 兼容例外必须在状态记录中明确标注。
