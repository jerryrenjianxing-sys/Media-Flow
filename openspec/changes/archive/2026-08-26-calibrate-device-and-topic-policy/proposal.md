## Why

五台真机的分辨率、系统导航区域和抖音页面状态不同，当前固定程序在“我”等非主信息流页面只能返回或重启，无法可靠点击语义明确的“首页”。现有主题判断又把模型自报置信度直接交给用户调节，已经出现与目标主题明显无关的内容被判为匹配并发送评论，缺少可重复校准的判定协议。

## What Changes

- 建立按稳定设备 ID 关联的设备档案，记录友好名称、型号、画面尺寸、密度、导航形态、能力和少量已验证的归一化兜底坐标；所有设备继续使用同一套固定程序。
- 固定程序恢复主信息流时优先使用 UI 文本/可访问性节点点击“首页”，只有语义节点不可用时才读取设备档案中的归一化兜底位置，并在每一步后验证。
- 将主题判断改成固定的分级相关性协议和证据输出，移除用户可调“主题置信度”；明显无关或无法判断的内容按未匹配处理。
- 将互动策略分成“主题匹配内容”和“其他安全内容”两组独立概率，使严格主题互动与少量通用互动可以同时存在。
- 增加独立的“搜索主题后开始”入口：先执行一次搜索并进入视频结果，再交回统一的信息流状态机；进入后仍逐条进行主题和安全判断。
- 完整记录页的任务与纠错区域默认各展示 5 条，用户分别点击“展开全部”后才分页查看余下记录。

非目标：不为不同分辨率复制多套执行器；不让 MBH/Codex 进入生产 Worker 临场点击；不自动恢复当前 2 条等待任务；不清理历史任务、截图或数据库；不在本变更中轮换或显示模型密钥。

## Capabilities

### New Capabilities

- `device-profiles`: 统一执行器使用可持久化的设备能力档案和语义优先的页面恢复。
- `topic-routing`: 使用可校准的主题判定协议、匹配/未匹配双概率和搜索主题启动模式。

### Modified Capabilities

- `records-browser`: 完整记录页的任务与纠错各自先显示 5 条并独立展开。

## Impact

影响 `fixed_runner/` 的设备恢复、模型判断、任务配置与存储兼容，影响本地控制 API 和 `control_console/` 的策略与记录页面。设备探查阶段只读截图/UI 树并允许单步返回首页，不触发点赞、收藏、评论或发布；模型对比只使用已经授权的内部测试截图并限定小样本成本。
