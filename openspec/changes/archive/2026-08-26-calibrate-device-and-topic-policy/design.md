## Context

当前生产链路由每设备独立 Worker 和 uiautomator2 固定程序执行，MBH/Codex 只承担开发期观察与异常复现。固定程序已有归一化布局参数，但没有稳定设备档案，也没有“首页”语义恢复步骤；主题接口只返回布尔匹配和模型自报置信度，控制台把阈值暴露给用户。

## Goals / Non-Goals

**Goals:**

- 保持一个状态机和一份执行代码，让设备差异只作为能力与末级兜底数据存在。
- 将两个已知失败做成秒级回归：从“我”页选择“首页”；旗袍样本不匹配工业/AI主题。
- 使主题匹配和通用安全互动能通过两组概率同时表达。
- 保持记录页初始可扫描，并支持独立展开。

**Non-Goals:**

- 不用模型实时决定设备点击，不为每台设备复制代码。
- 不把模型置信度当作可解释的真实概率，不承诺单帧视觉判断达到百分之百准确。
- 不在实现或验证阶段恢复排队任务，也不执行点赞、收藏、评论或发布。

## Decisions

### 统一执行器加设备档案

设备档案以 ADB 稳定 ID 为键，保存显示特征、型号、友好名称、能力及归一化兜底点。执行器先用文本、描述、资源 ID 等语义节点，档案坐标只作最后一级。相比按分辨率选择不同程序，这能避免同分辨率但系统导航、缩放或应用版本不同造成的错误分支。

### 恢复动作由小型状态机选择

恢复顺序为：若已在主信息流则结束；若存在“首页”节点则点击并验证；否则执行既有返回/关闭步骤；最后才应用已验证档案兜底或重新拉起。每一步只做一个动作并重新观察，失败立即留证。

### 主题判定使用枚举和证据，不暴露阈值

模型输出从 `matches + confidence` 改为 `relevance + evidence + safe`。主题提示词先明确“主要内容”和排除项；固定解析器只接受 `exact`。内部允许在回归集上比较模型，但运行配置不再由用户手调阈值。相比简单提高阈值，这能直接约束误判类型并为后续审计保留理由。

### 两组概率与三种内容模式

任务保存匹配组和其他安全内容组的三项动作概率。不限主题只用其他组，混合主题逐条路由，搜索主题在任务开始时增加一次确定性的搜索导航，之后仍走混合路由。旧任务字段在读取时迁移到等价默认，历史数据库不重写。

### 记录页按区域懒展开

任务和纠错初始请求量均为 5。每个区域独立维护展开状态和分页状态，避免必须滚过任务才能看到纠错，也避免一次渲染全部历史。

## Risks / Trade-offs

- [UI 树中的“首页”节点可能重复或不可点击] → 只选择可见、位于底部导航区域且边界有效的节点，点击后必须验证。
- [设备显示特征变化导致旧兜底漂移] → 档案包含特征签名，签名不一致时禁用兜底并要求重新探查。
- [单帧看不清视频主题] → `uncertain` 进入未匹配分支；搜索模式也不绕过逐条判断。
- [双概率增加配置项] → 用内容模式控制显隐，并提供清晰默认值与旧配置迁移。
- [云模型对比产生少量费用] → 只使用小型授权样本集，先比较现有模型；没有明确收益不切换生产模型。

## Migration Plan

1. 保持调度暂停，保存当前配置与设备状态；不修改运行数据库。
2. 先增加回归测试和设备档案读取兼容，再接入恢复和主题路由。
3. 对在线设备用 MBH 只读探查并单步返回首页，生成初始档案；离线设备保留未验证状态。
4. 完成离线测试、控制台测试、API 与浏览器检查后重启服务，Worker 继续保持暂停。
5. 回退时恢复旧配置 UI 与旧解析分支；新增档案文件可被旧版本忽略，历史任务和证据保持不变。
