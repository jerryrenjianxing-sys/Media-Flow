## Context

当前控制配置、预设和任务载荷以 JSON 保存，任务提交会为设备与轮次创建独立队列项；执行器继续读取单一 `topic_prompt` 与 `search_query`。评论生成已拥有一次视觉模型调用和后续独立发送前约束。变更必须保留 console → API → SQLite → Worker → 固定执行器的生产链路，不触碰运行目录、证据文件和设备状态。

## Goals / Non-Goals

**Goals:**

- 用一个高内聚内容计划模块承载版本、校验、归档、轮次解析和冻结快照。
- 让现有执行器通过兼容字段继续运行，避免一次性重写主题与搜索状态机。
- 在现有评论模型调用中注入受限候选和模板，并生成可审计来源。
- 让页面操作面向非技术用户，同时保持旧单主题与预设入口。

**Non-Goals:**

- 不改变设备动作控制平面、写入授权规则或未知结果不重放原则。
- 不建立跨提交持久游标，不为主题增加独立概率，也不自动轮换同一轮搜索词。
- 不删除、迁移或重写历史任务、预设、截图与运行日志。

## Decisions

### 1. 内容计划使用“稳定计划 + 不可变修订”双表

SQLite 中使用稳定计划记录保存名称、当前修订与归档状态，修订表保存完整规范化 JSON。保存编辑只追加修订并更新当前指针；归档只修改稳定计划状态。相比在单表原地覆盖，这能让任务、预设和证据稳定引用历史内容；相比把主题拆成多张关系表，完整修订 JSON 更适合 1～20 个有序主题的原子版本化，也减少迁移与联表复杂度。

### 2. 提交调度解析并冻结兼容快照

控制配置只保存 `content_plan_id` 与 `content_plan_revision_id`。提交时一次读取指定修订，过滤启用主题，按轮次计算位置，并为每个底层任务注入 `content_plan_snapshot` 与审计元数据，同时将该主题的判定标准和搜索词复制到既有 `topic_prompt`、`search_query` 字段。这样多设备同轮一致，执行器无需理解数据库计划，也保证队列任务对计划编辑免疫。

替代方案是在 Worker 领取时查询计划，但会让排队任务受到后续编辑影响，并增加运行期数据库耦合，因此不采用。

### 3. 评论资产编排作为评论生成边界内的纯模块

新增评论编排模块负责规范化模板、根据随机种子与已用集合选择最多五条候选、构造审计上下文和解释模型来源。`comment_ai` 扩展既有结构化请求与响应，接受可选模板/候选并返回候选标识或自由生成来源；没有新字段时完全保持旧请求行为。执行器仍先完成主题、安全、概率和页面条件，生成后继续通过既有发送前约束和动作后验证。

候选选择不另开模型调用。相比先调用模型选词再调用模型改写，单次调用成本更低且符合现有超时与熔断边界。

### 4. 模板按非可信数据隔离

全局模板与主题补充模板使用明确数据边界注入用户消息，固定系统提示词继续声明它们只能补充语气、长度与表达，不能改变安全、主题或输出协议。模型返回仍经过本地长度、字符、禁止表达与结构校验。模板冲突时固定规则优先。

### 5. 页面通过窄 REST 接口管理复合资源

新增内容计划列表、保存新修订和归档接口；每次保存提交完整计划文档，服务端统一校验并返回规范化修订。内容资产页不直接操作主题子资源，避免产生主题顺序与修订版本的部分更新。新任务页仅读取计划摘要与选中修订，显示轮次预览。

### 6. 审计记录附加在现有任务结果与事件中

每次评论编排记录计划修订、模板快照摘要、候选、最终评论、来源、决定与发送前审核。成功截图继续使用既有受限图片接口。任务详情从冻结载荷和结果事件读取，不回查计划当前版本，从而避免历史漂移。

## Risks / Trade-offs

- [完整修订 JSON 会重复存储词池] → 限制主题与词池规模，换取原子版本和简单恢复；首版不做增量压缩。
- [模型可能忽略候选标识或输出不一致来源] → 本地解析失败时标记自由生成或跳过，不根据文本猜测来源。
- [旧预设固定的修订已归档] → 允许显式恢复历史修订并标注历史版本，不自动换成当前版本。
- [计划在提交前被并发更新] → 配置携带明确修订标识，提交读取该修订而非当前指针；缺失或无效时拒绝提交。
- [模板或词池包含提示注入] → 作为非可信数据隔离，固定系统规则、本地校验和发送前约束保持优先。
- [前端新增页面增加维护面] → 复用现有控制台布局、表单组件和主题变量，不引入新 UI 依赖。

## Migration Plan

1. SQLite 启动时幂等创建内容计划与修订表，不修改现有任务和配置记录。
2. 新字段均为可选；旧配置、预设和任务缺失时走原单主题逻辑。
3. 先上线只读列表与版本化保存，再接入任务提交冻结，最后接入评论编排与页面展示。
4. 回滚代码时新增表和任务 JSON 字段可安全保留，旧版本会忽略未知字段；不删除任何运行数据。
5. 验收只先执行零写入预览；真实评论仍需单独、当次明确授权。
