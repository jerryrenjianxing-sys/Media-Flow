## Context

当前主题请求由固定系统提示词和用户自由文本拼接，主题输出已有四级相关性、画面证据和安全字段。离线评测已区分人工确认参考与候选参考，但运行请求和报告尚无独立的主题策略版本，主题文本也缺少结构校验。设备动作由固定执行器负责，主题模型只返回判断。

## Goals / Non-Goals

**Goals:**

- 用一个小型、无外部依赖的数据结构统一表达主题边界。
- 保持现有自由文本配置可运行，同时让标准策略可直接复用。
- 让每次判断和离线报告能追溯提示词版本与主题策略版本。
- 通过单元测试和现有截图回归验证编译结果与判断边界。

**Non-Goals:**

- 不让 AI、Codex 或 MBH 直接发送任何设备动作。
- 不在本次变更中更换生产模型、调整互动概率或修改设备配置。
- 不把关键词实现为本地字符串命中规则，也不训练或微调模型。
- 不自动清理历史截图、日志、SQLite 数据或评测报告。

## Decisions

### 使用 JSON 主题策略加确定性文本编译

结构化策略保存在版本控制内，编译器按固定字段顺序生成供应商无关的文本合同。相比把规则继续写死在一个长提示词里，这能独立复用和审查；相比引入数据库或新配置服务，JSON 更容易回滚且不增加运行依赖。

### 保留自由文本兼容层

现有控制台和任务配置继续传入字符串。字符串若符合已知策略标识或与默认策略规范文本一致，可加载结构化策略；其他非空文本作为单一兼容类别编译，并自动附加统一证据和排除边界。这样不需要迁移历史任务，也避免突然改变 API。

### 关键词仅是纳入线索

编译文本明确要求“主要画面语义 + 具体证据 + 未命中排除”三者同时成立。未选择本地关键词打分，因为字幕、用户名和评论会产生大量伪命中，也无法覆盖视觉主体。

### 主题版本与提示词版本分离

提示词版本表示分类协议，策略版本表示业务主题边界。两者分别记录，后续可以只换行业策略而不宣称模型协议改变，也可以只优化协议并用同一策略回归。

## Risks / Trade-offs

- [结构化策略过长增加输入成本] → 限制类别和线索数量，编译为紧凑文本，图片仍是主要 token 成本。
- [自由文本兼容策略边界较弱] → 明确标为 `legacy-free-text`，建议正式长期任务使用版本化策略。
- [现有样本过少造成虚高一致率] → 报告增加覆盖缺口，候选样本不计入完整准确率。
- [更保守的边界降低召回] → 先保证限定主题模式准确，`adjacent` 和未匹配内容仍可走独立低概率分支。

## Migration Plan

1. 先增加策略加载、编译和单元测试，不触碰任务队列或设备。
2. 将默认 AI/制造/包装策略用于现有主题样本离线回归。
3. 回归通过后再让主题请求记录策略元数据，旧自由文本继续兼容。
4. 如需回滚，只需恢复旧提示词构造路径；新增 JSON 和报告字段可保留且不会改变 SQLite 任务或 Android 状态。
5. 全过程不连接设备、不修改运行数据库、不清理历史证据；任务池维持原状态。
