## Context

Vinext 1.0.0-beta.2 的 `start` 命令在未设置 `NODE_ENV` 时仍会返回 `@vite/client` 与虚拟开发模块。Vite 8 的控制台转发器在 WebSocket 建立前调用 `send` 会产生用户看到的重复错误遮罩。另一个已验证问题是 Node CLI 会出现同路径子进程，旧 PID 选择顺序先选子进程，导致停止角色时真正监听端口的直接进程未被结束。

## Decisions

- 在网页角色环境中显式固定 `NODE_ENV=production`，不依赖 beta 工具推断。
- 网页健康探测以 HTTP 200、存在 `/_next/static/` 且不存在 `/@vite/`、`/@id/` 为健康标准。
- 进程启动后优先核验 `Popen` 返回的直接 PID；仅当其可执行文件不匹配时查找子进程。
- 不修改设备执行器或任务语义，修复期间只在任务池为空时重启网页和后台宿主。

## Rollback

回滚只需恢复网页环境、健康探测和 PID 选择三处代码，再重启后台宿主。SQLite、截图、设备档案和手机状态均未迁移或修改；回滚不需要恢复业务数据。
