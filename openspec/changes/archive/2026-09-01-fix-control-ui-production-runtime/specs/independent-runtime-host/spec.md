## MODIFIED Requirements

### Requirement: 单实例与有界自恢复
后台宿主 MUST 保持单实例，并 SHALL 有界检查受管角色；无状态服务或已配置且未请求停止的 Worker 意外退出时 SHALL 被重新拉起，不得产生同角色重复进程。网页角色 MUST 使用生产构建资源，健康检查 SHALL 把开发热更新入口、错误覆盖页或不可用响应视为不健康；进程登记 MUST 优先核验直接启动的目标进程，避免停止角色后遗留真正的端口监听器。

#### Scenario: 网页服务意外退出
- **WHEN** 后台宿主发现网页服务的已核验进程已经退出
- **THEN** 系统重新启动一个网页服务并更新可审计状态

#### Scenario: 网页返回开发热更新资源
- **WHEN** 网页健康探测发现页面使用 `/@vite/`、`/@id/` 或缺少生产静态资源
- **THEN** 系统把网页角色判为不健康并在有界失败次数后以生产环境重启

#### Scenario: Node CLI 产生同可执行文件子进程
- **WHEN** 网页角色直接启动进程和临时子进程均使用同一个 Node 可执行文件
- **THEN** 系统登记直接启动的 PID，停止或重启角色时不得遗留其端口监听器

#### Scenario: Worker 被明确停止
- **WHEN** 某设备已有安全停止请求或用户明确停止该 Worker
- **THEN** 后台宿主不得把该 Worker 视为意外退出并反复拉起
