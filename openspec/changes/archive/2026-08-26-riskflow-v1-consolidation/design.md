## Context

参见 `proposal.md`。当前代码已经形成 React/Vinext 控制台、本地 Python 接口、SQLite WAL 队列、每设备 Worker 和 uiautomator2 固定执行器；86 项 Python 测试和 2 项控制台测试通过。项目此前没有 Git 基线，约 2.9GB 依赖、截图、日志、数据库和工具与源码混放，正式决定仍分散在旧文档和聊天中。

## Goals / Non-Goals

**Goals:**

- 让新任务能从项目文件恢复当前真实架构、安全边界和工作流程。
- 让每项高影响改动都有可审阅、可验证、可归档、可回退的变更包。
- 保留既有运行证据和历史方案，同时阻止它们继续冒充当前架构。

**Non-Goals:**

- 不修改运行接口、数据库表、任务状态或设备动作。
- 不拆分 `worker.py`，不更换前端或自动化技术栈。
- 不删除历史证据，不创建远程仓库，不执行五设备预演。

## Decisions

### 1. 项目根目录同时作为代码和规划事实源

Git 与 OpenSpec 均初始化在 `wo-c`。主规格描述已接受行为，活动 change 描述准备改变的内容，代码和测试用于核对实际实现。

替代方案是把规划放在 `pi` 或单独仓库中；这会让新任务在错误工作目录修改规格，增加代码与决策漂移，因此不采用。

### 2. 文档按用途单一负责

- `AGENTS.md`：短流程和触发指针。
- `PROJECT.md`：产品定位、正式架构、边界与事实源顺序。
- `STATUS.md`：当前可用状态、基线与治理队列。
- `RUNBOOK.md`：启动、停止、检查、设备预演与故障证据。
- `docs/decisions/`：长期有效且需要解释原因的架构决定。
- `CHANGELOG.md`：可用版本和治理里程碑。

不在每份文件重复完整架构；Agent 按任务类型读取对应文档。

### 3. 旧材料保留并显式降级

在旧 AutoGLM/统一 Agent 池材料顶部增加历史状态说明，不移动、不删除正文。这样保留研究证据，同时让搜索结果直接显示其非正式状态。

替代方案是立即删除或重写旧材料；这会损失决策背景，也不利于审计，因此不采用。

### 4. OpenSpec 使用当前生成的项目级技能

OpenSpec 1.10.0 以 Codex/core/zh-CN 初始化，生成 `.agents/skills/` 和 `openspec/config.yaml`。项目上下文只放长期约束，详细事实通过 `AGENTS.md` 指向对应文档，避免生成技能膨胀或复制业务规则。

### 5. Git 只保存可复现资产

根级 `.gitignore` 排除运行数据库、证据、日志、PID、依赖、构建输出、浏览器资料、APK、工具包和秘密。本地基线标签提供回退点；第一阶段不配置 remote。

## Risks / Trade-offs

- [旧文档仍可能被搜索命中] → 在文件首屏增加一致的历史状态标记，并在 `PROJECT.md` 列出正式事实源。
- [治理文件可能过期] → 每次归档都检查主规格、状态和变更记录是否需要同步更新。
- [忽略规则可能误排除未来正式资产] → 新增资产提交前使用 Git 待跟踪清单核对，不以文件是否自动出现作为唯一判断。
- [OpenSpec 版本变化导致技能目录变化] → 以实际生成目录和 `openspec update` 差异为准，升级单独提交。

## Migration Plan

1. 建立 `.gitignore`、秘密检查、本地基线提交和标签。
2. 关闭遥测，初始化 OpenSpec，并将生成资产单独提交。
3. 创建本变更的规格、设计和任务。
4. 新增项目文档和架构决定，标记旧材料状态。
5. 执行严格 OpenSpec 校验、离线测试、服务与页面验收。
6. 完成本 change 后同步主规格并归档。

回退方式：治理提交可逐个 `git revert`；最初可运行版本始终由标签 `riskflow-v1-baseline-2026-08-26` 指向。运行数据库和证据未纳入 Git，也不会在回退中被触碰。
