# Design: 只读纠错分析与视觉安全门

## 设计边界

设备 Worker 仍是唯一设备动作平面。异常分析器只从 SQLite 领取 `queued` 异常，读取已经落盘的截图和错误元数据，调用模型后把结构化建议写回 `analysis_json`。它不导入设备控制模块，也不访问 ADB。

## 纠错分析状态机

`queued -> analyzing -> completed|failed`

SQLite 事务原子领取一条记录，避免多个分析器重复处理。结构化建议只允许已知的恢复类别和文字说明，不接受坐标或动作序列。分析失败仅改变分析状态，不改变原任务终态，也不影响设备 Worker 继续执行。

## 视觉安全门

每条通过本地页面门的视频只调用一次视觉模型。返回结果同时包含主题相关性和 `safe`。固定执行器先判断 `safe`：只有明确为 `true` 才允许进入概率抽样后的互动动作；`false`、无效返回或模型异常均不执行互动并记录安全门原因。

## 回滚

可停止并移除纠错分析器进程，已有异常记录与任务状态不受影响。视觉安全门改动可回退到前一提交；数据库未增加破坏性迁移。运行数据库、截图和设备状态均保持原样。
