## Context

当前首页组件同时承担配置、设备、模型、运行和记录职责。已有 `/records` 与 `/governance` 独立路由，适合延续多页工作台，而不是继续在首页增加折叠区。配置以本地 API 的 `default` profile 为跨页事实来源。

## Decisions

- `/` 只编辑内容与行为参数；用户点击下一步时先保存配置，再进入 `/devices`。
- `/devices` 只负责实时检索、设备选择、档案状态与画面矩阵；保存设备选择后进入 `/run`。
- `/run` 重新读取已保存配置与状态，集中执行暂停、停止、取消等待、保存和提交；不会依赖前一页内存状态。
- 设备画面接口通过 ADB 对明确在线的稳定设备 ID 执行一次只读截图，限制超时和 PNG 响应，不写设备、不保存图片。
- 新设备先运行只读探查；档案签名与 Mobile Harness/uiautomator2 通过后才标记 verified。Portal 缺失时记录 `adb-only`，不绕过系统安装保护。

## Risks / Trade-offs

- [跨页保存失败] → 页面留在当前步骤并展示本机接口错误，不跳转。
- [多设备截图造成负载] → 只在设备页按人工刷新或低频批次刷新，接口单请求有超时。
- [设备截图与任务争用] → 只读截图不与任务动作混合；运行中的设备显示状态但默认不自动高频刷新。
- [后台假运行] → 以接口和心跳为准，不以旧 PID 文件作为服务健康证据。

## Verification

- OpenSpec 严格校验、Python API 测试、控制台测试与构建。
- 浏览器检查三个页面、导航、保存跳转、明暗主题和窄屏布局。
- 新华为仅做截图、UI 树和能力读取；回读设备档案与 API 状态，任务数量保持不变。
