## Context

见 `proposal.md`。当前控制台把三种内容模式并列展示，后端默认 `general`；搜索链路已经具备搜索、结果卡验证、沉浸流确认和恢复后重搜。每条视频已有一次多模态主题与安全判断，适合复用为分动作路由而不增加模型调用。

## Goals / Non-Goals

**Goals:**

- 让搜索模式成为清晰的产品主路径，同时保持旧模式和旧任务语义不变。
- 让搜索来源只影响点赞/收藏的主题资格，不削弱安全、控件和动作后验证。
- 让评论继续使用 topic-v3.1 的 `exact + evidence + safe` 严格条件和发送前约束。
- 让配置、预设、任务事件与页面文案能解释同一条路由决定。

**Non-Goals:**

- 不建立关键词池，不在同一轮自动轮换或改写搜索词。
- 不增加第二次视觉模型调用，不改变模型供应商或主题定义。
- 不迁移历史数据库，不补写历史任务事件，不删除旧预设或证据。
- 不把搜索来源可信扩展为跳过页面安全检查、动作前语义控件检查或动作后验证。

## Decisions

1. 新增单一布尔字段 `search_trust_results`，而不是新增三组搜索概率。搜索主任务复用匹配组概率；这保持预设和执行器结构简单。字段必须显式存在且为真才启用，缺失即为假，保证历史任务语义不漂移。
2. 搜索来源可信只改变动作主题资格：安全结果上的点赞/收藏选择匹配组概率；评论仍用模型返回的严格匹配。主题命中统计继续来自模型判断，不能从已执行动作反推。
3. 每条视频仍只调用一次现有多模态分析。先应用本地页面阻断和 `safe`，再分别计算点赞、收藏、评论的路由资格；各动作继续独立通过现有控件门和动作后验证。
4. 搜索词自动跟随状态只存在于页面表单，不进入任务运行协议。页面用“自动跟随 / 手动覆盖”本地状态控制；保存和提交的始终只是最终 `search_query`。单行规范化统一替换 `、，；,/;|` 等分隔符并合并空白，多行不自动生成。
5. 备用模式采用界面折叠，不创建第二份配置对象。切换只改变 `content_mode` 和兼容字段，所有概率与策略仍保存在同一表单，避免模式切换丢参数。
6. 路由说明由执行器在逐视频事件中显式登记，任务详情只读展示。历史缺字段时不推断新语义；这避免更改 SQLite 表结构，也避免页面从最终动作倒推原因。
7. 当前安装的一次性默认切换通过保存正式配置完成，保持设备、概率、预览和约束等已有值；只修改 `content_mode=search`、可信字段和可用搜索词。它不提交任务。

## Risks / Trade-offs

- [搜索结果漂移导致低相关点赞] → 评论继续严格主题门；主题命中率独立记录，搜索来源可信可在配置中关闭。
- [历史任务被新默认改写] → 缺字段严格按假处理，任务配置在入队时冻结，页面不补造历史事件。
- [多行主题误生成无意义搜索词] → 多行禁止自动生成，保留现有搜索词并要求手填。
- [备用模式参数切换丢失] → 使用单一表单状态并增加切换回归测试，不在模式切换时重建配置。
- [安全门被误解为已放宽] → 搜索来源只改变主题资格；`safe=false`、已知阻断、控件缺失和动作后未知仍按既有失败关闭。
- [一次性默认保存影响运行任务] → 仅在队列无运行和等待任务时保存，且不重启 Worker、不提交设备任务；否则保持现状并报告。

## Migration Plan

1. 先增加配置、执行路由和页面离线测试，确认旧任务缺字段保持严格行为。
2. 实施后运行 OpenSpec、全部 Python 测试、控制台测试与构建，再检查本地 API 和真实页面。
3. 队列为空时保存当前安装的搜索默认方案；不修改数据库历史或证据。
4. 使用单台设备、3 条、全部动作概率为 0 的预览任务验证搜索、沉浸流和恢复；只有证据完整才报告具备内部参数轮条件。

回滚时将页面默认和正式配置恢复为原值，并关闭 `search_trust_results`；旧模式、旧任务和所有运行证据无需迁移或删除。已发生且结果明确的动作不反向重放。
