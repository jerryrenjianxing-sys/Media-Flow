## Context

当前控制接口通过 PowerShell 包装器解密 OpenRouter Key 并启动 Python Worker。控制接口保存的是包装器 PID，而真正的 Worker 子进程可能在包装器退出判断错误后继续占用设备锁。根启动脚本又直接引用 Mobile Harness 的虚拟环境，并分别启动 API 和前端但不保存可核验的进程身份。SQLite 已有暂停位和任务终态，但只有 `pending/running/completed/failed`，无法表达用户取消或安全停止。

已验证事实：当前任务池可暂停、历史运行记录保留、四个 Worker 曾出现外壳与子进程生命周期不一致。假设：目标主机继续是当前 Windows 用户和本机回环网络，Node.js、npm、ADB 可由自检发现；第五台设备是否在线不属于本变更前提。

## Goals / Non-Goals

**Goals:**

- 让一个非技术用户能够可靠地启动、查看、停止和重启 RiskFlow，而不影响其他 Python/Node 程序。
- 让 Worker 状态对应真正的 Python 执行进程，并在维护前得到可信的“无运行任务、无设备执行进程”结论。
- 让暂停、停止、取消和清空分别有稳定终态、接口和页面反馈。
- 保持数据库、设备锁、未知动作结果不重放和默认预演等现有安全约束。

**Non-Goals:**

- 不把全部运行时打包成无需 Node/Python 的便携单文件。
- 不在本变更中拆分执行器业务状态机、引入新的模型或实现 AI 纠错分析。
- 不自动删除历史证据，不自动重试可能已经改变状态的动作。
- 不执行真实账号互动或未知页面上的 AI 点击。

## Decisions

### 运行管理作为深模块

新增 `runtime_control` 模块作为唯一进程管理 seam。其小接口只暴露 `status/start/stop/restart`，内部隐藏 PID 记录、进程镜像、命令行/工作目录核验、日志路径和 Windows 终止细节。控制接口和 PowerShell 脚本都通过该接口，不再各自实现进程判断。

### Worker 直接由控制接口启动真实 Python 进程

控制接口通过本机 PowerShell 一次性解密 DPAPI Key，将必要环境变量只传给项目独立 Python Worker，并直接保存 Worker PID。PowerShell 不再作为长驻父进程。停止 Worker 前必须同时核验 PID 存活、镜像为项目虚拟环境 Python和进程创建令牌；启动时同时登记本项目 `worker.py` 与目标设备 ID，系统能读取命令行时再交叉核验命令标记。核验失败只报告，不扩大终止范围。

### 项目本地环境与凭据

正式 Python 路径固定为项目 `.venv\\Scripts\\python.exe`，引导脚本创建环境并安装锁定依赖。加密 Key 保存到项目 `.secrets/openrouter-api-key.dpapi`，目录进入忽略规则。若新路径不存在而旧路径存在，只进行本机加密文件复制迁移，不解密打印、不删除旧文件。

### 任务停止使用协作式请求

SQLite `system_state` 保存全局或设备级 stop 请求。Worker 只在一个视频步骤结束、结果已经落盘后检查；命中时将当前任务标记为 `stopped` 并退出领取循环。等待任务取消直接从 `pending` 原子转为 `cancelled`。两者都是终态且不会自动恢复或重放。

### 历史清理保持独立且受保护

“取消等待”只改变任务状态，不删除记录；“清空历史”仍是破坏性操作，只在没有 `running` 任务时允许，并继续要求明确确认字符串。运行截图和日志不随任务表清空而删除。

## Risks / Trade-offs

- [Windows 进程命令行读取权限不足] → 默认拒绝停止并报告需人工检查，绝不退化为结束所有 Python/Node。
- [安全停止只能在步骤间响应] → 页面明确显示“停止请求已发送”，当前动作完成前仍为运行中；避免在输入或状态改变中途强杀。
- [旧 Worker 未加载新停止逻辑] → 精确重启已核验 Worker 后再开放安全停止；孤儿任务继续由现有对账逻辑收口为失败。
- [创建独立环境增加首次启动时间] → 引导与日常启动分离，自检明确缺失项；日常启动不重复安装依赖。
- [新增终态影响旧页面] → 数据库迁移只扩展允许值，页面对未知终态采用保守“已结束”展示，回归测试覆盖历史四种状态。

## Migration Plan

1. 增加运行管理和任务生命周期离线测试，保持现有服务与 Worker 不变。
2. 创建项目虚拟环境并安装固定依赖；迁移加密 Key 的 DPAPI 文件副本，验证不泄露明文。
3. 任务池暂停且运行中为零后，用新运行管理精确替换在线设备 Worker。
4. 验证本地 API、页面、取消等待和无互动安全停止；不提交真实互动任务。
5. 回退时停止经身份核验的新进程，恢复旧提交并继续使用原数据库；新增 `cancelled/stopped` 历史保持可读，不改回等待。
