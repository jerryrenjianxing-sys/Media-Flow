## Context

`send_comment` 已在发送按钮点击后保存 `video-{n}-comment-sent.png`，并继续通过 UI 树验证评论可见。当前缺口只是该文件没有进入任务 `result_json`，控制台也只有异常截图接口。

## Goals / Non-Goals

**Goals:**

- 成功发送的每条评论都在任务结果中登记一条截图证据。
- 页面可从对应任务直接打开每张截图。
- 文件读取沿用异常截图的本地目录边界检查。

**Non-Goals:**

- 不为预览评论标记“已发送”证据。
- 不新增截图数据库表，不回填历史任务，不改变评论生成、发送、去重或复核规则。
- 不为验收制造真实评论。

## Decisions

- 复用发送后已有截图，避免增加设备交互和额外等待。
- 在任务结果中保存 `comment_screenshots` 数组，每项包含 `video_index` 和 `screenshot_path`，同时支持单评论任务与多视频主题任务。
- 使用 `task_id + video_index` 定位证据；服务端从已保存任务结果解析真实路径，并要求解析后的文件位于 `DEFAULT_ARTIFACTS` 下。
- 只有发送复核成功后才把截图加入结果；若发送或复核失败，沿用现有异常截图链路。

## Risks / Trade-offs

- [运行目录被移动或清理] → 接口返回截图不可用，不回退到任意路径读取。
- [任务内多条评论] → 以视频序号区分并逐条显示，避免覆盖。
- [旧任务无登记信息] → 本次不扫描和回填历史目录，避免状态接口持续遍历磁盘。

## Migration Plan

无数据库迁移。新任务开始写入扩展后的结果 JSON；回退时移除结果字段消费、截图接口和页面链接，历史 JSON 中的附加字段可安全忽略。
