## Context

当前评论路径已经包含页面安全门、主题路由、概率选择、视觉候选生成、本地格式检查、设备输入和发送后复核。候选生成提示词追求“自然观看者评论”，这与“用户是否允许当前账号对该类内容发言”是两个不同问题；见 `proposal.md` 与 `specs/comment-policy-gate/spec.md`。

现有截图已在候选生成阶段保存，任务结果和运行目录可承载结构化审核记录。正式设备动作仍只能由固定执行器完成，验收默认使用预览和离线夹具。

## Goals / Non-Goals

**Goals:**

- 在评论文本进入手机之前建立独立、失败关闭、可测试的用户约束门。
- 让通用审核协议版本化，并允许用户通过短文本定义禁止范围或表达要求。
- 让预览和真实发送共享同一审核逻辑及结构化记录。
- 将新增模型成本限制在已经产生候选评论的少数视频上。

**Non-Goals:**

- 不把主题匹配和评论政策合并成一个含义模糊的判断。
- 不自动重写被拦截评论，不在同一视频重试生成。
- 不让审核模型返回坐标或设备动作。
- 不在本变更中更换模型、密钥、任务数据库或互动概率逻辑。

## Decisions

### 1. 使用独立的第二阶段审核，而不是只扩写生成提示词

流程为：既有门与概率命中 → 生成候选 → 本地硬规则 → 发送前约束审核 → 设备输入。独立审核能明确记录“为什么这句话命中了用户约束”，也能对生成模型自身的漏判形成隔离。备选方案是把全部规则塞入生成提示词，但它无法证明候选经过了独立拦截，也难以区分生成失败和约束拒绝。

### 2. 通用审核协议固定版本，约束内容由用户配置

代码内维护 `comment-constraint-v1-2026-08-27` 通用审核协议；任务载荷携带 `comment_policy_enabled` 和规范化后的 `comment_policy_prompt`。约束文本作为带边界的数据处理，不能改写系统协议或既有安全规则。结果类别采用稳定枚举：`constraint_match`、`style_mismatch`、`sensitive_or_unsafe`、`policy_uncertain`、`allowed`。页面提供示例“不对日常生活相关内容发表评论”，但不把它写死为所有账号的规则。

### 3. 审核同时读取截图和候选评论

只看文本无法判断“这句话是否命中内容约束”，只看截图又无法审核措辞。因此复用候选生成时的当前截图，并把候选、协议版本和用户约束作为结构化输入。模型只返回 `allow|block`、类别、理由和置信度，不返回改写文本或动作。

### 4. 解析和异常统一失败关闭

审核结果只有在结构有效、版本匹配、`decision=allow` 且置信度达到固定阈值时放行。网络错误、降级模型结果无效、低置信度或未知类别均转为 `policy_uncertain` 并取消评论；该取消是正常的单视频业务结果，不计为设备故障，也不阻断后续浏览。

### 5. 记录审核摘要而不扩张证据系统

在既有逐视频决策记录和任务结果中新增 `comment_policy_reviews`，包含视频序号、候选评论、政策版本、结论、类别、理由和置信度。控制台展示放行/拦截计数及拦截原因；发送后截图仍只对真实发送且复核成功的评论登记。原始隐藏推理和 API Key 不进入记录。

### 6. 配置与预设保持向后兼容

默认关闭自定义约束，页面提供“不对日常生活相关内容发表评论”示例；开启后才执行新增审核。旧任务或旧预设缺字段时保持关闭，以避免无提示改变既有任务行为。自定义预设包含开关和文本，但继续排除设备、密钥、随机种子和 `preview_only`。

## Risks / Trade-offs

- [第二次模型调用增加延迟和少量费用] → 只在已有候选评论时调用一次；拦截后不自动重写或重试。
- [单帧画面可能把行业内容误判为日常内容] → 采用保守失败关闭并记录类别与理由，先用离线正反样本校准，不以小样本宣称正式准确率。
- [用户约束文本可能包含提示注入] → 将其作为带边界的数据段处理，系统提示词明确不可覆盖审核协议和既有安全规则；输出使用严格结构并由本地解析器再次验证。
- [旧配置缺字段导致行为变化] → 迁移时采用安全默认值且不修改历史任务；回滚代码后旧字段会被忽略，不影响数据库读取。
- [用户规则过于宽泛导致大量拦截] → 页面提示采用“禁止主题 / 禁止表达 / 允许例外”结构，并显示审核原因；用户可随时关闭或修改约束。

## Migration Plan

1. 先增加纯函数政策模型、结构解析和正反样本测试，不连接设备。
2. 接入评论候选后的预览路径，确认被拦截候选不调用输入函数且任务继续。
3. 增加配置、预设和控制台字段，以缺失字段安全兼容旧数据。
4. 完成 OpenSpec、Python、控制台构建与渲染测试，并检查本地 API；不提交真实评论任务。
5. 在任务池暂停且无运行任务时精确重启在线 Worker。若出现回归，回滚代码和 Worker；不修改或清理运行数据库、历史截图和密钥。
