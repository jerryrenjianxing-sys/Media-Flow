## Context

正式链路仍是控制台、Python 本地接口、SQLite 队列、每设备 Worker、uiautomator2 固定执行器和 Android。当前 `comment_ai.py` 的主题、评论和发送前审核各自包含相似网络循环；OpenRouter 请求同时发送主模型与备用模型，HTTP 403 最终以普通异常进入 `execution_tasks.py`，后者会增加页面连续异常并在达到阈值后结束任务。参见 `proposal.md` 和本变更三份增量规格。

现有运行数据库、证据目录和设备状态必须保留；所有真机验证继续使用设备独占 Worker。MBH 只在 Worker 释放设备后观察未知页面，任何验证出的恢复动作仍需进入固定规则并由固定执行器复核。

## Goals / Non-Goals

**Goals:**

- 用一个小型公共调用边界统一错误分类、重试、响应解析和脱敏记录，消除三套网络循环的行为漂移。
- 把模型可用性状态留在单个任务内，三次相同永久拒绝后快速熔断；新轮次重新受控探测，避免永久屏蔽已经恢复的路由。
- 让页面异常计数只表达设备页面问题，让模型指标只表达模型问题。
- 用已保存截图建立秒级离线/只读回放反馈环，再逐级进入 20 视频真机轮次。
- 保持每个动作的既有固定闸门和动作后确认，不因追求成功率放宽安全要求。

**Non-Goals:**

- 不引入外部工作流平台、分布式队列或新的常驻 AI Agent。
- 不建立跨机器全局熔断服务；首版熔断限定在每个任务/Worker，四设备最坏只产生各自的少量探测请求。
- 不自动改写提示词来规避供应商政策，不通过代理绕过区域或条款限制。
- 不把 MBH 变为正式执行平面，也不让模型输出坐标或动作。

## Decisions

### 1. 使用单一类型化模型调用边界

在固定执行器模型模块内建立一个轻量公共请求函数，返回文本和尝试元数据，或抛出带 `kind`、HTTP 状态、可重试性、模型路由和脱敏详情的类型化错误。主题解析、评论解析和发送前审核继续保留各自业务解析器。

选择理由：错误分类与网络策略只有一处，业务提示词和结果验证仍相互隔离。相比继续复制三套循环，更容易锁定回归；相比引入独立微服务，改动范围和运行复杂度更小。

### 2. 先由客户端分类，再由任务级熔断收口

网络层最多执行配置化总尝试次数，默认两次；只对超时、SSL EOF、429、502、503、504执行带抖动退避，并遵守 `Retry-After`。400、401、402、403、413和参数拒绝立即返回。OpenRouter 的同模型供应商故障转移始终开启，它与是否配置备用模型相互独立；任务执行层按“错误类别+状态码+模型路由”计算指纹，连续三次相同永久错误后打开本任务熔断。

选择理由：OpenRouter 的供应商/模型回退已经发生在单次请求内部，客户端继续重试同一个403不会增加成功概率。没有备用模型不代表应禁止同一模型切换健康供应商。任务级熔断足以把本次12,556次洪泛收敛到每设备少量探测，同时不需要新增共享锁或常驻协调器。

### 3. 模型错误不进入页面恢复状态机

`execution_tasks.py` 分别维护页面连续异常和模型错误指标。模型失败时若设备仍在主信息流，只保存模型证据并禁止本视频互动，不调用页面恢复，也不记录“已跳过页面”；主题必需任务触发熔断后以明确模型错误结束。只有真实页面识别或导航失败才进入既有返回、关闭和冷启动恢复。

选择理由：页面恢复无法修复供应商拒绝，把两者混合会制造错误的“已恢复/已跳过”统计，并可能无意义重启应用。

### 4. 以能力表适配模型请求

保留现有版本化提示词和本地严格解析。模型能力表只记录少量决定请求格式的事实：是否支持严格 JSON Schema、是否支持 JSON Object、是否支持流式图片请求。Gemini 继续使用严格 Schema；GLM 5.3 Flash 候选使用 JSON Object，并由现有解析器验证字段、枚举和安全值。

选择理由：简单替换模型名会与当前 `require_parameters=true` 冲突。小型显式能力表比运行时猜测或捕获参数错误后重发更可预测，也不会把一次请求变成隐式两次费用。

### 5. 运行结果增加质量层而不改变动作重放规则

任务存储接受新的 `degraded` 终态；主题必需模型不可用仍为 `failed`，只读任务中非必需模型不可用才可为 `degraded`。记录页和汇总只把 `completed` 计入完整成功率。任何可能已经改变状态但结果不明的动作继续直接失败，绝不因本变更自动重放。

选择理由：仅在 `result_json` 放标记会让旧汇总继续把降级任务算成功；独立终态能让用户直接判断长任务质量。

### 6. 验收采用逐级风险阶梯

第一层使用捕获的403响应和模拟瞬时故障建立秒级回归测试；第二层对最多200张既有截图做只读模型A/B；第三层选择一台在线设备运行单个20视频、互动概率为0的兼容预演；第四层在固定程序稳定后恢复用户方案并完成连续10轮。未知页面只在任务结束并释放设备锁后用MBH观察。

选择理由：先证明网络和任务语义，再把真实设备变量加入，可以把失败定位到单一层次。20视频预演不能证明90%目标，连续10轮才进入目标窗口。

### 7. 仅对“明确未生效”的互动动作执行一次有界重试

点赞或收藏点击后若动作后证据明确显示仍未激活，固定执行器重新读取当前页面闸门与控件语义；只有仍在允许互动的主信息流、控件语义明确为未激活且视觉状态也未激活时，才允许重新定位后再点击一次。语义缺失、状态冲突、页面变化或第二次验证失败均立即停止该动作，不再重放。评论发送保持零重试。

选择理由：明确的未激活状态代表第一次点击未改变账号状态，可以安全地处理一次偶发漏点；任何不明状态仍保留原来的严格边界。

### 8. 平台身份安全验证触发本轮互动熔断

点赞或收藏阶段若UI树同时出现“身份安全验证”标题和“操作环境存在风险/请完成身份验证”正文，固定执行器按既有规则安全返回，并在本轮剩余视频中关闭点赞与收藏；浏览、主题判断和评论约束流程继续运行。新轮次重新受控探测一次，不把视频字幕中偶然出现的单一关键词当成弹窗。

选择理由：该弹窗说明当前账号或设备不接受继续进行同类互动。重复点击只会制造同类失败，也可能扩大状态不确定性；本轮熔断能把一次事件限制为最多一个视频错误，同时保留下一轮恢复后的重新探测机会。

## Risks / Trade-offs

- [新模型虽然便宜但主题准确率下降] → 使用同一批截图、同一提示词和独立参考标签对比；未通过有效响应和一致性门槛就不切主模型。
- [OpenRouter账号级Guardrail使所有模型继续403] → 开启路由元数据并先做一次受控诊断；识别为账号或组织规则后停止模型轮换，不进行规避性尝试。
- [新增 `degraded` 影响旧页面或脚本] → 同步更新终态集合、API序列化、统计和渲染测试；未知旧记录保持原状。
- [熔断过早掩盖短暂故障] → 只有永久错误指纹触发三次熔断；瞬时错误走有界退避，不进入永久错误计数。
- [真机回归产生账号状态变化] → 前三层互动概率为0；进入完整方案后仍使用既有概率、安全门和动作后验证，结果不明立即失败且不重放。
- [运行数据受代码或迁移影响] → 实施前创建SQLite一致性备份；只做追加兼容迁移，不删除任务、异常或证据文件。

## Migration Plan

1. 在不连接设备的条件下建立403、SSL EOF、429/5xx、无效JSON和熔断回归测试，并确认旧实现能复现错误语义。
2. 创建运行数据库一致性备份，记录当前服务、任务池和设备锁基线。
3. 实施类型化调用边界、能力适配、任务级熔断和独立指标；扩展任务终态、API与页面。
4. 依次执行OpenSpec严格校验、Python测试、控制台测试、构建、API和浏览器检查。
5. 使用既有截图完成有上限的只读A/B，选择通过门槛的模型配置。
6. 暂停领取并确认目标设备空闲后，精确重启对应Worker，运行单个20视频零互动预演。
7. 根据证据修复后进入连续10轮窗口；每轮保留任务、模型和页面统计。

回退时恢复原模型配置和原Worker代码，停止新任务领取并精确重启受影响Worker。已产生的 `degraded` 记录和新增指标只保留不删除；回退版本如不能识别该终态，则保持新API读取层直到历史兼容转换完成。数据库备份只用于灾难恢复，不用来覆盖正常新增任务或动作证据。
