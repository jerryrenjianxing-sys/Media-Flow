## Why

2026-08-28 的四设备长任务中，80 个轮次只有 47 个完成，12,556 次主题模型请求被供应商以 HTTP 403 拒绝；程序仍逐视频重复同类请求，并把模型通道故障累计为页面异常，最终造成 33 个轮次失败。下一次长任务前必须把模型故障与设备故障分离，并建立可重复的 20 视频验证闭环，避免以大量“跳过”冒充完整流程成功。

## What Changes

- 为云端视觉判断新增结构化故障分类：永久拒绝、瞬时网络故障、限流、供应商故障、无效响应和成功分别记录。
- 对瞬时故障使用有界退避重试；对相同 401/402/403 或参数拒绝不重复请求，并在单设备任务内触发模型通道熔断。
- 模型通道故障不再累计为页面/导航连续异常；主题必需模式在熔断后快速失败并保留证据，不继续无意义浏览，非主题只读模式可以明确标记降级而继续。
- 为不同模型建立请求能力适配，支持严格 JSON Schema 与仅 JSON Object 的差异；模型切换前使用已保存截图进行只读 A/B 回放。
- 增加模型请求与任务结果的可观察指标，明确区分“完整成功”“降级完成”“模型通道失败”“页面恢复失败”和“安全跳过”。
- 采用每轮 20 个视频的验证循环：离线回归通过后先做单设备最小预演，再做连续 10 轮验证；完整成功轮次至少 9/10，进入模型的画面有效结构化响应率至少 95%，且不得把模型失败跳过计入成功。

明确非目标：不允许 AI 直接点击设备；不自动重放任何结果不明的点赞、收藏或评论；不删除或覆盖现有数据库、截图和日志；不绕过模型供应商的区域、账号或内容政策；不以更换模型为理由放宽既有主题、安全或评论发送前约束；不进行无上限模型调用或无上限设备循环。

## Capabilities

### New Capabilities

- `model-runtime-resilience`: 定义云端模型故障分类、有界重试、熔断、供应商能力适配、只读回放和运行指标。

### Modified Capabilities

- `runtime-safety-baseline`: 将模型通道故障与页面异常分离，并规定主题必需任务在模型不可用时的安全收口。
- `task-lifecycle`: 在不自动重放状态改变动作的前提下，区分完整成功、降级完成和模型通道失败的可见结果。

## Impact

- 主要影响 `fixed_runner/comment_ai.py`、`fixed_runner/execution_tasks.py`、任务与异常记录结构、控制 API 及记录页面。
- 需要扩展 Python 回归测试、控制台展示测试和基于既有截图的模型回放工具。
- 真机验收只通过现有固定执行器和设备独占 Worker 运行；MBH 仅用于观察未知页面并把验证后的恢复方法沉淀为固定规则。
- 模型 A/B 会产生小额、设上限的 API 费用；运行数据库和证据只追加、不清理。
