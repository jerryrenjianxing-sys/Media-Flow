## Context

现有正式链路已经由每设备 Worker 和 uiautomator2 固定执行器承担动作，设备档案只保存显示事实与少量兜底位置。新设备的 Portal/输入组件安装、MBH 前检和抖音校准曾以人工步骤完成；当前安装版已经内置 Python、ADB 与 uiautomator2，因此可以把正式所需部分收入 RiskFlow，而不把 MBH 变成运行依赖。

## Goals / Non-Goals

**Goals:**

- 在固定程序内部形成一个深的初始化 Module：调用者只需创建、继续、取消和读取结果。
- 以平台 Adapter seam 隐藏抖音页面与控件差异，保持通用流程、设备档案和动作安全语义。
- 支持幂等阶段、人工断点、证据、旧档案兼容和独立 Windows 运行。

**Non-Goals:**

- 不自动启用 ADB、登录账号、处理平台身份验证或绕过厂商安装保护。
- 不把所有抖音执行代码一次性重写，不交付第二个真实平台 Adapter。
- 不让 AI 直接点击，不默认执行任何账号写入。

## Decisions

### 独立初始化存储而非普通任务类型

在同一 SQLite 中增加初始化专用表，记录阶段、状态、请求选项、结果和报告路径；初始化执行线程与普通 Worker 复用同一设备锁。这样 `waiting_user` 和断点续跑不污染任务终态，也不会让普通任务统计出现初始化记录。备选方案是增加普通任务类型，但其终态和领取语义不适合人工断点。

### 小平台Interface和抖音Adapter

平台 Interface 只暴露页面观察、控件解析、校准和动作验证所需的少量语义方法，抖音 Adapter 内部复用现有 `Uia2DouyinRunner` 与定位函数。首版同时提供内存测试 Adapter，形成第二个真实测试 Adapter 而不是只设计假想扩展点。

### 语义优先、视觉候选、固定复验

实时 UI 树始终优先；平台规则可补充稳定语义；只有前两者失败才调用现有云端视觉通道。视觉响应使用严格 JSON，包含页面类型、控件角色、归一化区域、置信度和证据。初始化器验证前台包、页面类型与导航结果后才持久化，AI 实现不接收设备对象。

### 两层档案和局部失效

设备能力档案继续以稳定序列号为主键；平台档案另存并带包名、App 版本、显示签名与 Adapter 版本。运行时仍实时定位，档案坐标只是签名匹配时的兜底。显示/App变化将平台档案标为 `stale`，不删除旧档案或阻断仍可通过语义完成的既有流程。

### 控制组件最小化

正式初始化使用 uiautomator2 自带的 `u2.jar` 和 `app-uiautomator.apk` FastInputIME；初始化记录原输入法并在验证后恢复。Mobilerun Portal不属于硬依赖，避免厂商安装失败扩大正式运行面。

### 显式写入验收隔离

完整写入验收是初始化请求的一次性选项，默认 false。点赞/收藏仅在原状态明确时测试并恢复；评论只在安全普通视频上发送固定文案一次，成功或未知均写入不可重放检查点。该授权不写入普通任务配置。

## Risks / Trade-offs

- [厂商阻止 FastInputIME 安装或切换] → 保存截图和错误进入 `waiting_user`，不尝试绕过；允许用户处理后续跑。
- [云端模型定位错误] → 低置信拒绝，固定程序必须验证页面转移；无法验证即等待或失败。
- [App更新导致坐标漂移] → 坐标绑定显示与App签名，变化时立即禁用，语义路径可继续并提示快速复验。
- [随机评论无法清理] → 默认关闭，页面明确提示真实发送且不自动删除；结果未知绝不重试。
- [大范围重构影响现有任务] → 先将现有抖音Runner包装为Adapter，保持旧公开入口和任务结构，后续再逐步迁移调用点。

## Migration Plan

1. 新表使用 `CREATE TABLE IF NOT EXISTS` 在线创建，不修改现有任务表。
2. 新平台档案保存到运行数据目录；缺少新字段的设备按旧档案展示并继续既有语义流程。
3. 先上线接口与只读初始化；真实写入验收保持默认关闭。
4. 发布前审计便携 Python 内的 uiautomator2资源，不把本机档案或证据打包。
5. 回退时停止初始化执行线程并移除页面入口；新表和平台档案保留但旧版本忽略，设备原输入法在每次初始化 finally 路径恢复。
