## Purpose

将可复用的浏览、搜索和互动流程与平台页面差异隔离，使同一流程可在多个设备上运行，并为未来新增平台提供小而可验证的 Adapter seam。

## ADDED Requirements

### Requirement: 通用流程只使用语义动作
通用流程 SHALL 通过平台 Adapter 请求启动、主页恢复、搜索、观看、滑动、评论面板和互动等语义动作，不得读取平台私有坐标或包名。

#### Scenario: 抖音设备执行搜索流程
- **WHEN** 通用流程请求搜索并进入沉浸流
- **THEN** 抖音 Adapter 解析对应页面和控件并返回经验证的状态结果

### Requirement: 控件解析优先级
平台 Adapter MUST 依次使用当前 UI 树语义、已验证规则和经复验的视觉候选解析控件；归一化坐标只可在显示签名与页面证据匹配时作为兜底。

#### Scenario: UI树存在语义控件
- **WHEN** 当前 UI 树包含可见且角色匹配的目标控件
- **THEN** Adapter 使用该实时控件并忽略历史坐标

#### Scenario: AI返回候选区域
- **WHEN** 语义与规则均无法解析且视觉模型返回结构化候选
- **THEN** AI结果只作为候选，固定程序验证前台包、页面类型和操作后转移后才能保存或使用

### Requirement: 新平台通过 Adapter 扩展
新增平台 SHALL 通过实现包名、页面分类、控件解析、状态验证、恢复规则和校准清单接入，设备探测、初始化状态、任务锁、证据和通用流程 SHALL 保持复用。

#### Scenario: 使用测试平台Adapter
- **WHEN** 测试 Adapter 提供与抖音不同的页面与控件实现
- **THEN** 同一通用流程无需修改即可通过该 Adapter 完成模拟导航
