## Context

项目已经通过 `AGENTS.md`、主规格和 OpenSpec 项目技能约束开发，但既有规则只明确要求高影响变更建立完整 change。长期迭代需要一个不依赖用户重复提醒的统一入口。

## Goals / Non-Goals

**Goals:**

- 让行为改动稳定进入 OpenSpec 流程。
- 让项目规则和主规格保持一致。
- 保留与风险相称的低成本例外。

**Non-Goals:**

- 不改变 RiskFlow 运行架构、设备动作、任务数据或模型配置。
- 不把默认流程解释为高风险动作的长期授权。

## Decisions

- 在 `AGENTS.md` 内放置简短的强触发规则，使新任务无需依赖历史聊天即可命中 OpenSpec。
- 在 `project-governance` 主规格增加可验证的默认流程要求，作为长期单一事实来源。
- 以“是否改变行为”作为边界；相比按文件类型或代码行数判断，这一边界更符合风险和产品影响。

## Risks / Trade-offs

- [小改动流程变重] → 为纯文案、注释、说明和无行为样式保留简化例外。
- [OpenSpec 被误解为执行授权] → 在规则和规格中保留付费、删除、设备写操作与发布的独立确认门槛。

## Migration Plan

1. 更新项目 Agent 规则并严格校验 change。
2. 归档 change，把增量要求同步到主规格。
3. 若需要回退，恢复 `AGENTS.md` 原有变更门槛并通过反向 change 移除新增要求；运行数据库和设备状态不受影响。
