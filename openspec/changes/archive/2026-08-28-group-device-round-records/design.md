# Design

## 展示模型

原始 `TaskRecord` 继续作为审计与执行真相。控制接口在读取时派生 `TaskGroup`：

- 新记录以 `submission_id + device_id` 为稳定组键；
- 历史记录仅在任务类型、设备、轮数配置和轮次序列相容时归组；
- 非多轮任务或无法可靠归组的记录形成单任务组。

组状态优先级为：运行中、等待执行、部分失败、全部成功、安全停止、已取消。失败不被成功轮次覆盖。

## 详情与证据

详情接口接收控制接口已经返回的组内任务 ID，并重新从数据库读取，最多允许一个正常设备批次的有限任务数。每轮返回：

- 原始终态、开始/结束时间、耗时和结果统计；
- 该任务关联的纠错事件；
- 运行目录内经过边界校验的代表性 PNG 文件。

图片读取继续使用 task ID 与文件名映射，服务端验证任务运行目录属于 `DEFAULT_ARTIFACTS` 且文件是该目录的直接 PNG 子项。页面永不接收本地绝对路径。

## 性能

首页返回最近五个设备批次；完整记录页按设备批次分页。详情只在点击时加载。代表性截图限制数量，避免首次打开记录页加载所有图片。

## 兼容性

保留现有 `tasks`、任务统计、评论截图与纠错接口。新增 `task_groups` 和详情读取路径，旧调用方不受影响。执行器忽略展示字段，不改变任务执行结果。
