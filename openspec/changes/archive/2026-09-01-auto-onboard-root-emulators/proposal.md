# Change: 自动接管 Root 虚拟机

## Why

新建 MuMu 实例虽然可以通过本地 ADB 控制，但当前仍需人工把端口加入设备池、启动初始化、等待完成并再次提交任务。多开时这段重复操作成本高，而且同一实例可能同时暴露多个 ADB 地址，若只按地址识别会重复接管。

## What Changes

- 新增“自动初始化新虚拟机”和“自检通过后按当前方案运行”两个独立开关，默认关闭。
- 后台通过 MuMuManager 与实时 ADB 发现已启动实例，只接管 Root、本机回环 ADB 且 Android 身份未登记的实例。
- 同一 Android 身份的多个 ADB 地址视为别名，不重复初始化、不重复启动任务。
- 新实例先执行现有零写入初始化，再运行 3 条全零动作自检；只有自检完整通过才按当前保存方案提交一次正式任务。
- 初始化、自检或正式任务进入任何终态后均不自动重放；人工暂停继续优先于自动运行。
- 真机和已有手动初始化设备保持原流程，不被自动接管。

## Non-goals

- 不自动创建、启动或克隆 MuMu 实例。
- 不处理登录、短信验证、身份验证或厂商安全确认。
- 不把 Root 作为唯一虚拟机判断依据，也不自动接管 Root 真机。
- 不改变现有任务概率、主题策略、评论安全门或未知写入不重放规则。

## Impact

- Affected specs: `device-discovery`, `device-initialization`, `task-lifecycle`, `console-page-workflow`
- Affected code: 后台宿主、控制配置、设备页、状态接口与对应测试
