## Context

见 `proposal.md`。当前 `capture_gate` 在主题分析前先调用与互动动作相同的主信息流确认，并要求视频、点赞、评论、收藏四类控件同时可见。搜索沉浸式页面的控件集合会随布局变化，导致合法视频在模型调用前被判为 `visual_main_feed_check_failed`。

## Goals / Non-Goals

**Goals:**

- 把只读主题判断的页面确认与写入动作的控件确认分层。
- 复用现有前台包、搜索会话状态和阻断标记，不引入新的坐标模板。
- 保持动作执行前的语义控件定位和状态复核不变。

**Non-Goals:**

- 不改变 Gemini 模型、主题提示词、概率路由或数据库结构。
- 不允许搜索结果列表、广告页或外部应用进入主题互动。
- 不为缺失互动按钮的页面补造坐标点击。

## Decisions

1. 为页面闸门增加“是否要求完整互动控件”的显式参数。主题分析使用只读模式，互动动作继续使用严格模式。相比按设备或分辨率增加例外，这能保持通用状态机并直接表达安全意图。
2. 搜索视频确认在 `allow_search_feed` 已由搜索入口成功验证后，只要求抖音前台包与视频播放语义信号；广告、商业、直播、特效等阻断仍由统一分类器处理。相比仅依据截图亮度或搜索框坐标，语义信号更稳定。
3. 回归测试使用缺少部分互动控件的搜索视频 UI 树夹具，分别断言只读主题判断允许、严格互动闸门拒绝，并保留广告拒绝测试。

## Risks / Trade-offs

- [搜索页错误暴露视频播放信号] → 仅在已成功进入搜索视频会话后启用，并继续校验前台包与阻断标记。
- [主题模型成本略增] → 仅对此前被误拦的合法视频增加只读调用；广告与危险页面仍提前跳过。
- [旧 Worker 仍加载旧代码] → 任务池暂停且无运行任务时仅重启在线设备 Worker，再做零互动最小预演。

## Migration Plan

1. 先以离线回归测试复现并修复。
2. 运行全部 Python 测试和 OpenSpec 严格校验。
3. 暂停任务池并重启在线设备 Worker，使新代码生效。
4. 用单台搜索模式、零互动概率做最小设备预演；失败则回滚代码并保留现有运行数据库和截图。

回滚只需恢复本次代码改动并重启 Worker，不修改或删除 SQLite、任务记录、截图和设备状态。
