## Context

当前五台正式真机均在线且队列为空。抖音5号运行 33.0.0 并已有 v2 档案；其余设备运行 37.5.0、40.1.0 或 40.2.0。现有 v2 实现仍包含面向 v33 页面标题的固定假设。控制台七页重复输出顶部导航，窄小字号和互动页失效样式变量造成桌面视觉断层。

## Goals / Non-Goals

**Goals:**

- 让每台真机只使用与自身 App 和显示签名匹配的 v2 校准事实。
- 在不运行视频轮次的情况下取得五台同口径巡检回执。
- 用一个共享桌面外壳统一七页信息架构和视觉语言。

**Non-Goals:**

- 不把 MBH 变成生产动作平面，不升级 Mobilerun 或安装额外依赖。
- 不改变每5轮巡检节奏、互动概率、评论策略或现有历史数据。
- 不针对手机或窄屏建立独立产品布局。

## Decisions

### 1. 校准档案作为任务冻结快照

设备档案保存互动巡检配置，计划器只把当前设备的匹配档案复制到任务载荷。执行器验证设备 ID、App 版本、显示签名和档案版本后才使用语义控件或坐标后备。相比在运行时读取可变档案，这能保证排队任务可审计并防止校准更新改变旧任务行为。

### 2. 语义操作保持通用，版本差异进入数据档案

公共流程仍按消息、互动聚合、点赞收藏、评论、弹幕、我和访客语义执行；资源标识、标题变体、页面签名和归一化后备按设备存储。不会为每台复制一套完整执行程序。

### 3. MBH 校准串行，固定巡检按设备并行

校准逐台停止对应 Worker并复用设备锁，避免探索和正式执行竞争。校准通过后，五个固定任务可由五个独立 Worker 并行领取；每台仍只有一个执行者。

### 4. 桌面外壳替代页面内导航

新增共享客户端工作台组件，页面只提供当前导航键、状态说明和主内容。侧栏按“创建与准备、执行与结果、治理”分组；全局横幅放在主内容顶部。相比继续修补七份顶部栏，可一次消除导航漂移、主题入口不一致和桌面拥挤。

### 5. 使用现有巡检列表接口生成五设备总览

互动页从已有回执列表中按正式设备 ID 取最近一条，不新增专用聚合接口。没有回执的设备显式显示“尚未巡检”，减少后端表面和兼容成本。

## Risks / Trade-offs

- [抖音新版页面可能不暴露稳定资源标识] → 只在三遍校准后使用设备绑定的语义和归一化后备；否则保持未校准。
- [访问列表会清除未读角标] → 将其记录为已授权副作用，先采集入口角标再进入页面。
- [五台并行固定巡检增加 USB 压力] → 校准串行；固定任务只做列表读取且每设备独立，持续监测 ADB 在线状态和任务终态。
- [侧栏重排影响已有页面选择器] → 抽取共享结构后更新服务端渲染测试，并在四种桌面尺寸、深浅主题逐页验收。
- [脏工作区存在大量既有改动] → 仅编辑本变更涉及文件，不重置、覆盖或格式化无关内容。

## Migration Plan

1. 先创建规格和失败测试，不修改正式设备档案。
2. 逐台完成 MBH 校准，将通过结果写入各自档案；未通过设备保持原版本且不提交 v2。
3. 部署固定程序并精确重启五个 Worker，提交五个独立巡检任务。
4. 使用真实回执完成桌面工作台重排和浏览器验收。
5. 若回滚，恢复设备档案中的旧巡检版本并回退共享外壳代码；运行数据库、回执、截图、UI 树和访客基线均保留，不删除设备数据或应用状态。
