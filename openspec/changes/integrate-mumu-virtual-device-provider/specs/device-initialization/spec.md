# device-initialization Specification

## MODIFIED Requirements

### Requirement: 自动初始化后执行零写入自检
dev.11标准虚拟机 SHALL 复用同一Worker与独占租约，按本次任务准备连接、显示、应用和输入能力；每项成功立即保存。不再强制全套初始化、三条视频自检或逐设备三次巡检校准。三次验证只用于开发期共享规则提升，MUST NOT 伪造成功记录。

#### Scenario: 模板实例等待登录
- **WHEN** 自动流程在新虚拟机中识别到登录、身份或安全验证页面
- **THEN** 软件不自动登录或绕过验证；连接、看屏和任务选择不受影响，只有实际业务遇到该页面时等待用户处理

#### Scenario: 初始化与自检通过
- **WHEN** 实例已连接且实际显示符合900×1600、320 DPI
- **THEN** 系统允许选择任务，冻结需要的准备步骤并由固定执行器按需检查，不自动提交正式任务

#### Scenario: 初始化或自检失败
- **WHEN** 初始化进入等待、失败、取消或陈旧状态，或者自检不是完整成功
- **THEN** 自动流水线停在对应阶段并保存原因，不重新初始化、不重新提交自检

#### Scenario: MediaFlow重启后继续等待
- **WHEN** 后台在 `waiting_user` 或自检前阶段重启
- **THEN** 系统按持久化初始化记录、Provider真实状态和当前页面恢复展示，不假定登录完成或自动越过断点

#### Scenario: 初始化环境没有模型Key
- **WHEN** 虚拟机已连接ADB但当前Windows用户尚未配置OpenRouter Key
- **THEN** 固定Worker仍可启动并完成不需要模型的连接、应用和UI检查；只有首次真正调用视觉模型时才进入“等待配置模型”，且不得清除已验证的ADB映射

#### Scenario: dev.9可选视觉验证未通过
- **WHEN** 标准MuMu初始化的固定巡检路线需要视觉兜底，但模型缺失、拒绝、超时或预算不足
- **THEN** 仅该巡检能力保持待验证，基础初始化、ADB与看屏仍保留；保存异常现场并显示对应处理说明，不因一次视觉失败重启或重建虚拟机

### Requirement: 维护不受业务暂停误阻断
系统 SHALL 区分业务队列暂停和停止所有自动操作。业务暂停时用户明确提交的维护可由同一Worker领取；所有自动操作停止时维护也不得领取。排队及等待用户不占动作租约，正在执行才阻止人工接管。

#### Scenario: 业务暂停且维护排队
- **WHEN** 队列暂停且设备准备尚未被领取
- **THEN** 页面显示排队，不显示运行中，允许取消或人工接管；无人接管时Worker可领取维护但不得领取业务

#### Scenario: 正在准备时取消并接管
- **WHEN** 用户请求取消正在运行的准备
- **THEN** 系统先请求执行者在安全检查点停止，确认终态后才开放控制，不提前释放租约

#### Scenario: 升级旧式准备记录
- **WHEN** 本机升级确认两条指定旧初始化仍为queued且没有执行证据
- **THEN** 仅取消这两条并保存升级原因，不补跑、不修改历史终态
