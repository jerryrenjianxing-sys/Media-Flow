# console-page-workflow Specification

## MODIFIED Requirements

### Requirement: 设备页控制自动接管
设备页 SHALL 以统一“添加设备”作为真机和虚拟机接入主入口；既有新虚拟机自动接入能力 SHALL 并入该流程，不再以第二张含义重复的大卡展示。接入成功后 SHALL 等待用户从任务台提交正式任务。

#### Scenario: 添加真机
- **WHEN** 用户选择连接真机
- **THEN** 页面展示ADB授权状态、教程和Agent文档，并复用现有初始化断点

#### Scenario: 添加虚拟机
- **WHEN** 用户选择添加虚拟机
- **THEN** 页面根据MuMu安装状态引导下载或进入平台内创建、配置、登录和零写入自检

#### Scenario: 只开启自动初始化
- **WHEN** 用户通过统一添加设备流程完成虚拟机创建但没有提交任务
- **THEN** 新虚拟机完成初始化与零写入自检后保持待命，不提交当前方案

#### Scenario: 开启完整自动接管
- **WHEN** 旧配置仍包含自动运行标志
- **THEN** 兼容层保留配置但统一添加设备流程不自动提交正式任务，并提示从任务台确认

### Requirement: 非正常状态提供完整问题出口
设备页、添加设备对话框和任务台 SHALL 使用同一份后端状态说明。每个非正常状态 MUST 同时给出当前阶段、未继续原因、影响范围、推荐处理方法、可执行主操作和诊断编号；技术异常默认折叠，前端不得根据设备状态自行猜测原因。

#### Scenario: 人工前提尚未完成
- **WHEN** 虚拟机已连接ADB，但仍缺少抖音安装、登录、安全验证、档案复验或模型能力
- **THEN** 页面保留已经成功的连接和看屏能力，停止转圈并显示对应的人工操作按钮与继续入口

#### Scenario: 可恢复连接暂时失败
- **WHEN** MuMu实例已运行但当前ADB地址不可用
- **THEN** 页面显示可重试连接问题，说明不会重复启动虚拟机，并提供重试连接或重新检索入口

#### Scenario: 问题已经解决
- **WHEN** 后台下一次真实状态对账确认阻断原因消失
- **THEN** 问题摘要自动移除该项并展示下一项真实前提，不要求用户手工清理旧错误

#### Scenario: 长操作不再有进展
- **WHEN** 操作达到截止时间、连续三次状态读取失败或后台重启后不存在对应非终态操作
- **THEN** 页面结束忙碌动画，显示明确失败或待确认状态并恢复至少一个安全出口
