## Why

> 现行适用范围：见[上下文清理清单](../../../docs/context-cleanup.md#活动变更的适用范围)。本文件保留历次决策与未完成事实；退役聊天、旧详细巡检和旧初始化门槛不因本变更仍在列表而恢复。当前状态只读STATUS，勿以旧任务勾选推断本轮验收。

MediaFlow 目前只能在 MuMu 实例已经启动并暴露 ADB 后发现和初始化设备，非技术用户仍需进入 MuMu 管理大厅完成创建、配置和启停，设备页也只有定时截图而没有受设备锁保护的实时人工操作。现在需要把经授权的 MuMu 作为 MediaFlow 背后的虚拟设备引擎，使安装、实例生命周期、画面、初始化和任务选择形成一条独立运行且可审计的产品链路。

## What Changes

- dev.11采用本机干净模板与按需运行：只从现有实例提取完整APK集合，不复制应用数据；新建空白模板安装回读后克隆，模板不参加任务、不跨电脑分发。
- dev.11取消逐设备三次校准、登录资格和强制三视频自检门票；业务暂停不阻止显式维护，排队/等待用户不占动作锁。

- 新增版本化虚拟设备 Provider，首版通过本机 `MuMuManager.exe` 管理 MuMu 实例，不打开或自动操作 MuMu 管理大厅。
- 新增独立虚拟机与生命周期操作记录，使用 MediaFlow 永久 ID 关联 MuMu 实例编号、运行期 ADB 地址和 Android 身份。
- 支持按版本化配置配方创建、配置、启动、停止、重启、克隆、备份、恢复和确认删除虚拟机；本机模板仅作为可选加速，不跨电脑分发。
- 将现有 Root 模拟器发现、独立初始化和 3 条零写入自检接入新建流程；登录和身份验证继续由用户完成。
- 新增仅监听本机的实时画面网关：设备墙只读，聚焦画面可在取得维护锁后点击、滑动和输入。
- 设备页增加虚拟设备工作区、生命周期进度、内嵌画面、人工接管与降级单机窗口入口；真机路径保持不变。
- 新增统一“添加设备”入口：真机走教程与人工断点，虚拟机走 MuMu 官方下载、安装后自动探测及平台内创建初始化。
- 新安装默认设备清单为空；真实ADB库存、任务草稿、历史任务和设备档案不再互相生成设备卡片。
- OpenRouter连接增加本机加密回读、免费鉴权和显式的当前模型最小调用测试，并在任务提交前展示真实可用状态。
- 产品版本改为目标正式版本与单调测试序号组合：当前测试线为 `0.4.1-dev.2`，后续代码变化必须递增测试序号；安装包以Git标签绑定唯一干净提交和发行清单，不再生成同号不同内容的包。
- 保持固定执行器、SQLite 普通任务、历史任务、截图和设备档案兼容，不自动提交正式社媒任务。
- 非目标：不自动登录或绕过平台验证；不开放设备身份伪装；不让人工控制与 Worker 同时操作设备；不把 MuMu 更新绑定到每次 MediaFlow 小版本更新。

## Capabilities

### New Capabilities

- `virtual-device-management`: 虚拟设备 Provider、稳定身份、生命周期操作、模板、备份恢复和故障对账。
- `device-live-view`: 本机实时画面、只读观察、受锁人工接管、输入映射和安全降级。
- `device-onboarding`: 设备页和任务台共用的真机/虚拟机接入流程、空状态及安装后自动探测。
- `model-connection`: OpenRouter候选Key保护、鉴权反馈、模型实测和任务启动门禁。

### Modified Capabilities

- `device-discovery`: 将停止中的 MuMu 实例和 Provider 状态纳入设备工作区，并把运行期 ADB 地址映射到稳定虚拟设备身份。
- `device-initialization`: 按配置配方创建的虚拟机在安装抖音并登录后自动衔接初始化和 3 条零写入自检。
- `execution-architecture`: 增加持有现有设备锁的人工维护控制会话，继续禁止与 Worker 并发动作。
- `windows-distribution`: 安装版内置 Provider 和接入页面，但不携带或转发 MuMu 安装包及跨电脑模板。
- `task-workbench`: 第04步始终提供添加设备入口，并在无设备或全部不可用时展示明确空状态。
- `console-page-workflow`: 设备页与任务台复用同一接入弹窗和状态语义。

## Impact

- 后端新增 MuMu Provider、虚拟设备操作协调器、SQLite 记录和画面会话授权；后台宿主新增画面网关角色。
- 控制接口新增虚拟设备、操作进度和画面会话 API；`/api/status` 只做向后兼容扩展。
- 控制台设备页和任务台增加共享添加设备弹窗；设备页继续承载虚拟设备与真机分区、创建向导和实时画面组件。
- 前端/本地网关引入固定版本的 Tango/ya-webadb、匹配的 scrcpy server 和 WebCodecs 解码路径；不复用无鉴权的 ws-scrcpy 服务。
- 首版实时画面和浏览器操控只支持MediaFlow确认的本机MuMu实例；真机继续使用既有截图路径。
- 在浏览器实时操控验收后，将现有WinForms启动器升级为WebView2桌面壳。桌面壳和浏览器永久复用同一前端、接口与本机服务，不形成第二套业务实现。
- 安装版只打开 MuMu 官方下载页并轮询本机安装状态；敏感数据、运行数据库、日志和账号状态不得进入发行包。
