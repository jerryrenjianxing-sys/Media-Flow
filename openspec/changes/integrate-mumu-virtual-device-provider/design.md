## Context

MediaFlow当前正式链路是控制台、回环本地API、SQLite WAL队列、每设备Worker与独占锁、固定执行器、uiautomator2和ADB。已有Root模拟器接入只能发现已经运行且暴露ADB的MuMu实例；用户仍需进入MuMu管理大厅创建、配置和启停，设备页也只有定时截图。

本机已验证MuMu 6.5.7.0管理命令覆盖实例清单、创建、克隆、重命名、配置、启停、窗口显示与隐藏、ADB、应用管理、导入导出和删除。因此本变更把MuMu定义为本地虚拟设备Provider，而不是把MuMu界面自动化嵌入MediaFlow。MediaFlow不托管、不转发MuMu安装程序，也不猜测静默安装参数；MuMu缺失时只打开官方Windows下载页，用户完成安装和UAC后由MediaFlow自动探测并继续。

## Goals / Non-Goals

**Goals:**

- 在MediaFlow内完成MuMu实例完整生命周期，并用永久MediaFlow身份隔离Provider实例编号和运行期ADB端口。
- 从版本化配置配方创建空白虚拟机，完成抖音安装与登录后复用现有初始化与3条零写入自检。
- 在设备页提供本机内嵌只读设备墙和受现有设备锁保护的人工控制。
- 以独立持久操作记录、安全对账和有界恢复处理生命周期与画面故障。
- 用统一添加设备入口串起MuMu官方下载、安装后探测、虚拟机创建与真机人工接入，同时维持Velopack、MuMu及运行数据的独立更新边界。
- 保持普通任务、固定执行器、真机、旧档案、旧历史记录和现有截图接口兼容。

**Non-Goals:**

- 不自动登录、处理短信或身份验证，不绕过厂商或平台安全确认。
- 不开放IMEI、设备指纹或批量身份伪装。
- 不让网页、AI、MBH或Provider直接加入普通任务动作平面。
- 不重写刷视频Worker、任务队列和平台Adapter。
- 不公开局域网画面服务，不把本地ADB作为浏览器通用能力。
- 不让MediaFlow小版本自动升级MuMu，也不在普通卸载中删除MuMu或实例。

## Decisions

### Decision: Provider通过MuMu命令行而不是界面自动化工作

首个 `VirtualDeviceProvider` 实现为 `MuMuProvider`。它解析经探测确认的 `MuMuManager.exe`，使用无控制台子进程调用命令，并为每个命令设置超时、编码归一化、结构化结果和原始输出留证。MediaFlow不点击MuMu管理大厅，也不调用会打开管理大厅的 `main launch`；窗口降级只调用目标实例的显示命令。

Provider接口分为探测、只读清单、设置读写与验证、启停、窗口、ADB解析、克隆、备份恢复和删除。上层协调器只依赖该接口，因此未来可添加第二Provider而不修改任务Worker。

替代方案是直接控制MuMu UI或把命令散落在API路由和页面中。前者受界面版本和缩放影响，后者无法统一超时、幂等、证据和互斥，均不采用。

### Decision: 永久身份、Provider身份、ADB地址和Android身份分层保存

`VirtualDevice`使用MediaFlow生成的UUID作为永久对外身份；同时保存MuMu实例编号、当前ADB端点和Android ID等可用身份事实。重启后先按Provider实例匹配，再用Android身份验证，端口仅作为可更新的连接属性。历史任务冻结并保留提交时地址，不迁移或改写。

`VirtualDeviceInventory`是本机虚拟机库存的唯一接口，负责Provider扫描、自动纳管、存在性对账、启动和ADB重绑定。Provider扫描到的本机MuMu实例（包括默认实例0）均进入虚拟机库存；名称和创建来源只作展示，不是接入或任务资格。`/api/status.devices`只表示实时ADB在线设备，`virtualization.devices`表示包括停止实例在内的本机MuMu库存；页面不得再根据ADB在线列表反向构造虚拟机记录。停止时当前ADB端点清空，最后端点仅用于诊断和重连，不具有在线语义。

这避免把 `127.0.0.1:16416` 等运行期地址误当成永久设备，亦避免同一实例经多个ADB别名创建多个Worker。出现多个候选时失败关闭并等待人工确认。

### Decision: 生命周期操作使用独立持久协调器

新增SQLite记录 `virtual_devices`、`virtual_device_operations` 和 `device_view_sessions`。生命周期操作不进入普通社媒任务表；同一实例同一时刻最多有一个非终态操作，创建、克隆、导入、导出和删除采用请求幂等键。

协调器在每个不可逆或难以判定阶段前后读取Provider真实状态并保存证据。MediaFlow重启后不从旧百分比继续，而是对账实例清单、配置、进程、Android启动、ADB和身份，再收口为完成、失败或等待确认。未知结果不自动重放。

页面的“启动中”只来自数据库中真实存在的 `queued` 或 `running` 操作，不能从实例 `running` 或 `adb_ready` 状态猜测。实例已运行但ADB不可用时显示可重试错误，重试跳过重复启动命令并直接进入ADB解析。创建与接管名称由服务端按Provider安装身份分配单调递增序号，删除后不复用。

### Decision: 明确虚拟设备和操作状态机

虚拟设备主状态为：

`creating → stopped → starting → booting → adb_ready → initializing → waiting_login → validating → ready`

并允许 `stopping / backing_up / restoring / deleting / degraded / failed / retired`。状态是已观察事实与当前意图的产品摘要，不代替底层Provider证据。操作状态固定为 `queued / running / waiting_user / completed / failed / cancelled`。

### Decision: 标准化使用配置配方，本机模板仅为可选加速

默认创建Android 15空白实例，再写入并回读2核、1.75GB、900×1600、320 DPI、30 FPS、静音和Root开启等配置。新实例默认关闭自动旋转，但该开关不参与标准资格判定。抖音只从公司批准的APK或固定下载地址自动安装；缺少批准来源时转为内嵌画面人工安装。

MediaFlow安装包不携带MuMu离线程序或跨电脑 `.mumudata`。用户可在当前电脑把一个已清理且未登录的实例登记为本机加速模板，但该模板不得进入发行包、不得自动复制到其他电脑。

### Decision: 登录是显式人工断点，后续复用现有初始化

新实例ADB就绪后记录Root和Android身份，隐藏原生窗口并打开内嵌画面。Root状态不作为整机门槛；Android身份变化只使账号状态、局部校准和业务资格失效，不清除已确认的ADB与看屏能力。识别为未登录或验证页面时进入 `waiting_login`，用户必须通过人工控制完成。点击继续时固定程序按任务能力重新检查前置条件，再复用现有抖音初始化和3条全零动作自检；通过后允许加入草稿，不自动提交正式任务。

### Decision: 画面采用固定版本Tango与scrcpy组合并置于本地网关后

不采用ws-scrcpy。画面实现锁定Tango/ya-webadb稳定 `2.3.x` 与 `scrcpy-server 3.3.3`，构建时将两者作为不可拆分版本对检查。scrcpy内部协议不承诺兼容，因此浏览器只使用MediaFlow自有会话协议，不直接依赖原始scrcpy协议。

后台宿主新增 `device-stream-host`，仅监听 `127.0.0.1:48139`，连接本机ADB、启动匹配server、转发H.264帧和经授权的有限输入消息。浏览器用WebCodecs解码；不支持时保留 `/api/device-image` 截图模式。

首版实时路径仅对已写入虚拟设备映射的本机MuMu实例签发会话。真机即使在线也只展示既有定时截图，避免把未经验收的真机编码与输入差异混入首版。

### Decision: 桌面版只是同一网页的WebView2宿主

现有WinForms启动器升级为 `.NET Framework 4.8 + WebView2 Evergreen` 窗口。启动器仍先检查本地后台，随后在桌面窗口加载 `127.0.0.1:3000`；Chrome入口永久保留用于开发和降级。关闭窗口只隐藏界面并保留托盘，后台任务不随UI退出。桌面壳不复制React页面、不增加专用任务接口，也不改变固定执行器边界。

设备墙限制为每台最高450px、10 FPS、约1 Mbps、只读、无音频；聚焦画面最高900px、30 FPS、约4 Mbps、无音频。聚焦同一设备前关闭其墙流。隐藏窗口必须通过持续画面验证；黑屏时只显示目标实例窗口，不打开管理大厅。

### Decision: 只读观看与人工动作采用不同权限

只读会话可在Worker运行时存在，不持有动作锁且所有输入消息均由服务端拒绝。人工控制必须在服务端再次确认无任务和无初始化后取得现有设备独占锁，并签发短期随机令牌。断线15秒使令牌失效并释放锁；新任务提交遇到人工会话时拒绝，不抢占。

控制协议只允许触控、滑动、有限键盘和剪贴板，不允许任意shell或ADB命令。页面坐标先扣除黑边，再按实际帧、方向和内容矩形归一化；点击黑边直接丢弃。人工中文输入优先剪贴板，自动初始化仍使用既有AdbKeyboard/UIAutomator路径。

### Decision: 生命周期、画面与任务故障域分离

画面先重建单台流，仍失败再有界重启网关；不得重启API、Worker或普通任务。Provider操作失败只影响目标实例。批量启停为每台建立独立操作，一台失败不会回滚或取消其他实例。

停止、重启、克隆、备份、恢复和删除均先检查普通任务、初始化与人工会话。删除要求实例名确认，默认先备份；删除后只把设备标记为 `retired`，历史证据继续保留。

### Decision: MediaFlow只负责官方下载交接和安装后自动探测

MuMu缺失时，统一添加设备弹窗打开MuMu官方Windows下载页并进入等待安装；后端每5秒探测注册表、已知目录和用户提供的安装目录。用户完成Windows安装、UAC、VT设置或系统重启后，MediaFlow自动识别兼容管理命令并继续创建流程。

MediaFlow仍由Velopack独立更新，既不更新也不卸载MuMu。MediaFlow卸载默认保留MuMu、虚拟机、备份和 `%LocalAppData%\MediaFlow\data`。完整清理是另一个明确确认的流程，不复用普通卸载。

### Decision: 设备库存、草稿与档案采用单向依赖

`/api/status`只把当前ADB真实发现的设备作为运行库存；停止的MuMu实例只进入虚拟设备清单。草稿和历史任务可以引用暂时不存在的设备，但只能显示为失效选择，不得反向制造离线设备卡片。新安装默认选择为空，旧版精确的五设备开发种子在本机无真实ADB或Provider绑定时只清理选择，不修改历史任务。

真机档案绑定本机安装ID并只存放在用户数据目录。虚拟机发行内容只允许无账号、无Android身份、无ADB地址和无坐标的共享配置/语义配方；实例使用前仍按Android镜像、显示、导航、输入、抖音界面和适配器签名快速复验。MuMu宿主版本不进入页面档案键，Provider只按所需命令能力判定兼容。

### Decision: 模型连接分为免费鉴权与显式实测

新Key先写入候选加密文件并由同一Windows用户解密回读，再调用OpenRouter当前Key接口。鉴权成功后才原子替换正式Key；401或403丢弃候选并保留原Key；超时和429保留为待验证候选但不覆盖可用Key。真实模型测试由用户单独点击并明确少量计费，状态和时间持久化但任何接口、日志和任务载荷不得返回明文Key。需要模型的内容模式只有在当前Key鉴权和当前模型实测均通过后才可提交，纯观察且不需要模型的任务不受影响。

所有控制台到本机API的请求统一经过有界超时层并完整读取响应体后才结束计时；模型保存、虚拟机操作、初始化、任务提交和证据备份失败后必须解除按钮忙碌状态并显示可重试说明。模型配置操作在后台串行执行，同一时刻只允许一个保存、复验或实测，避免超时后的重复点击并发改写候选Key。草稿自动保存会取消已经过时的请求，周期刷新不会无限叠加。

### Decision: 开发版和安装版共享唯一版本源

`packaging/version.json` 是产品目标版本和开发测试序号的唯一可写来源。当前目标正式版本为 `0.4.1`，开发安装版本由它与 `development_iteration` 派生；本次修复对应 `0.4.1-dev.7`。每次可安装内容发生变化都必须先递增测试序号，全部验收通过后才构建不带预发布后缀的 `0.4.1`。源码运行显示 `0.4.1-dev.7+Git提交` 及脏工作区标记，安装包、桌面程序、后台和 `release-manifest.json` 使用同一派生身份。

可安装构建除要求工作区干净外，还要求 `mediaflow/v<安装版本>` Git标签精确指向当前提交，以非循环方式固定“版本号到唯一提交”的映射。发行清单记录目标版本、测试序号、提交号和渠道；多台电脑只能从同一标签提交生成该版本，不能各自形成分叉安装版。OpenSpec工具版本独立保持 `1.10.0`，不参与MediaFlow产品版本比较。

品牌安装向导使用SemVer顺序比较正式版与预发布版：`0.4.0 < 0.4.1-dev.1 < 0.4.1-dev.2 < 0.4.1`。检测到更旧版本时走正常升级；检测到完全相同版本且提交身份一致时允许保留数据的修复安装；相同版本但提交身份不同则拒绝覆盖并要求增加版本号；检测到更高版本时阻止降级。程序回退由Git标签和Velopack恢复上一版，数据库、截图、Key与设备档案不随程序回退。

## Risks / Trade-offs

- **MuMu命令输出或语义随版本变化。** Provider按版本探测能力、保留原始输出并以夹具覆盖乱码、超时和异常退出；不兼容版本只读展示。
- **创建或克隆的命令结果可能不明确。** 使用前后清单差异、配置回读和幂等键；存在多个候选时等待确认，绝不重复创建。
- **隐藏MuMu窗口可能影响编码或渲染。** 先做单台和30分钟设备墙验收；黑屏时仅显示目标单机窗口。
- **WebCodecs和H.264路径增加前端与网关复杂度。** 固定版本并保留截图降级；画面失败不影响Worker。
- **五台并发流占用GPU、CPU和带宽。** 设备墙限制分辨率、帧率和码率，聚焦时停墙流；最终以30分钟本机压力测试决定默认并发上限。
- **人工接管与自动任务存在竞态。** 所有控制建立和任务提交均由服务端在同一设备锁上复检；断线使用短租约回收。
- **官方安装仍包含人工步骤。** Windows安装、UAC、VT配置和必要重启只能由用户完成；平台负责解释当前断点并在安装后自动继续。
- **浏览器不能读取系统文件选择器的真实目录。** 自定义安装位置使用平台内路径输入并由后端校验，不伪装成浏览器文件选择。

## Migration Plan

1. 先增加Provider只读探测和新表，不改变当前ADB发现、Worker和设备选择。
2. 将已知MuMu实例按Provider编号与Android身份关联为 `VirtualDevice`；旧设备档案继续有效，无法唯一匹配的记录保持未绑定。
3. 分阶段开放启停与创建，默认不开启自动接管或正式任务提交。
4. 接入配置配方、应用安装断点、初始化和3条零写入自检；失败只停在新流程，不影响真机路径。
5. 加入只读画面，再加入受锁人工控制；保留现有截图接口作为降级。
6. 完成克隆、备份、恢复和确认删除后更新Velopack发行内容。
7. 使用一次性测试实例与隔离数据完成真实验收，本机模板始终保持可选且不进入发布产物。

SQLite迁移只新增表和可空关联字段，不重写普通任务、设备档案或历史截图。所有运行数据继续位于用户数据目录。

## Rollback Plan

- 关闭虚拟设备功能开关并停止 `device-stream-host`，现有真机、ADB设备发现、截图接口、任务队列和Worker继续运行。
- Provider数据库记录保留为只读审计；不删除MuMu实例或回退其配置。
- 若新ADB映射失败，恢复使用当前已验证的旧设备入口，但不得同时为同一Android身份启动两个Worker。
- 卸载或回退MediaFlow版本不会删除MuMu、模板、业务实例、备份或用户数据。
- 创建、克隆、恢复或删除出现未知结果时不做自动回滚命令，而是保留证据并等待人工对账，避免二次破坏。

## Open Questions

- 公司批准的抖音APK路径或固定下载地址尚未配置时，虚拟机流程会停在人工安装断点，不能声称全自动安装抖音。
- 内嵌实时画面不可用时仍可降级打开目标单机窗口；不得打开MuMu管理大厅。
