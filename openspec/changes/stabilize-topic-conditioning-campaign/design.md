## Context

见 `proposal.md`。真实种子轮显示，同一搜索页面在三台设备暴露抖音语义节点，而华为-01 的 UI 树只包含 `com.android.systemui`；截图和前台包均证明已经进入搜索视频流。现有确认函数把“UI 树可见”同时当作浏览资格和互动资格，导致只读阶段误失败。

## Goals / Non-Goals

**Goals:**

- 让已验证搜索转场在应用 UI 节点缺失时仍能进入只读主题判断。
- 用真实故障形态建立快速、确定性的回归测试。
- 保持所有写入动作的语义控件、安全门、概率和动作后复核不变。
- 对约束审核中可判定为输出结构损坏的结果只读复核一次，避免把格式错误误当成业务拒绝。
- 对主题判断中不可解析的模型输出使用同图、同策略的一次只读格式修复，减少格式故障造成的无效样本。
- 以每设备 20 条为一轮，每轮都从指定主题搜索进入视频流，仅验收搜索结果流的主题质量和固定程序稳定性，不再测量主页自然推荐率。

**Non-Goals:**

- 不用截图坐标替代点赞、收藏或评论控件。
- 不改变主题定义、模型供应商或用户填写的发送前约束；对“日常生活”采用与既有规范示例一致的窄范围解释，并强化既有 JSON 契约的格式修复提示。
- 不自动重试结果未知的状态改变动作，不删除历史证据，不修改数据库结构。

## Decisions

1. 视觉兜底只放在“已点击经过验证的搜索结果”之后，并同时要求抖音前台包、UI 树不含抖音节点和既有深色视频流外壳。相比全局放宽主信息流判断，这个状态窗口更窄，且可由当前执行轨迹证明来源。
2. 搜索会话确认函数接收可选截图；语义播放标记仍为首选，只有语义树完全缺失应用节点时才使用截图。若 UI 树存在抖音节点但语义不符，继续失败关闭，避免遮罩页或个人页误入。
3. 视觉兜底只设置 `allow_search_feed`，主题分析可走既有只读搜索路径；每个点赞、收藏和评论动作仍重新执行严格 `capture_gate`，不复用进入时结论。
4. 调优改为“指定主题搜索 → 搜索视频流连续运行 → 未达标则冷却后再搜索”的单路线闭环。连续两轮完整 20 条、精确命中率至少 30% 且模型有效率至少 95% 后才判为搜索流稳定；每台 10 条评论只统计发送后验证及截图均存在的记录。
5. 发送前约束若返回非法枚举、旧策略版本或不可解析 JSON，可对同一截图和候选评论再做一次只读审核；低置信度、明确阻断或第二次仍无效时继续失败关闭，不触碰手机。
6. `comment-constraint-v2-2026-08-30` 把“日常生活”限定为个人饮食起居、穿搭自拍、宠物、家庭、旅行和个人情绪等主体；专业访谈、技术科普、行业新闻、产品演示和业务讨论不因表达轻松而自动落入该类别，但仍须通过全部安全底线与其他明确约束。
7. 搜索结果宫格与沉浸式视频流分开识别：出现至少三个搜索分类标签时，即使 UI 树同时暴露播放标记也不得视为视频流。只有第一次结果卡点击后明确仍停留在同一搜索宫格，才可对原验证卡片重试一次；页面变化或结果不明时不得重放。
8. 已验证搜索会话中，完整的点赞、评论、收藏语义控件组本身可以确认“可浏览视频外壳”，即使设备暂未暴露播放标记；评论面板关闭后的确认使用这一只读外壳，不再因误判而连续返回到搜索结果页。该结论只用于浏览与关闭确认，写入仍逐动作重新过严格门。
9. 任一评论发送后若出现平台“身份安全验证”，当前轮次立即熔断后续评论尝试，只保留只读浏览和主题统计；不点击“去验证”、不重试发送，也不把未知结果计作成功。人工完成平台验证后由新轮次重新建立动作资格。
10. 主题模型首次响应若仅因 JSON 不可解析而无效，可对同一截图、同一主题策略执行至多一次只读格式修复；有效结论、低置信度、主题不匹配、403 拒绝和网络边界均不触发该修复。第二次仍无效时按 `invalid_response` 失败关闭，并记录两次分析尝试，绝不重放手机动作。
11. uiautomator2 的单次 JSON-RPC 传输等待由库默认 300 秒收紧到 20 秒；继续保留库内有限重试，使普通短暂延迟可恢复，同时保证设备读取通道卡死能回到现有异常边界，而不是让单个 Worker 无限占用设备。
12. 搜索视频结果卡同时兼容两种语义结构：旧版标题资源 `desc`，以及新版“`cover` 封面 + 标准视频时长 + 可点击卡片”。新版结构允许卡片从屏幕高度 12% 后开始，以适配 720×1600 设备的紧凑导航；仍不得使用盲坐标或仅凭任意图片节点点击。
13. 搜索沉浸页中的内嵌评论提示（例如“期待你的评论”）不得仅凭文案被判为已打开评论面板。只有该提示出现且完整的点赞、评论、收藏语义控件组缺失时，才按评论面板阻断浏览；完整控件组只恢复只读浏览资格，互动仍逐动作重新过门。
14. 已含旧版 `desc` 标题语义的搜索结果卡与“封面 + 时长”新版卡一样，可从屏幕高度 12% 后开始；标题语义本身已限定为视频结果，不再因紧凑导航把 12%–18% 区间内的合法卡片拒绝。
15. 培养验收使用只读轨迹审计：`task_start` 的配置从嵌套 `payload` 读取，发送前约束使用 `video_index`，发送确认使用 `video`；严格评论必须同时满足当前轮主题为 `exact`、`safe=true`、存在当前画面证据、约束放行、发送后验证以及同轮截图存在。搜索流连续达标只统计完整 20 条的 `search` 终态轮次，主页 `mixed` 轮仅保留历史展示，不再进入当前活动达标序列。
16. 分时搜索轮按设备设置 120 分钟冷却：从该设备上一轮任务的终态时间开始计算，冷却期内心跳只做只读审计，不提交新设备任务。冷却结束且未达标时仍提交 `search` 轮，不再路由到 `mixed_measurement`。
17. 平台身份安全验证是跨轮写入阻断：审计器从 `reaction_session_circuit_opened` / `comment_session_circuit_opened` 的 `platform_identity_safety_verification` 原因建立阻断，只能由其后明确的评论发送验证或“写入前未激活、写入后已激活”的点赞/收藏证据解除。阻断期间仍可做只读主题培养与测量；主题达标但评论不足时进入 `await_identity_verification`，不继续刷量、不自动验证。
18. `passed_with_recovery` 与 `passed` 都是可验收终态，但只有同时满足 `mixed`、目标20条、实际20条以及模型有效率不低于95%才进入自然流连续达标序列。`failed`、`degraded`、`stopped` 和缺少终态的轮次始终排除；恢复成功不会抹掉完整样本，恢复事件和截图仍独立留档。
19. `--since` 是指标窗口，不是安全状态重置：自然流、严格评论和连续达标只读取窗口内轮次；平台身份验证阻断、其后的明确写入解除证据以及设备最后终态读取全部可用历史。新的报表起点不得让旧阻断失忆，也不得缩短冷却。

## Risks / Trade-offs

- [深色非视频页面被误认] → 仅在验证过的搜索结果单次点击后启用，并要求抖音前台；任何写入仍需语义门。
- [搜索页 UI 树恢复后出现不一致] → 语义信号优先；存在抖音节点但不符合视频信号时不走视觉兜底。
- [搜索结果与自然推荐含义混淆] → 使用每轮 20 条且连续两轮达标，报告明确标记“搜索结果流”，不用该结果宣称主页推荐画像已稳定。
- [真实评论数量增长过快] → 每轮复盘后再提交下一轮，评论候选继续经过主题、安全和发送前约束，未知状态不重放。
- [格式复核被误当成放宽审核] → 仅结构错误可复核一次；低置信度与明确阻断不复核，最终仍需 `allowed` 且置信度达到既有门槛。
- [搜索宫格被误判为视频流] → 分类标签优先否决播放标记；只在第一次点击已知未生效时重试一次，并保存动作原因。
- [评论面板已关闭却继续返回] → 在已验证搜索会话中接受完整互动控件组作为只读外壳，同时继续排除搜索宫格和评论面板；不把该资格复用于写入授权。
- [身份验证被重复触发] → 第一次出现即对当前轮次开启评论熔断，保留截图和未知结果，不自动验证或重发。
- [模型返回说明文字而非 JSON] → 仅对原截图做一次严格结构修复；不改变主题定义、不复用写入资格，第二次失败照常跳过。
- [设备 UI 读取通道卡死] → 单次传输最多等待 20 秒并使用库内有限重试；失败进入既有页面异常/设备重连路径，未知写入仍不重放。
- [搜索结果标题资源名变化] → 用封面、时长和可点击祖先三项稳定结构识别结果卡，同时保留旧标题语义路径；缺少组合证据仍失败关闭。
- [内嵌评论提示与评论面板同文案] → 结合完整互动控件组区分搜索沉浸页与已打开面板；该判据只用于浏览恢复，不授予写入资格。
- [标题卡受固定顶部比例误拒] → 仅对含 `desc` 标题或“封面 + 时长”组合证据的卡片使用 12% 下限；普通可点击区域仍不具备视频结果资格。
- [临时汇总误读事件字段] → 使用版本内只读审计器交叉核对嵌套配置、主题判断、约束决定、发送确认和截图；缺一项均不计数，不从任务结果反推未知写入。
- [培养与测量过于密集] → 每设备以前一终态时间建立 120 分钟冷却；心跳到点但设备仍在冷却时只审计并等待，不用短时连续结果证明稳定。
- [身份验证阻断被新轮次遗忘] → 审计器跨轮保留阻断状态，仅用阻断后的明确写入验证清除；阻断设备输出 `read_only`，主题达标后等待人工处理。
- [已验证恢复被误算为失败] → 接受 `passed_with_recovery` 的完整20条轮次，同时保留视频数、模型有效率和终态三重门，不因放宽状态名称而纳入失败或半轮数据。
- [新报表窗口清除了安全状态] → 指标按 `since` 过滤，身份阻断、解除证据和最后终态按全历史计算；更换起点只影响统计，不影响写入资格与冷却。

## Migration Plan

1. 用华为-01 保存的故障形态先写回归测试并确认旧实现失败。
2. 实施最小视觉兜底，运行目标测试、全部 Python 测试和 OpenSpec 严格校验。
3. 等当前任务全部进入终态后，仅重启四个设备 Worker；不停止 API、页面或分析器。
4. 先重跑华为-01 搜索种子轮，再继续四设备分阶段验收。

回滚时恢复本次确认逻辑并重启空闲 Worker；不修改、回滚或删除 SQLite、任务记录、截图和设备状态。已执行且结果明确的互动不反向重放。
